# Stochastic site and state ownership inventory

**Snapshot:** 2026-10-24, `feature/nature-143-native-policy-comparator`. **Status:** assembled index and ownership crosswalk; row-level acceptance audit remains in progress. **Authority:** [Unified stochastic architecture](UNIFIED_STOCHASTIC_ARCHITECTURE.md) and [implementation roadmap](STOCHASTIC_ARCHITECTURE_ROADMAP.md).

This document joins existing inventories instead of copying their site rows. The detailed stable-site ledger stays in [Desired RNG migration status](DESIRED_RNG_MIGRATION_STATUS.md); the static direct-call report stays in [RNG direct-call census](RNG_DIRECT_CALLSITE_CENSUS.md). Semantic protocol and reference-build documents linked from those rows retain the mechanism-specific evidence.

The guarded Native-policy fallback authorizes exact SiteId/stream/operation triples in addition to the concrete adapters' finite site sets. Combat mappings follow their typed request constructors; immediate win rewards admit their source-listed `player.rewards` sites, War Hammer's elite shuffle and Fishing Rod's third-combat choice on their exact `run.niche` sites, Native summoned-creature HP and in-place Tough Egg hatchling HP choices on `run.niche`, and elite relic queue shuffles admit only `relic_grab_bag.queue_shuffle.swap_index` on `run.treasure_room_relics`. PotionFactory rarity and model requests are explicitly mapped to both `run.combat_potion_generation` and `player.rewards` where those source contexts use them; membership under one stream does not authorize an unlisted triple. The explicit engine-owned prototype reward scope retains only its declared legacy reward requests, including Pael's Tooth's saved-card return; the concrete legacy provider now rejects other requests under native control. This is an emulator control-boundary allowlist, not evidence of Native source parity.

The Native-policy outcome audit now covers each of those admitted persistent
shuffle results that occurs on the audited action path: War Hammer's ordered
eligible card instances and boss/Lava Rock ordered relic offers use pool-shuffle
schema V4. Fishing Rod's selected card instance uses card-index schema V2.
These additions annotate the existing Native provider decisions; they do not
establish source-pool completeness, stream parity, or cursor parity.

The generated-card outcome family also retains the ordered card-model pool and
selected offer for Native combat-reward `player.rewards` draws. Generated-card
schema V2 adds that reward site while V1 keeps combat-only completeness.
Native combat-reward `card_rarity.roll.unit_float` and
`card_rarity.upgrade_roll.unit_float` use a separate typed outcome annotation
for their threshold, offset update or upgrade result. Card-odds schema V1
requires both registered reward float sites in newly marked traces.
Native `reward.potion_odds.unit_float` results also retain the offered flag and
pity update; potion-reward odds schema V1 requires each such draw in new traces.
Forced rewards remain draw-free.
Combat-reward PotionFactory picks retain the selected rarity and model support
beside both exact `potion_factory.*` decisions. PotionFactory schema V1 requires
paired outcomes for the two `player.rewards` sites in new traces.
Native combat rewards also retain raw GoldReward amounts and relic rarity with
the ordered fallback queue support and selected identity. Their V1 schemas
require matching annotations for each `player.rewards` request in new traces;
gold is recorded before later reward modifiers.

The Rest reward crosswalk is `PrototypeRooms.StepRest` →
`EnterRestHealRelicReward`: relics with a positive
`RestHealCardRewardCount` can request `reward.card_rarity.ticket` and
`reward.card_model.index_draw`, or Native-shaped fallback
`card_rarity.roll.ticket`, `card_rarity.encounter_model.index_draw`, and
`card_rarity.upgrade_roll.ticket`. The shared run-action continuation captures
these requests only when `NativeRunRng` is absent; this crosswalk does not
establish source-pool completeness, hook call order, or Native cursor parity.
For configured Native Act 1 Rest Heal, `ReferenceNatureRunActionSessionV111`
also captures the `player.rewards` rarity float, model index, and upgrade
float as a typed prefix. It derives each rarity law from the saved offset
history and replays the selected action before committing the reward and
Nature cursor; source-pool completeness and Native cursor parity remain open.
