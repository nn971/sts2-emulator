# Native v0.111.0 combat reward RNG ordering

Source pin: `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`.
See `Core/Rewards/RewardsSet.cs`, `Core/Rewards/GoldReward.cs`,
`Core/Rewards/PotionReward.cs`, `Core/Rewards/CardReward.cs`,
`Core/Odds/PotionRewardOdds.cs`, and `Core/Models/Relics/PrayerWheel.cs`.

The base `RewardsSet.GenerateRewardsFor` constructs a GoldReward, invokes
`PotionRewardOdds.Roll` to decide whether to construct a PotionReward,
then constructs CardReward (and an elite RelicReward).
`GenerateWithoutOffering` subsequently calls `Populate` on each
of these rewards **in construction order**. Thus the relevant reward
stream chronology is:

1. Check potion reward pity (unless forced by White Beast Statue, which
   returns immediately with no draw and no pity update).
2. Populate GoldReward (inclusive integer amount).
3. Populate PotionReward, if offered (rarity + model draws).
4. Populate the base CardReward (rarity + card + upgrade per option).
5. Populate relic reward, for elites, using the relic grab bag.
6. Populate combat-earned additional rewards, if any.
7. Apply `Hook.ModifyRewards`; Prayer Wheel adds a new CardReward to
   normal fights **after** original rewards populate. Its rarity rolls
   advance the same persistent card pity after the base reward.

The restricted Overgrowth path now follows this ordering for gold,
potions, base card offers, and Prayer Wheel's appended card offers.
It still approximates the underlying native PRNG and unimplemented
hooks, and maintains the prototype's ordered card/potion/relic player
decision flow. Ordinary combat gold is awarded only on
`take_reward_gold`. Legacy prototype regions retain their
original generation behavior.
