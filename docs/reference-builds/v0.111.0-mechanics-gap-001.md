# v0.111.0 Silent mechanics gap — pass 001

Reference target:

- STS2 `v0.111.0`
- commit `41cef1ea`
- build fingerprint
  `3bb5598a35f7763c9de22078643ac2777190994b2be85ebd4ebf5c9d154aa45e`

Reference content source for this pass:

- Spire Codex `data-beta/v0.111.0/eng/`;
- exact tables are kept in a local, gitignored research cache;
- no game-data corpus is vendored into this repository.

This pass is an **inventory**, not a native-fidelity claim. Spire Codex's structured fields are
extremely useful indexes, but some are parser-derived and can be inconsistent with the localized
description. For example, Blade Dance's derived `cards_draw` is populated even though the card
generates Shivs rather than drawing cards. The analyzer now reports these contradictions instead of
treating every derived column as authoritative. Localized/raw text is used as a cross-check, and the
pinned decompiled `sts2.dll` remains the executable specification for semantics, ordering and
dynamic legality.

## Current coverage

  - `proto.silent.die_die_die`.

The 27 name matches must still be checked for numbers, upgrade deltas, targeting, powers and
conditional semantics. Name matching is not parity.

## First high-value missing primitive: Sly

Seven pinned Silent cards have Sly:

- Abrasive;
- Flick-Flack;
- Reflex;
- Ricochet;
- Sneaky;
- Tactician;
- Untouchable.

The pinned keyword text is:

> If this card is discarded from your Hand before the end of your turn, play it for free.

This interacts directly with the engine's existing suspendable discard selections, but the exact
native ordering still matters:

- whether the discarded card enters the discard pile before auto-play;
- whether the Sly play resolves before the discarding card's continuation;
- how completion/card-play events are nested;
- how a random-target Sly card such as Ricochet chooses targets;
- how death/combat-end short-circuiting interacts with the parent card play.

Therefore Sly should be implemented **after static source inspection**, not inferred solely from the
keyword sentence.

After local decompilation, begin with:

```fish
dotnet run --project src/Sts2Emulator.Cli -- \
    reference-source-search data/extracted/v0.111.0/decompiled Sly

dotnet run --project src/Sts2Emulator.Cli -- \
    reference-source-search data/extracted/v0.111.0/decompiled Discard

dotnet run --project src/Sts2Emulator.Cli -- \
    reference-source-search data/extracted/v0.111.0/decompiled CardPlay
```

## Implementation order from this gap

### A. Content cleanup already safe from static evidence

Completed in this pass:

- canonicalized the starter relic name to Ring of the Snake;
- corrected Blade Dance to Exhaust;
- corrected Skewer from 7×X to 8×X, retaining its +3 upgrade;
- corrected Slice from 5 to 6 damage, retaining its +3 upgrade;
- corrected Sucker Punch from 7 (+3) to 8 (+2), retaining Weak 1 (+1);
- added version-pinned regression tests for the starter baseline and these corrections.

Still to do:

- compare the remaining name-matched cards beyond simple base scalar fields;
- quarantine the five cards absent from v0.111.0 from future native rulesets;
- keep Shiv as a token rather than treating it as a reward-pool Silent card.

### B. Silent discard family

- inspect and implement Sly;
- generalize discard as an event rather than only a pile movement;
- verify Survivor/Acrobatics/Dagger Throw continuations against static source;
- then add the seven Sly cards that require no further unsupported mechanic.

### C. Turn-bound card keywords

- Innate;
- Retain;
- Ethereal/end-turn Exhaust;
- Unplayable and Eternal where needed by generated/status/curse content.

These should be keyword-driven properties rather than individual card special cases.

### D. Random combat choices

Add a generic deterministic operation for:

- random live enemy;
- random card satisfying a filter;
- repeated random targeting.

The RNG stream/call order must be sourced from the pinned DLL before claiming parity.

### E. General conditional effects

Replace named special cases with a small predicate/effect representation only after classifying the
19 Silent cards from source. Likely reusable predicates include:

- hand empty / hand composition;
- first/next N events this turn/combat;
- cards played this turn;
- target status/power state;
- unblocked damage;
- discard/draw counts;
- pile membership;
- HP/death conditions.

### F. Solo-first exclusions

Ally/multiplayer targeting is a real native mechanic, but it should not block the first trustworthy
solo Silent emulator. Preserve the distinction in the model and defer multiplayer resolution until
the solo run is faithful.

## New tooling

The branch now contains:

- `ReferenceCorpus`
  - summarize local version-pinned tables;
  - resolve native IDs/names/class-style aliases;
  - fetch exact entities;
- `ReferenceMechanicsGapAnalyzer`
  - compare the pinned Silent pool with the current prototype;
  - distinguish missing content from missing engine primitives;
  - distinguish token/out-of-pool cards from cards absent in the pinned build;
  - compare static starting-run fields;
- `ReferenceSourceSearch`
  - search the one-time local ILSpy decompilation by text with file/line output.

CLI entry points:

```fish
dotnet run --project src/Sts2Emulator.Cli -- \
    reference-corpus-summary data/external/spire-codex/v0.111.0/eng

dotnet run --project src/Sts2Emulator.Cli -- \
    reference-corpus-get data/external/spire-codex/v0.111.0/eng cards SURVIVOR

dotnet run --project src/Sts2Emulator.Cli -- \
    reference-mechanics-gap data/external/spire-codex/v0.111.0/eng

dotnet run --project src/Sts2Emulator.Cli -- \
    reference-source-search data/extracted/v0.111.0/decompiled Sly
```

The JSON form of the gap report is available via:

```fish
dotnet run --project src/Sts2Emulator.Cli -- \
    reference-mechanics-gap data/external/spire-codex/v0.111.0/eng --json
```

This report should be regenerated conceptually whenever the pinned target changes; build-specific
