## Event progression

Trial is one of seven Glory shared events. Its opening page offers
**Accept** and **Reject**. Accept chooses, uniformly, one of three
cases: Merchant, Noble, Nondescript. Reject leads to a follow-up page
offering Accept again or **Double Down**, which opens a run-abandon
confirmation. The emulator represents the confirmation as a separate,
resumable decision page. Cancelling returns to the Reject page;
confirming terminates the run.

| Case | Guilty | Innocent |
| --- | --- | --- |
| Merchant | Gain Regret, then obtain two front-of-bag relics | Gain Shame, then upgrade two selected deck cards |
| Noble | Heal 10 HP | Gain Regret and 300 Gold |
| Nondescript | Gain Doubt, then resolve two independent optional three-card reward offers | Gain Doubt, then transform two selected deck cards |

The event is implemented as explicit `EventState.NativePageIndex`
pages 0 (opening), 1 (reject), 2 (merchant), 3 (noble), 4
(nondescript), and 5 (abandon confirmation). Generated rewards and
deck-choice prompts use existing reward/event continuations, so
persistence, identity, and interruption/return are shared with the
rest of the engine. Each completed outcome returns to the map,
counting the room once. All three curses are excluded from ordinary
reward and combat-generation pools.

## Combat curses

**Regret** is an unplayable, non-upgradable curse. At hand-end it
deals unblockable, unpowered damage equal to the hand's card count.
**Shame** applies 1 Frail and **Doubt** applies 1 Weak at hand-end.
The first application of either debuff sets a one-time
`SkipNextPlayerTurnEnd` marker when that debuff was previously
absent. This preserves the native skip-duration-tick behavior on
the same turn; existing stacks follow the ordinary timer.

## Limitations and evidence

This is source-oriented **emulator-level** implementation, not a
claim of real-game parity. The explicit fixture
`PrototypeNativeLaterActFixture.CreateGloryEvent(seed, TrialId)`
makes the content testable, and the experimental Glory event selection now
includes Trial. The scenario roll uses the prototype event RNG
rather than native event-stream semantics. Card reward generation
currently uses the implemented Silent reward pool and prototype
Rewards stream instead of the exact native character pool and
`CardCreationOptions` odds. Two relic pulls use the persistent
source-shaped subset bag, which remains incomplete. Transform
selection relies on the shared prototype transformation pool.
The native abandon-confirmation UI is represented by two headless
actions rather than a platform modal.

Tests cover deterministic/fork-safe case selection, both rejection
branches, each court outcome, multi-stage card rewards and deck
choices, Regret damage, Weak/Frail duration, invalid actions, and
ordinary event-room completion. Live oracle validation and the
complete later-act selection policy are pending.
