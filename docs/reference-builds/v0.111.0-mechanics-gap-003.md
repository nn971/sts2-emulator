This pass continues the static-first workflow. No new live-game capture was required.

## Progress since pass 002

### Per-hit random enemy targeting

The prototype now has a reusable `RandomEnemy` effect target and a dedicated
`combat_targets` RNG stream.

Static source inspection of native `AttackCommand` establishes the important semantics:

1. before every hit, rebuild the currently live opponent list;
2. for randomly targeted attacks, choose one target through
   `RunState.Rng.CombatTargets.NextItem(...)`;
3. duplicates are allowed unless the command explicitly disables them;
4. a creature killed by an earlier hit is absent from the candidate set for later hits.

This unlocks pinned **Ricochet**:

- 2 Energy;
- Sly;
- 3 damage;
- 4 hits;
- +1 hit on upgrade;
- each hit rerolls a live enemy independently.

The prototype RNG codec is still provisional. The stream separation and call shape are source-backed;
the exact native PRNG/seed state remains a later parity task.

### Effect provenance and card type

Queued combat effects now retain their source kind:

- card;
- potion;
- power;
- relic;
- system.

Cards can additionally carry explicit `PrototypeCardType` metadata.

This was necessary to stop broad effect primitives from silently acquiring incorrect native
semantics. For example:

- Dexterity may modify card-derived Block;
- Dexterity must not modify Afterimage/relic Block;
- Vulnerable modifies powered Attack damage;
- Fire Potion, Explosive Potion and Letter Opener damage are not powered card Attacks.

The existing direct-damage Silent cards have been annotated as Attacks where needed for this slice.

### Dexterity

Static `DexterityPower.ModifyBlockAdditive` confirms:

- Dexterity is additive;
- negative Dexterity is allowed natively;
- it applies only to powered card/monster-move Block from the owner.

The prototype now applies its Dexterity bonus only to card-sourced player Block. This fixes the old
prototype behavior where Afterimage Block was also increased by Dexterity.

### Thorns

Static `ThornsPower.BeforeDamageReceived` and `CreatureCmd.Damage` establish:

- Thorns triggers before the incoming attack damage is applied;
- it deals unpowered damage to the dealer;
- enemy Block can absorb that retaliation;
- if Thorns kills the attacker during `BeforeDamageReceived`, the already-started hit still lands;
- a multi-hit `AttackCommand` stops before the next hit because the attacker is then dead.

The shared prototype Thorns definition is now amount-for-amount: N Thorns deals N retaliation damage.
The old prototype elite is represented as having 2 Thorns rather than a hidden ×2 effect.

This unlocks pinned **Abrasive**:

- 3 Energy;
- Rare Power;
- Sly;
- gain 1 Dexterity;
- gain 4 Thorns;
- upgrade increases Thorns to 6.

### Vulnerable and powered Attack damage

The prototype now has incoming Attack-damage modifiers on statuses and preserves whether a queued
damage operation is a powered Attack.

Pinned Vulnerable is represented as:

- 3/2 incoming powered Attack multiplier;
- duration-style stacks;
- tick down at enemy turn end.

This unlocks pinned **Assassinate**:

- 0 Energy;
- Rare Attack;
- Innate;
- Exhaust;
- deal 10 (+3) damage;
- then apply 1 (+1) Vulnerable.

Regression coverage explicitly verifies that Vulnerable boosts a later Strike but does not boost
Fire Potion damage.

### Reusable combat predicates

A single predicate representation is now shared by card playability and conditional queued effects.

Implemented predicates:

- `DrawPileEmpty`;
- `TargetHasStatus(statusId)`.

This unlocks two source-backed examples.

**Grand Finale**

- 0 Energy Rare Attack;
- playable only while the Draw Pile is empty;
- deal 60 (+15) damage to all enemies.

The native class implements this through `IsPlayable`, not by accepting the play and failing later.
The emulator therefore removes Grand Finale from the legal action set whenever the predicate fails
and validates the predicate again on execution.

**Bubble Bubble**

- 1 Energy Uncommon Skill;
- target one enemy;
- if that target already has Poison, apply 9 (+3) Poison;
- otherwise the card still plays and spends its cost but the conditional effect does nothing.

The native class performs this condition inside `OnPlay`, matching the distinction between
playability predicates and effect predicates in the emulator.

## Gap analyzer improvements

`ReferenceMechanicsGapAnalyzer` now understands that the prototype has:

- random enemy targeting;
- draw-pile-empty playability;
- target-has-status conditional effects.

Grand Finale and Bubble Bubble are therefore no longer hidden inside the coarse
`conditional_effect` bucket. Synthetic corpus tests exercise both classifications.

The old synthetic assertion that `random_target` was unsupported was also corrected.

## Remaining conditional families

Static corpus/source inspection splits the remaining broad conditional bucket into reusable
families.

### Dynamic combat counts / calculated values

High-value next cluster:

- **Finisher** — hit once per Attack already finished this turn;
- **Flechettes** — hit once per Skill currently in hand;
- **Memento Mori** — bonus damage per card discarded this turn;
- **Murder** — bonus damage per card drawn this combat;
- **Precise Cut** — damage decreases per other card currently in hand.

These should share typed combat counters/query expressions rather than five named implementations.

### Delayed next-turn effects

Examples:

- Predator — draw cards next turn;
- Dodge and Roll — gain Block next turn;
- Sidestep — gain Energy next turn;
- Nightmare — create selected copies next turn.

The native code commonly represents these as temporary powers. The emulator should likewise use a
generic delayed-effect/power mechanism with explicit expiry rather than card-name checks.

### Event-reactive turn/combat effects

Examples:

- Corrosive Wave;
- Envenom;
- Serpent Form;
- Speedster;
- Strangle;
- Phantom Blades.

The existing event bus is a useful base, but event provenance needs to become richer enough to
distinguish attack/unblocked-damage/draw/card-type conditions.

### Temporary modifiers and legality

Still separate:

- Anticipate / temporary Dexterity;
- Blur / preserve Block;
- Bullet Time / no-draw + free-hand costs;
- Burst / replay next Skill;
- Grand-Finale-like future legality predicates;
- temporary Strength loss and other duration powers.

### Solo-first exclusions

Multiplayer/ally-target mechanics such as Concoct, Fade, Flanking and Sneaky remain deliberately
outside the first solo Silent fidelity slice.

## Known limitations after this pass

The newly implemented semantics are intentionally narrower than a global parity claim:

1. `combat_targets` is separated correctly, but still uses the prototype PRNG codec;
2. not every existing prototype card has complete native type metadata yet;
3. Vulnerable is implemented for enemy targets; player-side Vulnerable is not yet modeled;
4. Thorns retaliation currently updates combat state directly during enemy attacks and does not yet
   emit the full native damage/history hook sequence;
5. native decimal damage rounding and the general `ValueProp` system are not yet represented;
6. exact simultaneous-hook ordering remains a pinned-source/differential-parity task.

## Next implementation order

1. introduce typed combat counters/query expressions;
2. import Finisher and Flechettes first;
3. extend the same mechanism to Memento Mori, Murder and Precise Cut;
4. introduce temporary/delayed effect powers and correct Predator;
5. continue classifying event-reactive conditional powers;
6. only then return to exact RNG codec/call parity or a live differential capture if static source
   leaves an ambiguity.

The custom reference bridge remains idle for this pass.
