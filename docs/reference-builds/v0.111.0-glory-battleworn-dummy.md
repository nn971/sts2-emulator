## Event and encounter

The three initial options select precisely one training fight:

| Choice | Combat | Fixed HP | Success outcome |
| --- | --- | ---: | --- |
| Setting 1 | BattleFriendV1 | 75 | One optional random potion reward |
| Setting 2 | BattleFriendV2 | 150 | Upgrade up to two distinct eligible deck cards |
| Setting 3 | BattleFriendV3 | 300 | One optional front-drawn relic reward |

Each dummy's only move is `NOTHING_MOVE`. Its initial
`BattlewornDummyTimeLimitPower` has amount 3. At each enemy-side
turn end, it decrements if greater than one; on expiry the enemy
escapes, ending combat and setting the event's `RanOutOfTime`
condition. A timeout has no reward. A timely kill resolves the
setting-specific branch. Neither result adds an ordinary combat
reward, and the event room is completed exactly once.

Event combat is started by selecting its choice in the experimental Glory
event route; its fight is not drawn from the ordinary regional encounter bag.
The time-limit power and three encounter-specific monster classes
are registered explicitly, independent of any normal Glory pool.

## Scope and unresolved fidelity

The timer, no-attack move, initial HP, reward *types*, optional
reward UI and event completion are source aligned. Random
reward streams differ: V1 uses implemented potion rarity/selection
instead of the native unlocked character/shared potion pool;
V2 uses the prototype event stream for the pinned StableShuffle;
V3 draws from a restricted persistent relic bag (correct front
direction but incomplete model eligibility/stream semantics).
Native oracle traces are absent; tests establish emulator semantics
and canonical fork determinism only.

In the final content inventory, the abstract
`BattlewornDummyEventEncounter` remains a catalogue-only base
class while each concrete V1–V3 fight is registered for the event route and
excluded from ordinary maps. Native encounter-history and combat-won
relic ordering around *escape* require differential validation.
