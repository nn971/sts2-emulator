# Later-act Ancient assignment audit

Target: single-player STS2 v0.111.0 / source commit
`706ef1c9fa2219220065849fd5265328607ece20`.

This audit records the source call order for selecting Hive and Glory Ancients.
The source call-order audit below is retained for the later RNG pass.
Act-local Ancient assignment now executes in the configured Silent route.

## Source order

`RunManager.GenerateRooms` first copies `UnlockState.SharedAncients` and
unstable-shuffles that list on `State.Rng.UpFront`. It then visits
`State.Acts.Skip(1)` in act order. For each later act it calls
`UpFront.NextInt(shared.Count + 1)`, assigns the first `count` shared Ancients
to that act, and removes them from the shared list before processing the next
act. In the default three-act sequence this partitions the unlocked shared
pool between Hive and Glory.

The only source-defined shared Ancient at this pin is Darv. `UnlockState`
removes Darv unless `DarvEpoch` is revealed. The shared pool therefore has
zero or one entry; the per-act `NextInt` calls still occur for Hive and Glory,
including when the remaining list is empty.

After partitioning, `RunManager` visits acts in order and calls each act's
`GenerateRooms` on the same UpFront stream. `ActModel.GenerateRooms` draws the
event ordering, encounter histories, elite history, boss and finally one
Ancient from `GetUnlockedAncients(unlockState)` followed by that act's assigned
shared Ancient subset. On the final act, Ascension's Double Boss selection is
drawn after that act's room generation and Ancient selection.

Act-local Ancient order at this source pin is:

- Hive: Orobas, Pael, Tezcatara; Orobas is removed until `OrobasEpoch` is
  revealed.
- Glory: Nonupeipe, Tanx, Vakuu.

These ordered pools and the UpFront call sequence are source facts. Exact
native cursor parity still requires matching every earlier room-generation
draw, unlock state, multiplayer room count, native primitive behavior and the
Ascension-dependent trailing draw in the integrated run fixture.

## Current emulator integration

Configured Silent three-act runs now persist a selected act-local Ancient in
both prepared later-act encounter bags at run initialization. Hive dispatches
Orobas, Pael or Tezcatara; Glory dispatches Nonupeipe, Tanx or Vakuu before map
choice. All six openings use their existing acquisition, reward and deck-choice
continuations. Entering an opening with an identity different from its stored
assignment is rejected. Named fixtures can still explicitly prepare an Ancient.

The current assignment uses prototype `event` randomness. It does not implement
the shared Darv partition or native UpFront draw schedule. Those remain work
for shared Ancient implementation and the subsequent RNG pass. Orobas offers
only its eight supported Silent relics: cross-character Sea Glass and Prismatic
Gem offers are explicitly deferred by current scope. The full native assignment
and offer distribution is therefore not a claimed behavior of this profile.

`ExperimentalSilentThreeActRouteV111Tests` samples all six act-local assignments
from run start and checks their snapshot/fork persistence. Direct boundary tests
verify each opening, and whole-route tests exercise the additional Ancient
choices through both Act 1 routes and A10 double bosses.
