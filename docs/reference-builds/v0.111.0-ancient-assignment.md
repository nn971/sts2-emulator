# Later-act Ancient assignment audit

Target: single-player STS2 v0.111.0 / source commit
`706ef1c9fa2219220065849fd5265328607ece20`.

This audit records the source call order for selecting Hive and Glory Ancients.
The source call-order audit below is retained for the later RNG pass.
Act-local Ancient assignment now executes in the configured Silent route.

## Source order

`RunManager.GenerateRooms` first copies `UnlockState.SharedAncients` and
unstable-shuffles that list on `State.Rng.UpFront`. It then visits
`State.Acts.Skip(1)` in act order. For each later act it calls
`UpFront.NextInt(shared.Count + 1)`, assigns the first `count` shared Ancients
to that act, and removes them from the shared list before processing the next
act. In the default three-act sequence this partitions the unlocked shared
pool between Hive and Glory.

The only source-defined shared Ancient at this pin is Darv. `UnlockState`
removes Darv unless `DarvEpoch` is revealed. The shared pool therefore has
zero or one entry; the per-act `NextInt` calls still occur for Hive and Glory,
including when the remaining list is empty.

After partitioning, `RunManager` visits acts in order and calls each act's
`GenerateRooms` on the same UpFront stream. `ActModel.GenerateRooms` draws the
event ordering, encounter histories, elite history, boss and finally one
Ancient from `GetUnlockedAncients(unlockState)` followed by that act's assigned
shared Ancient subset. On the final act, Ascension's Double Boss selection is
drawn after that act's room generation and Ancient selection.

Act-local Ancient order at this source pin is:

- Hive: Orobas, Pael, Tezcatara; Orobas is removed until `OrobasEpoch` is
  revealed.
- Glory: Nonupeipe, Tanx, Vakuu.

These ordered pools and the UpFront call sequence are source facts. Exact
native cursor parity still requires matching every earlier room-generation
draw, unlock state, multiplayer room count, native primitive behavior and the
Ascension-dependent trailing draw in the integrated run fixture.

## Current emulator integration

The source [`AncientEventModel`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/AncientEventModel.cs)
obtains the selected relic and calls `SetEventFinished` after acquisition.
Supported Tezcatara, Pael, Orobas, Darv, Tanx, Vakuu and Nonupeipe choices now
retain that result page after relic acquisition and any queued deck or relic
reward choices settle. Dismissing it returns from the pre-map Ancient opening
to map choice without recording an ordinary map-room completion.

Configured Silent three-act runs now persist a selected act-local Ancient in
both prepared later-act encounter bags at run initialization. Hive dispatches
Orobas, Pael or Tezcatara; Glory dispatches Nonupeipe, Tanx or Vakuu before map
choice. All six act-local openings use their existing acquisition, reward and
deck-choice continuations. Entering an opening with an identity different from its stored
assignment is rejected. Named fixtures can still explicitly prepare an Ancient.
Coverage marks all ten supported Silent outcomes complete for Tezcatara, Pael,
Tanx, Vakuu and Nonupeipe. Orobas retains only its deferred Sea Glass and
Prismatic Gem branches.

When `DARV_EPOCH` is revealed, the assignment includes Darv in at most one of
Hive or Glory, or in neither. The configured event dispatch opens Darv at that
act boundary. Darv now executes all twelve relic branches supported for
Silent: Astrolabe, Black Star, Calling Bell, Dusty Tome, Empty Cage,
Pandora's Box, Runic Pyramid, Snecko Eye, Ectoplasm, Sozu, Philosopher's Stone
and Velvet Choker. Black Star adds one relic to elite rewards. Ectoplasm adds
one energy per turn and blocks gold gains; Darv offers it only in Hive.
Calling Bell adds its permanent unique Curse and queues Common, Uncommon and
Rare relic rewards. Dusty Tome adds an upgraded Wraith Form. Pandora's Box
transforms every non-Eternal deck card tagged Strike or Defend. Sozu and
Ectoplasm are excluded from Glory offers. The 50/50 Dusty Tome offer branch
and Pandora's Box deck gate are implemented; native offer RNG and exact deck
eligibility remain for the later fidelity pass.

Assignment currently uses prototype `event` randomness and does not implement
the native UpFront draw schedule. Darv's offers use a persisted `DARV` event
RNG context. The ReferenceNature Ancient-offer session now models the binary
Dusty Tome/three-relic variant followed by the complete ordered relic-pool
shuffle, then replays both through Darv's existing opening generator. Its laws
remain `UNVERIFIED`; native call-order, source pool fidelity and seeded
result/cursor parity remain unaudited.
Orobas offers only its eight supported Silent relics:
cross-character Sea Glass and Prismatic Gem offers are explicitly deferred by
current scope. The full native assignment and offer distribution is therefore
not a claimed behavior of this profile.

`ExperimentalSilentThreeActRouteV111Tests` samples all six act-local assignments
from run start and checks their snapshot/fork persistence. Direct boundary tests
verify each opening, and whole-route tests exercise the additional Ancient
choices through both Act 1 routes and A10 double bosses.

## S0 stochastic boundary: later-act Ancient assignment

The three `event.later_act.*` rows describe run initialization, not an event
choice. The pinned source copies the unlocked shared-Ancient pool, shuffles it
on `UpFront`, then makes one bounded assignment draw for Hive and one for
Glory as the pool is partitioned. At this source pin Darv is the only shared
Ancient and is eligible only when its epoch is unlocked; each act also draws
from its ordered local Ancient pool. The default emulator assignment path
uses the legacy `event` stream, so source stream ownership and native cursor
parity remain open. Configured experimental Silent runs with a ReferenceNature
cursor now route the existing assignment calls through ReferenceNature's
Hive, Glory, and Ancient laws and persist the resulting act-local assignments
and advanced Nature cursor.

The player-visible observation exposes the assigned Ancient when entering
the act boundary; the shared pool, prior assignment, and draw state are
private generation constraints. Ordinary assignment runs in generator order.
On configured experimental three-act runs, the existing later-act preparation
session can suspend between assignment requests and encounter-bag draws,
replay the generators from the saved decision prefix, and publish the prepared
assignments, bags, and Nature cursor together.
Read-only `chance_law_query` exposes each bounded assignment and local Ancient
choice under explicit caller-declared conditions: Hive assignment has two
outcomes; Glory assignment conditions on whether Hive already received Darv
and preserves the source bound-one draw; Ancient choice conditions on act and
whether that act received Darv. Supply each call's declared ordinal on the
legacy `event` stream after its earlier calls. These laws are `UNVERIFIED` and
do not validate the full shared-pool partition or complete run-start prefix.
The configured experimental preparation boundary validates its Nature laws
and decision prefix. The resumable boundary is limited to the supported
experimental route and does not validate the complete Native run-generation
prefix. Native UpFront pool shuffling, source call-order parity, source pool
fidelity, and native cursor parity remain open.
