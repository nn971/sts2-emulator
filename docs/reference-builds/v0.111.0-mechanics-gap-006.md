## Progress since pass 005

### Whole-card replay and Burst

Pinned source for `BurstPower` and `CardModel.OnPlayWrapper` establishes that Burst is a
**play-count modifier**, not an effect duplicator.

For a matching Skill:

1. the card's play count is modified before its first execution;
2. Burst contributes exactly one additional execution;
3. one Burst stack is consumed after participating in the play-count modification;
4. Energy/resources are spent only once;
5. the card is moved to its result pile only once;
6. each execution independently runs the full card lifecycle;
7. nested player choices occur again on later executions.

The prototype now represents this with `PrototypeCardPlaySeriesState`. A card-play series carries:

- one source card instance;
- one target;
- the resources spent by the original play;
- the total play count;
- the next play index;
- the final source-card disposition.

Each execution rebuilds the card's effects from current combat state and emits its own
`CardPlayed` completion event. If an execution suspends for a card-selection choice, the pending
choice stores the remaining play-series state and resumes the next execution only after the current
choice and completion event finish.

This is materially stronger than replaying a precomputed effect list.

Pinned **Burst** is now represented as:

- 1 Energy;
- Rare Skill;
- apply 1 Burst;
- upgrade applies 2 Burst;
- each Burst stack duplicates one later Skill;
- unused stacks expire at player-turn end.

Regression coverage includes:

- Defend under Burst gains Block twice while paying one Energy;
- Survivor under Burst presents two independent discard decisions;
- Burst+ applies two stacks and duplicates two successive Skills.

### Power-card result-pile semantics

Static `CardModel.GetResultPileType()` shows that Power cards use `PileType.None`.

The prototype previously treated every non-Exhaust card as going to Discard after play. That was a
prototype shortcut and is now corrected:

- Attack/Skill cards still move to their normal result pile;
- Exhaust cards move to Exhaust;
- Power cards leave all combat piles after their final execution.

The card instance remains in the immutable combat-card registry for identity/history purposes, but
it is no longer in Hand/Draw/Discard/Exhaust.

This correction applies to existing powers such as Footwork and Noxious Fumes as well as newly
imported content.

### Tools of the Trade

Pinned source splits Tools of the Trade into two distinct hook families.

`ToolsOfTheTradePower.ModifyHandDraw` adds its amount to the normal hand draw.

`ToolsOfTheTradePower.AfterPlayerTurnStart` then selects exactly that many cards from Hand for
discard.

The prototype now represents these as stage-native power policies:

- `HandDrawBonusPerStack`;
- `DiscardAfterPlayerTurnStartPerStack`.

Pinned **Tools of the Trade** is represented as:

- 1 Energy;
- Rare Power;
- upgrade reduces cost to 0;
- draw 1 additional card during each normal hand draw;
- after player-turn start, suspend for exactly 1 discard per stack.

The existing generic hand-discard continuation is reused, so selecting a Sly card still follows the
normal discard/Sly lifecycle instead of bypassing it.

## Static-source lessons from this pass

### Replay is not one mechanic

The corpus uses several superficially similar ideas:

- Burst-style hook-driven additional play count;
- intrinsic/card-local Replay;
- generated duplicate cards;
- auto-play;
- repeated scalar hits.

These must remain distinct in the mechanics taxonomy.

The gap analyzer now reports Burst text as `next_skill_replay`; it does **not** mark the general
`replay` feature as implemented.

### The correct continuation boundary is the card lifecycle

A suspendable effect queue alone is insufficient for full fidelity.

Burst demonstrates that the continuation model must be able to suspend and resume:

- inside one card execution;
- between repeated executions of the same card;
- before final source-card movement/cleanup.

The new play-series state provides that boundary without introducing card-name branches.

### Some native hooks are better modeled as stage policies first

Tools of the Trade technically performs a player choice from `AfterPlayerTurnStart`.

The generic event-subscriber dispatcher still rejects arbitrary subscribers that suspend midway
through a subscriber list. For Tools, the exact source semantics are represented with explicit
hand-draw and post-turn-start policies instead.

This is intentional: the current implementation is behaviorally source-backed for Tools without
claiming that arbitrary hook suspension is solved.

## Current high-value frontier

### 1. General automatic-hook suspension

The remaining architectural gap is a continuation for an event dispatch itself:

- remember which subscribers have already run;
- suspend for a player choice;
- resume the same subscriber;
- continue later subscribers in deterministic application order;
- then resume the containing automatic turn pipeline.

This will be needed for future powers/relics that request choices from hooks outside a terminal
turn stage.

### 2. Delayed selected-card effects

Pinned **Nightmare** is the next representative card:

- select a card now;
- remember the selected card identity/state;
- next turn create copies of that selected card.

This requires a typed delayed payload rather than only scalar next-turn powers.

### 3. Card-local temporary keyword mutation

Remaining examples include:

- Expertise — drawn cards gain temporary Retain;
- Hand Trick — selected Skill gains temporary Sly;
- Master Planner — played Skills acquire Sly.

Combat-card state already exists. The next step is a typed keyword-override layer with cleanup
rules, not ad hoc booleans.

### 4. Intrinsic Replay

Burst support does not yet imply support for card-local Replay.

Intrinsic Replay should feed the same generic card-play-series machinery, but its count belongs to
the card instance/enchantment state rather than to a consumed player power.

### 5. Aggregate/value-query effects

Examples still include:

- Mirage — Block from total Poison across enemies;
- Accuracy — Shiv damage modification;
- Tracking — extra Attack damage against Weak enemies;
- Phantom Blades — first Shiv each turn gets bonus damage.

These should extend the typed value/count/predicate layer.

## Recommended next implementation order

1. delayed selected-card payloads, beginning with Nightmare;
2. typed combat-card keyword overrides;
3. intrinsic Replay using the new card-play-series machinery;
4. general event-dispatch suspension;
5. aggregate/value-query effects.

A new reference-bridge build or game restart is still not justified.
