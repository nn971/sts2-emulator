# v0.111.0 mechanics gap 137 — Silent Shiv token integration

The pinned source defines Shiv as a generated token rather than a member of
the ordinary Silent card reward pool. Its source record is
[`Shiv.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Cards/Shiv.cs),
blob SHA-256 `eb92dcec378fe8897f7b088de7cb78354562f65167eeceff8b95dfc6912f10c8`.
`StormOfSteel.cs` is pinned at blob SHA-256
`e492961648ad565b6525f1b51ad615b90fa770b3e54b12d2d49a56a8d5be5423`.

The coverage report previously used reward-pool membership as the only ordinary
card integration witness, so it marked this correctly excluded token as
unintegrated. Coverage now resolves the real card-play series for base and
upgraded Blade Dance, producing three and four Shivs, and base and upgraded
Storm of Steel, producing two Shivs or two upgraded Shivs from two other cards
in hand. It also checks that Shiv remains a non-reward-eligible Token Attack
with Exhaust and 4/6 damage across its base and upgraded variants.

This changes the integration evidence only; it does not add Shiv to a card
reward pool or claim native replay parity. Reproduce with
`python tools/check_v111_coverage.py` after building the Release CLI.
