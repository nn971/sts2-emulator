# v0.111.0 source-audited summon hooks: Living Fog and Surprise Power

Pinned source: `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`.

## Source audits

- `Core/Models/Monsters/LivingFog.cs: BloatMove()` invokes
  `CombatState.Encounter.GetNextSlot(combat)` before
  `CreatureCmd.Add<GasBomb>`. In `EncounterModel.GetNextSlot`, the
  first unoccupied slot in `LivingFogNormal.Slots` is selected. The
  slots are ordered `bomb1, bomb2, bomb3, bomb4, bomb5, livingFog`.
  Therefore the first Gas Bomb spawns in **bomb1**, not `bomb5`.
  The v111 opt-in combat implementation now sets first-slot selection
  only for source-identified Living Fog summoning; the prototype default
  and Two-Tailed Rat last-slot preference are not changed.
- `Core/Models/Powers/SurprisePower.cs: AfterDeath()` on Gremlin
  Merc has an unusual, important creation order:
  1. `CombatState.CreateCreature(FatGremlin, "fat")` rolls its
     `run.niche` HP and gives it **CombatId 2**, without adding it
     to the active enemy list;
  2. `CreatureCmd.Add<SneakyGremlin>(..., "sneaky")` creates the
     Sneaky Gremlin with **CombatId 3**, advances `run.niche` again,
     and adds it immediately;
  3. `CreatureCmd.Add(fatGremlin)` adds the previously created
     Fat Gremlin, so the final turn/slot order is **Merc, Sneaky, Fat**,
     but the native CombatId order is **1, 3, 2**.
  Thievery gold is transferred to Fat's Heist power, not Sneaky's.
- `Core/Entities/Creatures/Creature.SetUniqueMonsterHpValue` reads
  MaxHp for **all attached enemy creatures**, including a zero-HP
  creature whose death hook has not finished. The typed prototype
  retains historical dead enemies after native combat would have
  detached them, so those archived enemies must **not** affect later
  HP rolls. The opt-in path accepts an explicitly identified dying
  source during AfterDeath; ordinary enemy-turn summons exclude only
  living enemies. Precreated-but-not-added Fat does *not* contribute
  to Sneaky's HP uniqueness exclusion even though Fat's `run.niche`
  roll occurred first. We implement this exception only for this
  audited death hook. Neither spawning case consumes legacy
  prototype combat RNG for HP.

## Emulator changes

`NativeCombatRngEntryV111.SortGremlinMercDeathPair` atomically
permutes the typed enemy array alongside its native formation specs
and creature-local RNG contexts, without renumbering or reseeding
monster CombatIds. The model lifetime IDs and contexts remain stable
through deterministic combat snapshots and later summons.

`PrototypeGameEngine.ResolveEnemyDeathSummons` retains old creation
order and HP semantics in default runs, but in the pinned native
`GremlinMercNormal` mode it creates Fat before Sneaky, tracks Fat
as precreated/unattached for Sneaky's HP draw, then performs the
source addition-order permutation. Unexpected death-summon inventories
fail explicitly instead of introducing apparent native parity.

## Still unsupported

- Actual native transformation / in-place model mutation has not
  been migrated. In particular, `ToughEgg.Hatch()` in the native
  source changes the original creature's HP and move state without
  creating a new `Hatchling` creature; the legacy prototype
  `TransformEnemy` abstraction is **not** equivalent. Its native
  path still rejects rather than falsely reusing a monster-local RNG.
- Unverified randomized summon pools, cross-character mechanics and
  monster-specific hooks remain out of scope.
- Full combat execution, rewards and the Act 1 encounter-selection
  bag are still prototype-backed. A clean native game trace is
  required before exact end-to-end parity can be asserted.

## Regression tests

- The live Living Fog native entry integration test checks a bomb
  appears in slot `bomb1` through two real enemy turns, with
  reproducible snapshot and native HP cursor.
- The `SurprisePowerNativeDeathPrecreatesFatButAddsSneakyFirst` test
  independently checks **96 seeds** of Gremlin death creation order,
  both niche HP results, relative native IDs, slot order, inherited
  stolen gold, unchanged input snapshots and native RNG sidecar forks.

The implementation remains opt-in under the existing v111 experimental
native combat fidelity ID. Default agent training is unaffected.
