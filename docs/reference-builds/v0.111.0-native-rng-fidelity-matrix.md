# Native v0.111.0 RNG inventory and fidelity acceptance matrix

## Ground truth and provenance

Scope: **single-player Silent, Act 1 Overgrowth**, using native
`v0.111.0 / 41cef1ea` (binary fingerprint
`3bb5598a35f7763c9de22078643ac2777190994b2be85ebd4ebf5c9d154aa45e`).
The exact executable-source map is
`Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`:
`src/Core/Entities/Rngs/{RunRngType,PlayerRngType}.cs`,
`src/Core/Runs/RunRngSet.cs`,
`src/Core/Random/{PlayerRngSet,Rng,MegaRandom}.cs`,
`src/Core/Helpers/StringHelper.cs`, and
`src/Core/Saves/SerializableRng.cs`.

A **stream** is a mutable PRNG state; an **outcome pool** is the weighted or
filtered set of possible choices to which it is applied. Both need fidelity.
The underlying native PRNG uses **xoshiro256** (star-star)**, seeded with four
successive **SplitMix64** outputs. Every saved `SerializableRng` contains
`counter` and four 64-bit words `s0`–`s3` (the passive recorder names
the latter `state0`–`state3`). The current game seed is
`xxHash64(UTF8(seed_string), seed=0)`. A named stream uses that 64-bit
numeric seed plus `xxHash64(UTF8(snake_case(stream_name)), 0)`,
computed modulo 2^64. The constructor expands the resulting 64-bit
seed with SplitMix64.

Native `Rng.NextInt(max)` samples the xoshiro-derived `NextDouble()`,
multiplies by `max` and truncates, consuming one generator step.
`Rng.NextBool()` samples `Next(2)`. Fisher–Yates `Rng.Shuffle` uses
one `NextInt(i + 1)` per swap for i = n−1 down to 1. Rejection-sampled
Gaussian functions can consume a variable number of steps.

**Version sensitivity:** the developer announced an RNG engine switch to
xoshiro256** in v0.107.1 (June 19, 2026); guidance based on the earlier
`System.Random` correlation bug is not applicable to this pin.
`RunRngSet` also retains an `old`-prefixed seed compatibility path
with historical hashing; the audit explicitly declines that path.

## Exact persistent stream inventory

### RunRngType — 12 streams

| Name | Native purpose | Main checks |
| --- | --- | --- |
| `UpFront` | Pre-generated rooms, encounters and relic bags | Run initialization, room/boss selection, bag depletion |
| `Shuffle` | Initial combat and discard reshuffle order | Fisher–Yates and draw timing |
| `UnknownMapPoint` | Room type at unknown nodes | ?-room distribution and persistent odds |
| `CombatCardGeneration` | Random card creation during combat | Eligible card pool, filtering and draws |
| `CombatPotionGeneration` | Combat potion creation | Exclusions, selection |
| `CombatCardSelection` | Randomly select an existing card | Candidate list and order |
| `CombatEnergyCosts` | Confusion/Snecko-style random costs | Card identity, cost timing and bounds |
| `CombatTargets` | Random attack/ability targets | Alive/targetable filtering and repeated targeting |
| `MonsterAi` | Randomized enemy intents | Conditional weights, move-repeat constraints |
| `Niche` | Miscellaneous content RNG; also monster HP sampling | Call sites and sharing |
| `CombatOrbs` | Defect random orbs | Deferred in Silent milestone |
| `TreasureRoomRelics` | Shared treasure relic allocation | Multiplayer-only usage deferred |

The **native property** `CombatOrbGeneration` maps to enum value
`CombatOrbs`. These names must be preserved distinctly.

### PlayerRngType — 3 streams per player

| Name | Native purpose | Main checks |
| --- | --- | --- |
| `Rewards` | Reward cards/potions/relics, drop checks, reward gold | Rarity/pity, draw order, per-reward call counts |
| `Shops` | Shop inventory | Offer pools, exclusions, price modifiers |
| `Transformations` | Random transformed card | Eligibility and replacement constraints |

A new player has numerical seed
`xxHash64(UTF8(run_seed)) + player_slot_index`, modulo 2^64.
Each player stream adds its own snake-case-name hash as above.

### Additional context-specific RNGs (outside the 15 persistent enums)

These also come from the pinned game and must be represented by their
**derivation/lifecycle**, not collapsed onto a generic `combat` stream:

| Context | Native initialization | Status |
| --- | --- | --- |
| Standard Act n map | `Rng(run_seed_numeric, "act_n_map")` | Generated on map creation |
| An encounter's formation | `Rng(run_seed_numeric + TotalFloor + xxHash64(encounter_id))` | Per encounter, when generating monsters |
| A monster model | `Rng(run_seed_numeric + map_col + map_row + CurrentActIndex + Creature.CombatId)` | Created for each creature |
| Event instance | `Rng(run_seed_numeric + (shared ? 0 : player_slot) + xxHash64(event_id))` | Created at event begin |
| Particular piece of player content | `Rng(run_seed_numeric + player_slot + xxHash64(model_id) + mixin)` | Explicit optional mixin |
| Cosmetic randomness | `Rng.Chaotic`, time seeded | Outside gameplay parity |

The monster intent state machine receives `RunRng.MonsterAi`, while
`MonsterModel.Rng` is a different, per-creature generator. Monster
HP uniqueness rolls use `RunRng.Niche`; some moves therefore advance
shared run streams and other effects may advance local ones. The
standard map uses an independent act-specific generator rather than
the `UpFront` stream. Source locations:
`StandardActMap.CreateFor`, `EncounterModel.GenerateMonstersWithSlots`,
`CombatState.CreateCreature`, `MonsterModel.RollMove`,
`EventModel.Begin` and `Rng(Player,ModelId,mixin)`.

## Fidelity taxonomy and acceptance policy

| Category | Verify | Minimum for training-ready native-shape Overgrowth |
| --- | --- | --- |
| F1 Content | Metadata, values, Ascension, pools and eligibility | Source match + fixture |
| F2 Mechanics | Deterministic effects, statuses, turn/death/hook order | Source match + isolated differential |
| F3 Actions | Legal actions, targets, card identity, suspend/resume | Public-frame equivalence + isolated differential |
| F4 Random laws | Support, weights, pity, conditional rolls, history constraints | Source match + probability/distribution audit |
| F5 RNG engine | Codec, seed, stream ownership and consumption | Native stream map documented; exact seed replay separate |
| F6 Run generation | Map paths/rooms, encounters, Neow, rewards, shops, transitions | Native-shaped generator + sampled native checks |
| F7 Hidden/public state | Fork and save/load isolation; hidden information | Deterministic state and explicit fair observation projection |
| F8 Performance | Fork cost, simulation speed, memory, stable API | Regressions and measured throughput, later |

Verification levels should be tracked *per mechanic*:

- **L1: static pinned-source match** (algorithm/value documented);
- **L2: isolated differential match** (controlled action and state);
- **L3: distribution match** (including conditioning on history);
- **L4: exact-seed replay match** (intermediate states **and** RNG).

For strategy training, prioritize **L1+L2 on deterministic semantics
and L1+L3 on decision-relevant random laws**. L4 is the high-fidelity
target, not a prerequisite for initial useful policies.

## Emulator difference and recommended migration

The current `PrototypeRng` has exactly **six SplitMix64 streams**:
`map`, `combat`, `combat_targets`, `reward`, `shop`, `event`.
Its seeds are **SHA-256(seed + newline + stream ID)**, and its
`NextInt(max)` uses **modulo reduction**. The native v0.111.0
generator instead uses xxHash64 named seeds + SplitMix64 initialization
of a **256-bit xoshiro state**, and its bounded integers are based
on multiplication of `NextDouble`. Thus identical seeds currently
cannot give exact native RNG outcomes.

More importantly, the prototype's shared `combat` stream couples
random events that native STS2 separates: initial shuffle, monster
AI, card generation/selection, energy-cost randomness, etc. Replacing
the PRNG algorithm alone would preserve this incorrect dependency
graph.

Recommended order:

1. Introduce a **versioned native 12+3 stream map**, with individual
   per-map/per-encounter/per-monster/per-event constructors, preserving
   prototype semantics behind its existing codec.
2. Implement the exact wrapper (next int/float/double, shuffle,
   weighted draw and variable-draw distributions), and validate
   against saved native state/counter checkpoints.
3. Audit call-site ownership and roll order on the three captured
   elites and boss, then add explicit state-injection fixtures and
   first-divergence reporting.
4. Audit loot and encounter **outcome pools separately**, including
   order, exclusions, pity and without-replacement state.
5. Expand the native-check corpus and establish L4 replay gradually.

The user's uploaded passive trace already gives a strong RNG
state-evolution oracle; it does not contain every transient
per-entity generator and cannot by itself prove source-call
attribution.

**Statistical caution:** the 15 native RNGs are distinct deterministic
substreams derived from a **shared run seed**. Treating their *initial
states* as independent uniform variables is an explicit modeling
approximation, rather than the exact native one-seed distribution.
The separate factorized prior in
`docs/FACTORIZED_INITIAL_RNG_PRIOR.md` is therefore experimental
by design and must not be silently promoted to native parity.
