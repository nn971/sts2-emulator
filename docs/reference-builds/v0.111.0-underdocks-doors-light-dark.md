# Underdocks Doors of Light and Dark event audit

Target: single-player STS2 v0.111.0 / source commit
`706ef1c9fa2219220065849fd5265328607ece20`.

The pinned [`DoorsOfLightAndDark.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Events/DoorsOfLightAndDark.cs)
has source SHA-256
`ef7233f0b82ec9e37577bd3541d599acfd1709bba37c3bf0ffeb4e9f0381306f`. Light
stable-shuffles deck cards for which `IsUpgradable` is true, upgrades up to two
distinct cards, and finishes the event. Dark removes one selected deck card and
then finishes the event. Both choices retain their finished result page until
the player continues.

The complete source branch inventory has seven paths:

| Source path | Behavior | Verification |
| --- | --- | --- |
| `page/INITIAL` | Present Light and Dark. | `LightUpgradesTwoDistinctCardsAndDarkOffersRemoval` checks both legal choices. |
| `initial/LIGHT` | Select Light. | Same test selects the source option and checks two cards upgrade. |
| `page/INITIAL/LIGHT` | Resolve Light's initial choice. | Same test verifies a completed result page with `continue_event` as its only action. |
| `page/LIGHT` | Show the Light result and return to the map. | Same test continues to map choice; `DoorsLightFinishesWhenNoCardCanBeUpgraded` checks the empty-candidate completion. |
| `initial/DARK` | Select Dark and offer one card removal. | Same test checks the pending removal choice and chooses one legal card. |
| `page/INITIAL/DARK` | Resolve Dark's initial choice and selected removal. | Same test verifies that exactly the selected card leaves the deck and the result page opens afterward. |
| `page/DARK` | Show the Dark result and return to the map. | Same test checks the terminal page and explicit continuation to map choice. |

`PrototypeNativeUnderdocksDoors` samples Light's upgradable-card pool without
replacement, then uses the shared event continuation for both finished choices.
This preserves the source mechanic that a card is upgraded at most once per
Light selection. The current shuffle uses the prototype event stream; exact
native `StableShuffle` cursor parity remains part of the desired RNG work.
Dark uses the shared persistent deck-removal prompt. This branch audit does not
claim live-game RNG parity or native certification.
