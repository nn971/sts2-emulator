# v0.111.0 mechanics gap — pass 033

This pass narrows the active Act 1 fidelity milestone to **Overgrowth** and translates its native
weak-encounter queue into explicit, forkable run state.

## Region state

Act 1 now has a typed region identity:

- `Overgrowth`;
- `Underdocks`.

New prototype whole runs currently initialize as **Overgrowth**. Underdocks is intentionally not
selected or advanced by this pass; it remains a deferred region variant in the completeness ledger.

The chosen Act 1 region is part of canonical world state and is exposed in the AI observation because
the region is player-visible information.

## Weak encounter queue

Pinned Overgrowth source behavior is represented as a four-entry weak pool:

- `NIBBITS_WEAK`;
- `SLIMES_WEAK`;
- `FUZZY_WURM_CRAWLER_WEAK`;
- `SHRINKER_BEETLE_WEAK`.

The first three **ordinary monster combats** consume three distinct entries from this pool.

The implementation stores:

- the Act 1 region;
- the count of ordinary combats already started;
- the remaining weak encounter IDs.

Selection is uniform over the remaining IDs. The selected ID is removed immediately, so no weak
encounter can repeat during the three-combat weak phase.

This is distributionally equivalent to drawing three entries without replacement. Exact native RNG
state encoding and call order are still outside the current parity claim.

## Room-type boundary

Only `PrototypeRoomType.Combat` consumes the weak queue.

In particular:

- elites do not advance it;
- events do not advance it;
- shops do not advance it;
- rest sites do not advance it;
- bosses do not advance it.

This is important because the weak phase is based on the number of ordinary monster combats, not the
map floor number.

## Fork semantics

The queue lives in `RunWorldState` and deep-clones its remaining-ID array during `Fork()`.

Search branches can therefore consume different weak encounters without mutating sibling states.
The ordinary-combat counter and remaining set are also covered by structural invariants.

## Validation

The invariant layer rejects:

- negative or greater-than-three weak-combat counters;
- pool-size/counter disagreement;
- duplicate remaining encounter IDs;
- encounter IDs foreign to the Overgrowth weak pool;
- disagreement between the run region and encounter-pool region.

Focused tests verify:

- new runs initialize with all four Overgrowth weak encounters;
- the first three ordinary combats are distinct and consume the queue one entry at a time;
- an elite inserted before them leaves the queue untouched;
- the fourth ordinary combat no longer consumes weak-pool state;
- forked branches own independent weak-pool arrays;
- the AI observation exposes Overgrowth.

## Transitional fourth-combat behavior

Only the weak queue is promoted in this pass.

After three weak combats, ordinary combat selection currently falls back to the older prototype
weighted selector. That fallback is deliberately **not** claimed as native Overgrowth normal-pool
behavior.

The next pass should replace that fallback with a typed Overgrowth normal pool once enough normal
encounters are source-backed.

## Scope decision

The active completion target is now Overgrowth only.

Underdocks remains listed in `ACT1_COMBAT_COMPLETENESS.md`, but new mechanics, formations, pool
translation, and oracle work should preferentially advance Overgrowth until that region is complete.
