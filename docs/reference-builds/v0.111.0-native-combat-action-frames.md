# Native combat card action frames — identity and limits

Target branch: `prototype/full-run-silent`. Scope: **pinned STS2 v0.111.0, single-player Silent, Act 1 Overgrowth**.

## The bridge increment

The passive recorder now includes an optional `recorder_card_id` on native card-model projections in **both** player card piles and CombatHistory entries. The ID is allocated by **reference equality** of the actual native card object, monotonically within a combat. It is reset at CombatSetUp and cleared at CombatEnded/shutdown. It is an **observer-local identifier**, not a game card GUID or deck order, and makes duplicate copies of the same base card distinguishable across callbacks.

The existing `sts2-reference-probe-v4` schema and subscriptions are retained; the new field is additive. The recorder remains read-only, pinned to the exact game hashes, and does not patch action dispatch. An entry from an older v4 capture simply lacks `recorder_card_id`; consumers must treat its identity as class-only.

Native card identity is recorded as an independent dimension from native `ModelId` (e.g. `STRIKE_SILENT`) and from an emulator-side `CombatCardInstance.InstanceId`. Translation into emulator identities belongs to a controlled replay fixture.

## Action-frame extraction

```fish
python tools/native_overgrowth_action_frames.py \
  '/path/to/overgrowth-silent-act1-capture.jsonl' \
  --combats 5 6 9 --output /tmp/native-action-frames.json

# Include all numbered combats (the default):
python tools/native_overgrowth_action_frames.py \
  '/path/to/overgrowth-silent-act1-capture.jsonl' \
  --output /tmp/native-action-frames.json
```

The analyzer streams the JSONL, pairing `CardPlayStartedEntry` with `CardPlayFinishedEntry` by a stack so that nested plays can be reported. Each complete pair carries the card runtime class, observer-local card ID (when present), native target combat ID, start/end sequence, and the intervening observed history effects. Snapshot projections include HP, block, energy, **ordered visible hand**, public discard/exhaust, player/enemy power amounts and enemy HP. They omit draw-pile contents and native RNG state. `PlayerEndedTurn` is separately recorded as a passive marker, with its own confidence class.

The extractor flags mismatched card types/IDs and unmatched callback pairs, and reports a count of plays with strong card-object evidence. For a legacy capture, `card_class_only` is an explicit confidence value. No per-combat history or trace bytes enter Git.

## Fidelity boundary

A `CardPlayStartedEntry` callback can occur **after** some costs and lifecycle effects. A `CardPlayFinishedEntry` can occur **before** cleanup or subsequent queued effects. Accordingly the exported state fields are named `at_start_callback` and `at_finish_callback`, never “pre-step” and “post-step.” Damage and powers observed between these callbacks are evidence of an effect interval, rather than an attribution theorem: queued actions, passive powers and reactive hooks can interact.

This phase provides a **card-instance identity bridge and conservative action-frame IR**, ready for first-divergence diagnostics. A later step must add stable *post-quiescence* decision boundaries, faithful native legal-action capture, action/reward choices outside combat, and explicit RNG handling. The current corpus supports an action *observation* comparison, not exact emulator replay.

`python tools/native_overgrowth_action_frames_smoke.py` tests duplicate-card identity, target tracking, event spans, visible-only projection, legacy v4 fallback, mismatch reporting and per-combat filtering. GitHub CI also runs the existing .NET tests and native ledger tests.
