# v0.111.0 mechanics gap — pass 027

This pass adds the first reusable enemy status-card insertion primitive and promotes **Leaf Slime (S)**
and **Leaf Slime (M)** as source-backed Act 1 monster models.

## Enemy-created combat cards

Enemy move effects can now create combat-local cards directly in the player's discard pile.

The new typed effect carries a card ID and count. Each inserted card receives:

- a fresh combat-local instance ID;
- no persistent deck identity;
- normal combat-card state;
- active source-bound Afflictions through the same generated-card path used elsewhere.

This is intentionally a zone-specific primitive. It does not reuse create-in-hand semantics, so hand
size and draw-event behavior cannot accidentally affect enemy status insertion.

## Slimed

`proto.status.slimed` now represents the native status card used by Overgrowth slime enemies:

- cost 1;
- draw 1 card;
- Exhaust on use;
- Status rarity/type;
- excluded from normal rewards.

Enemy-created copies are combat-local and leave the persistent deck unchanged.

## Leaf Slime (S)

Pinned Act 1 values:

- HP 11–15 at A0–A7;
- HP 12–16 at A8+;
- Tackle: 3 damage, 4 at A9+;
- Goop: add 1 Slimed to the discard pile.

Its source-shaped state machine begins in a random state choosing Tackle or Goop. Both branches use
`CannotRepeat`, then return to the same random state.

## Leaf Slime (M)

Pinned Act 1 values:

- HP 32–35 at A0–A7;
- HP 33–36 at A8+;
- Sticky Shot: add 2 Slimed to the discard pile;
- Clump Shot: 8 damage, 9 at A9+.

The native deterministic alternation begins with Sticky Shot, so the existing sequential-loop policy
represents the move graph directly.

## Regressions

Focused tests cover:

- Slimed cost/type/Draw-1/Exhaust semantics;
- Leaf Slime (S) HP and A9 scaling;
- forced Goop creating exactly one combat-local Slimed;
- no immediate repeat after Goop;
- Leaf Slime (M) HP and A9 scaling;
- Sticky Shot creating two Slimed;
- Sticky Shot / Clump Shot / Sticky Shot alternation.

## Deliberate boundary

This pass promotes the two monster models rather than their native encounters.

Still separate:

- slime-group multiplicity and slot order;
- random medium-slime selection in the weak encounter;
- normal slime encounter formation;
- native weak/normal encounter-pool selection.

Twig Slime (M) remains pending because its random attack branch depends on exact
`CanRepeatXTimes` semantics, which should be pinned before production use.

## Next work

The strongest next dependency-driven step is:

1. pin `CanRepeatXTimes` and promote Twig Slime (M), ideally alongside another Act 1 random-state
   user;
2. then use the now-explicit encounter formation specs from pass 026 to promote the weak/normal
   slime encounter constructors;
3. continue summon/despawn/death primitives for the next shared enemy family.
