# v0.111.0 mechanics gap — pass 009

This pass extends card-local state, event-context mutation, Replay, and value-query mechanics.

## Native evidence

Pinned v0.111.0 structured/source evidence establishes the representative cases used here:

- **Master Planner** — Silent Rare Power, cost 2 (1 upgraded): whenever a Skill is played,
  that exact card gains Sly.
- **Replay** — each Replay stack causes one additional full play of the card. The card pays
  its normal resource cost once, resolves its normal play lifecycle once per pass, and moves
  to its result pile only after the series finishes. Pinned-era fixes also establish that
  remaining Replay passes are skipped once the last enemy is dead.
- **Tracking** — Silent Rare Power, cost 2 (1 upgraded): Weak enemies take 50% more damage
  from the player's Attacks.
- **Mirage** — Silent Uncommon Skill, cost 1: gain Block equal to total Poison on living
  enemies. In v0.111.0 the base card Exhausts and the upgrade removes Exhaust while retaining
  cost 1.

## Event-source card mutation

`PrototypePowerTriggerSpec` can now filter `CardPlayed` events by source-card type.
A trigger effect can mutate the exact combat-card instance carried by the event.

Master Planner is data over this primitive:

- subscribe to `CardPlayed`;
- require a Skill source;
- add a persistent combat-local Sly override to the event source.

This is deliberately separate from the "source card" parameter used by an actively resolving
card effect. Event provenance and effect provenance are different identities.

## Card-local Replay

`CombatCardInstance` and `PrototypeCombatCardSnapshot` now carry an integer Replay count.
Replay contributes additional executions to the existing whole-card play-series abstraction:

`total plays = 1 + card Replay + hook-driven additional plays`.

That means intrinsic/card-local Replay automatically inherits the semantics already required by
Burst:

- one resource payment;
- one final source-card movement;
- one `CardPlayed` lifecycle per execution;
- independent nested choices on each execution;
- compatibility with Burst-style play-count modifiers.

Replay and Burst are additive in the prototype. Tests cover Replay 2, Replay with repeated
Survivor choices, and Replay combined with Burst.

Nightmare snapshots preserve Replay along with upgrade level, opaque card state, combat-local
cost state, and keyword overrides.

If an execution defeats the final enemy, the remaining play series is now terminated and the
source card is finalized exactly once instead of running bookkeeping-only extra passes.

## Target-conditioned Attack modifiers

Player Attack modification now has a generic target-status-conditioned percentage component in
addition to tag-conditioned flat bonuses.

Tracking uses:

- required target status: Weak;
- bonus numerator per stack: 1;
- denominator: 2.

One stack therefore contributes +50% Attack damage against a Weak target, while non-Weak targets
are unchanged. Multiple stacks add their percentage contribution.

## Aggregate enemy-status values

A combat effect can now gain Block from the total stacks of a named status across living enemies.
Mirage uses this with Poison.

This query is evaluated when the effect resolves, so dead enemies do not contribute and the value
tracks the current combat state rather than a cached amount.

## Upgrade-sensitive Exhaust

Card definitions can now declare `LoseExhaustOnUpgrade`. Result-pile resolution consults the
actual combat-card upgrade level for both normal play and Sly autoplay.

Mirage is the first acceptance case: base Mirage goes to Exhaust; Mirage+ goes to Discard.

## Remaining structural frontier

The major continuation gap is now **automatic event-dispatch suspension**.

Today an ordinary card execution can suspend and resume nested choices, and whole-card play
series can do the same. An arbitrary power/relic event subscriber that itself asks the player to
choose still cannot suspend in the middle of the ordered subscriber list.

A complete solution should use an explicit continuation stack with frames for at least:

1. remaining effect operations;
2. remaining event subscribers plus current-subscriber cleanup;
3. remaining card-play executions;
4. remaining automatic turn-pipeline steps.

That will avoid encoding special turn stages or hook names into choice handling.

After that structural work, useful source-driven acceptance cases include Phantom Blades and
further enchantment/affliction card-local state.
