# v0.111.0 mechanics gap — pass 007

This pass implements the first typed delayed-card payload and uses Nightmare as the
source-backed acceptance case.

## Native evidence

Pinned structured data for `NIGHTMARE` gives:

- cost 3, upgraded cost 2;
- Silent Rare Skill;
- Exhaust;
- “Choose a card. Next turn, add 3 copies of that card into your Hand.”

The decompiled card/power implementation gives the missing operational detail:

1. `Nightmare.OnPlay` calls `CardSelectCmd.FromHand(..., 1)`;
2. it applies an instanced `NightmarePower` with amount 3 and stores the selected card;
3. `NightmarePower.SetSelectedCard` stores a `CreateClone()` snapshot and clears Affliction;
4. `NightmarePower.BeforeHandDraw` creates `Amount` clones of that stored card in Hand;
5. the power removes itself after those copies are generated.

This also confirms timing: Nightmare resolves before the ordinary hand draw rather than in the
post-draw player-turn-start hook used by Tools of the Trade.

The generic pile implementation adds one more relevant rule: adding a generated card to a full Hand
redirects that card to Discard.

## Emulator changes

The prototype kernel now has:

- a `Preserve` card-selection resolution for read-only hand choices;
- `PrototypeCombatCardSnapshot`, carrying card identity, upgrade, opaque card state, combat cost
  delta, and temporary cost;
- selected-card actions that attach a snapshot to a power;
- instanced powers, allowing multiple same-ID Nightmare powers to coexist with independent payloads;
- exact power-instance identity via application order, so one-shot trigger removal removes the
  triggering instance rather than every same-ID instance;
- power-trigger operations that can generate copies from the source power's card payload;
- full-hand overflow-to-discard for generated-card insertion.

Nightmare itself is therefore data over generic mechanics:

- choose one current Hand card and leave it in place;
- apply an instanced 3-stack `proto.power.nightmare` carrying its snapshot;
- on `BeforeHandDraw`, create one stored-card copy per stack and remove that power instance.

Burst + Nightmare is covered explicitly: each replayed Nightmare execution suspends for its own
selection and produces an independent payload power.

## Gap-analyzer classification

The reference mechanics analyzer now recognizes the specific
`delayed_selected_card_copies` family instead of leaving Nightmare under the generic
`copy_card` gap. The prototype capability manifest marks that family implemented.

## Remaining fidelity boundary

The snapshot captures every card-local state dimension currently represented by the prototype.
Native `CreateClone()` can also carry richer model state that the prototype has not typed yet.
Nightmare explicitly clears Affliction from its stored clone; Affliction itself is outside the
current prototype model.

That makes the next useful source-driven primitive **combat-card keyword/state overrides**. Once
those are typed, the snapshot can carry them naturally instead of teaching Nightmare another
special case.
