## Ceremonial Beast

Ceremonial Beast is represented as a normal enemy state machine plus two reusable power semantics.

Pinned values:

- HP 252, 262 at A8+;
- Stamp: gain Plow 150, 160 at A9+;
- Plow: 18/20 damage + 2 Strength;
- Stun: no action;
- Beast Cry: apply Ringing 1;
- Stomp: 15/17 damage;
- Crush: 17/19 damage + 3/4 Strength.

### HP-threshold enemy powers

Power definitions may now declare that, after a positive HP-loss event, they trigger when the owner's
resulting HP is at or below the power's stack count.

Plow uses this generic mechanism. On trigger it:

- removes itself;
- clears the owner's Strength;
- switches the owner's AI state to the explicit Stun move.

The trigger happens on HP loss, not merely on power application. Therefore if the Beast is already
below the threshold when Stamp applies Plow, it still waits until the next positive HP-loss event,
matching the native edge case.

### Per-turn card-play caps

Player powers may now expose a positive maximum number of cards playable in the current turn.

Ringing is a one-stack debuff with a cap of one card. It is removed at the end of that player turn.
Both legal-action generation and direct card-play validation enforce the same cap.

The focused phase regression exercises:

Stamp -> repeated Plow -> threshold crossing -> Strength reset -> Stun -> Beast Cry -> one-card
Ringing turn -> Stomp.

## Boss selection and run-state visibility

The Overgrowth boss is now selected when the run starts and stored in
`PrototypeActOneEncounterPoolState.BossEncounterId`.

This is deliberate: boss identity is strategic information that should be available to an AI before
the boss room is entered. Selecting only on room entry would make the emulator structurally unable to
support native boss-aware pathing decisions.

The current run emulator assumes the Overgrowth boss set is fully unlocked and chooses one of:

- `CEREMONIAL_BEAST_BOSS`;
- `THE_KIN_BOSS`;
- `VANTOM_BOSS`.

The selected encounter is fork-safe and the boss room simply instantiates it. Boss entry does not
consume weak, normal, or elite bags.

Account/meta-progression is deliberately outside this claim. In particular, progression rules such
as the first-ever-run Vantom guarantee are not being reinterpreted as seeded in-run randomness.

Exact native boss-selection RNG codec/call order also remains a later parity layer.
