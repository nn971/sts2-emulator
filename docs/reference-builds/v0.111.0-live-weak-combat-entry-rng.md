## Explicit opt-in and compatibility

The default configured v111 `FidelityId` remains
`v111-mechanics-prototype-rng-v1`. To opt into the first **live** native
combat RNG integration:

```csharp
var config = RunConfiguration.Create() with
{
    FidelityId = V111Build.NativeWeakCombatEntryFidelityId
};
var run = V111RunFactory.Create("test-seed", config);
```

Only configured single-player Act 1 runs can use this path. No legacy
prototype run, training adapter, or other configured run automatically
changes its outcomes.

When the native-enabled engine selects a supported weak encounter,
`PrototypeGameEngine.StartCombat` now:

1. Resolves the **exact pinned native `EncounterModel.Id.Entry`** and
   independently initializes the encounter formation RNG with
   `RunSeed + TotalFloor + deterministic hash(native entry)`.
2. Uses the source's fixed `GenerateMonsters()` formation instead
   of sampling it from the legacy prototype combat stream.
3. Creates initial enemy instances and starting powers; initializes
   HP maxima through `NativeCombatRngEntryV111.AttachAndRollInitialHp`,
   drawing from the **current persistent `run.niche`** stream.
4. Retains the advanced encounter RNG, monster-local streams (from the
   native combat IDs and map coords) and all 15 persistent run/player
   streams in `CombatState.NativeRng`.
5. Draws any opening monster decisions from native
   `run.monster_ai` rather than shared prototype `combat`.
   Subsequent `CommitEnemyIntents` uses the same native owner.
6. Synchronizes the advanced native run cursors with the run-level owner.
   Fork, whole-run snapshots and subsequent game steps preserve them.

The currently supported source-audited weak encounters are: 

| Act 1 | Native model name | Emulator encounter ID |
|---|---|---|
| Overgrowth | `NibbitsWeak` | `proto.encounter.nibbits_weak` |
| Overgrowth | `FuzzyWurmCrawlerWeak` | `proto.encounter.fuzzy_wurm_crawler_weak` |
| Overgrowth | `ShrinkerBeetleWeak` | `proto.encounter.shrinker_beetle_weak` |
| Underdocks | `SeapunkWeak` | `proto.encounter.seapunk_weak` |
| Underdocks | `SludgeSpinnerWeak` | `proto.encounter.sludge_spinner_weak` |
| Underdocks | `ToadpolesWeak` | `proto.encounter.toadpoles_weak` |
| Overgrowth | `SlimesWeak` | `proto.encounter.slimes_weak` |
| Underdocks | `CorpseSlugsWeak` | `proto.encounter.corpse_slugs_weak` |

The Act 1 map fixture stores ids `1:Floor:Column`; native row is
`Floor - 1` and the player gets native CombatId 0, so the first
created enemy receives CombatId 1.

## Strictly unsupported, not silently approximated

**Two dynamic weak encounters now have exact source-audited generation:**

- `SlimesWeak.GenerateMonsters()` makes three encounter-local
  `Rng.NextItem` calls, in this order: first small slime from
  `[LeafSlimeS,TwigSlimeS]`; the one remaining small slime
  (the singleton roll **still consumes RNG**); then a medium slime
  from `[LeafSlimeM,TwigSlimeM]`. Final formation order is
  **[first small, medium, second small]**, not generation order.
  In particular, the old generic `SelectionGroups` resolver consumes
  only two draws, and must not be called in native mode.
- `CorpseSlugsWeak.GenerateMonsters()` calls
  `CorpseSlug.EnsureCorpseSlugsStartWithDifferentMoves` once.
  That method makes one **encounter-local `NextInt(3)`** draw
  and assigns successive starter move indices modulo three.
  `NativeEncounterFormationV111.EncounterOpeningOffset` retains
  that first draw through combat entry; the engine uses the stored
  offset instead of consuming a second prototype combat RNG draw.
  This encounter-local starter rotation does not come from
  `run.monster_ai`.

Other unsupported normal/elite/boss/event combats still throw
`NotSupportedException` in the experimental mode rather than consume
prototype RNG for native formation or HP. Region-crossed encounters
are likewise rejected.

This experiment still selects encounter IDs using the existing
prototype Act 1 bags and stream, and continues to use prototype
card-shuffle, relic, potion, targeting, reward and other non-migrated
RNG. The map generator is source-shaped, not yet native byte-for-byte.
Some native monster move-state details are source-shaped rather than
proved against real reference traces. **A supported combat RNG path
does not imply entire encounter or complete-run parity.**

```fish
dotnet test Sts2Emulator.sln -c Release --filter FullyQualifiedName~NativeActOneLiveCombatRngV111Tests
```

The tests exercise real configured Overgrowth and Underdocks
RunStart → Neow → MapChoice → first combat → end-turn game transitions
for **all eight** weak encounter types. Additional source-oracle
tests replay Slimes Weak and Corpse Slugs Weak over hundreds of seeds
and compare encounter RNG counters, exact monster ordering and
Corpse Slugs' one-time AI rotation. Strict rejection now applies to
unmigrated normal/elite/boss/event content; other assertions cover
`run.niche` HP, snapshot replay and fork safety.
