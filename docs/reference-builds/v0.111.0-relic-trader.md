# Relic Trader

Relic Trader is integrated in the configured Silent route through the Hive
and Glory. The pinned event implementation is
[`RelicTrader.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Events/RelicTrader.cs)
(blob SHA-256 `d5aec2da5f9924b5b170dd0542898e2774f7024f7d969ec128219c8ef7076b35`).

## Pinned behavior

- The event is unavailable in Act 1 and requires at least five tradable
  relics.
- It shuffles the player's tradable relics and saves up to three. For each
  position, it also draws a replacement from the front of the run's relic
  grab bag. The event presents matching Top, Middle, and Bottom exchanges.
- Selecting an exchange removes the owned relic, obtains its paired relic
  through the normal acquisition path, and finishes the event. If no relic
  remains in the bag, the source factory uses Circlet as its fallback.
- Native `RelicModel.IsTradable` excludes used-up, pickup-effect, melted,
  pet-spawning, Starter, Event, and Ancient relics. The pinned definitions are
  [`RelicModel.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/RelicModel.cs),
  [`RelicFactory.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Factories/RelicFactory.cs),
  and [`RelicGrabBag.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Runs/RelicGrabBag.cs).

## Emulator behavior

`proto.native.shared.relic_trader` is registered once per run for Acts 2 and 3.
The event state persists each selected relic's array position and ID together
with its replacement ID. Replacements come from the existing persistent
Silent relic bag; acquiring one runs the common relic-acquisition hooks. The
model also upgrades existing cards when an acquired relic carries the
`UpgradeAddedCardType` behavior, which covers the three Eggs in the supported
bag. Choosing an exchange retains the native finished page until the player
continues to the map.

The tradable relic check uses the configured ordinary relic pool and modeled
pickup, pet, potion-capacity, and upgrade-on-pickup metadata. The event can
therefore select supported pool relics that are not currently eligible for
replacement draws. Unmodeled used-up state and native bag order, eligibility,
and RNG still require the fidelity review. The coverage report records all
inventoried choices as implemented and integrated; native parity remains
unverified. A Release solution build and the coverage-baseline checker were
run for this change. No tests were run.
