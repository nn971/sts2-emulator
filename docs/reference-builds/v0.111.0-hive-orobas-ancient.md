# Orobas execution status

The configured Silent three-act route now prepares an act-local Ancient for
Hive and Glory at run initialization and opens the assigned event at act entry.
`NativeOrobasEventV111` implements Orobas's eight supported Silent relic offers
through the existing acquisition handlers. It chooses one of Electric Shrymp or
Glass Eye, one of Alchemical Coffer/Driftwood/Radiant Pearl/Sand Castle, and one
eligible starter replacement (Touch of Orobas or Archaic Tooth). The third offer
is locked when neither starter dependency exists. Selected offers, event history
and the event-local RNG cursor persist through snapshots and choices.

Cross-character card mechanics are explicitly postponed by the current user
scope. Sea Glass and Prismatic Gem's foreign-card offer alternative are omitted
from this executable profile. Their future implementation must restore the
full first pool and its character/alternative draws. Colorful Philosophers is
also deferred for the same reason. Orobas branch completeness remains false.

`V111OrobasEventTests` resolves every supported offer, including Glass Eye's
five separate reward groups, Electric Shrymp's Skill enchantment, four Coffer
potions and slots, six Sand Castle upgrades, and both starter replacements.
Tests verify locked/unoffered rejection, repeat-entry rejection, unchanged
input state, snapshots, fork hashes, and return to the unvisited Hive map.
Integration exposed and corrected Coffer's missing four-slot capacity metadata.

Generation currently uses the existing native event-local PRNG for these
three supported pool draws and prototype event randomness for run-start
act-local assignment. RNG fidelity and native replay are deferred. Shared
Darv assignment and execution remain separate outstanding implementation work.

## S0 stochastic site contract: `event.orobas.relic_offer.index_draw`

This row uses `NativeOrobasEventV111.BeginOpeningWithAudit` at the Act 2,
floor 0, unvisited Hive Ancient boundary. Its owner is the event-local
`context.event.OROBAS.player_0` stream and the three ordered request ordinals.
The semantic operation is one bounded index choice per offer pool. The
source-shaped eligible supports are the ordered Pool 1/2/3 relic IDs after
`IsChoiceEligible` filters the starter-dependent Pool 3; an empty Pool 3 is
represented by its locked placeholder and still occupies the third request.
The current Silent profile omits unsupported foreign-character alternatives.

The ordered pools and player eligibility are private generation constraints.
The event saves the selected `OfferedChoiceIds` and event RNG state. The player
observation projects the offered IDs and visible choice values through
`PrototypeAiEnvironment`. `ChanceLawEngineV111.QueryAncientOffer` and the
opt-in JSONL `chance_law_query` operation return an outcome-blind law over
stable choice IDs with support and conditioning fingerprints. The same query
operation also covers Pael and Tezcatara; `QueryOrobasOffer` remains a
compatibility entry point. `ReferenceNatureAncientOfferSessionV111` now adds an
atomic three-choice session for all three sites. It keeps partial choices and
the sampler cursor private to the session, then resolves the completed
transcript through the existing event generator with a scripted provider.
Fork, save, restore, and JSONL handles preserve and replay-check the complete
session. The session and event retain the conditioning information through the
origin snapshot and decision transcript; the event's compatibility fields do
not add a separate support-fingerprint property. The Python binding exposes
`State.begin_reference_nature_ancient_offer(site_id, nature_seed=None)`.
There is no privileged-inspector projection in this contract; native Fidelity
Inspector work remains outside scope.

The selected offers enter the ordinary event-choice action path, which applies
the selected relic effect once. The atomic offer session commits the run and
ReferenceNature cursor only after all three offers resolve; the counterfactual
provider does not advance the native event cursor. `UNVERIFIED` is the
probability provenance: native stream ownership and source pool evidence do
not by themselves establish a calibrated conditional law. Unsupported
provider modes and invalid opening boundaries throw before a child state is
published.

The dependency notes below describe earlier incremental work and its source
references; historical gating statements are superseded by this status.

# Hive Ancient: Orobas dependency audit

Target: single-player STS2 v0.111.0 / source commit
`706ef1c9fa2219220065849fd5265328607ece20`.

This is a source audit for the currently missing Hive Ancient. It does not
claim that Orobas is executable or assigned in normal runs. The exact event
source is [`Orobas.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Events/Orobas.cs)

## Opening offers

`GenerateInitialOptions` creates exactly three relic options in order:

1. From a three-entry list consisting of Electric Shrymp, Glass Eye, and one
   additional option. The additional option is Prismatic Gem with probability
   `0.3333333`; otherwise it is Sea Glass configured for one randomly selected
   unlocked character other than the owner. If there is no other unlocked
   character, Sea Glass falls back to the current character. One option is then
   selected uniformly from this three-entry list.
2. One uniformly selected relic from Alchemical Coffer, Driftwood, Radiant
   Pearl, or Sand Castle.
3. One uniformly selected relic from the currently eligible subset of Touch of
   Orobas and Archaic Tooth. Touch requires a starter relic; Archaic Tooth
   requires a transformable starter card. If neither is eligible, the source
   exposes a locked placeholder option.

The source call order is character selection, the Prismatic Gem float roll,
selection from the first three-entry list, selection from Pool 2, then selection
from Pool 3. Empty or singleton candidate behavior and each primitive's stream
consumption must remain explicit when this generation is migrated to native RNG.
The event uses its owned event RNG; the source code alone does not establish
the correct earlier run-start Ancient assignment draw sequence.

Every relic source is pinned in `data/coverage/v111-inventory.json`. In
particular, Sea Glass and Prismatic Gem cannot be implemented faithfully using
the current Silent-only reward catalogue. Offering placeholder relic effects
would make the Ancient reachable while leaving its selection branches
incomplete, so the Ancient must stay unassigned until each offered dependency
is executable.

## Integration sequence

1. Implement the shared acquisition continuations listed above, preserving
   event/reward parent state, independent relic instances, and snapshot/fork
   behavior.
2. Add Orobas's persisted three-option opening and its special relic-instance
   data (Sea Glass character, Touch starter/upgraded relic, Archaic Tooth card
   transform).
3. Add branch tests for each selectable relic, locked Pool 3, empty eligible
   card/potion/relic cases, event-context draw order, and snapshot restore.
4. Integrate Orobas into Hive Ancient dispatch only after all three visible
   options can resolve to completion.
5. Audit run-start Ancient assignment and `run.up_front` draw order separately;
   this event audit does not authorize or imply a normal assignment policy.
