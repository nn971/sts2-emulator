# Underdocks Sunken Treasury event audit

Target: single-player STS2 v0.111.0 / source commit
`706ef1c9fa2219220065849fd5265328607ece20`.

The pinned [`SunkenTreasury.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Events/SunkenTreasury.cs)
has source SHA-256
`aff29a71527bf8fe8b091ee99b9365b30a55a2e1bd6bf7ea8036e8c7d8598ab0`. On
entry, the event stores a small-chest roll of 60 plus `NextInt(16) - 8` and a
large-chest roll of 333 plus `NextInt(61) - 30`. First Chest grants the stored
small amount. Second Chest grants the stored large amount and adds Greed to the
deck. Both choices finish the event and expose a result page.

The complete source branch inventory has seven paths:

| Source path | Behavior | Verification |
| --- | --- | --- |
| `page/INITIAL` | Present First Chest and Second Chest. | `TreasuryPersistsBothRollsAndChoicesSettleOneRolledAmount` checks both source options and the two entry rolls. |
| `initial/FIRST_CHEST` | Choose the small chest. | Same test verifies the selected gold equals the stored roll. |
| `page/INITIAL/FIRST_CHEST` | Resolve the initial First Chest choice. | Same test checks the event remains on a finished result page. |
| `page/FIRST_CHEST` | Show the small-chest result, then return to the map. | Same test continues explicitly and checks no Greed was added. |
| `initial/SECOND_CHEST` | Choose the large chest. | Same test verifies the selected gold equals its stored roll. |
| `page/INITIAL/SECOND_CHEST` | Resolve the initial Second Chest choice. | Same test checks the finished result page after Greed is added. |
| `page/SECOND_CHEST` | Show the large-chest result, then return to the map. | Same test continues explicitly and checks exactly one Greed card. |

`PrototypeNativeEventCompletionPages` describes the two terminal choices, and
the shared continuation preserves the result page until `continue_event`.
Branch effects use the already persisted event amounts and consume no extra
draw on the result or continuation pages. The event-entry `NextInt` calls still
use the prototype event stream; native cursor parity remains open.
