# v0.111.0 native combat RNG: HP + AI snapshot integration

Source pin: `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`,
`Core/Combat/CombatState.cs`, `Core/Entities/Creatures/Creature.cs`,
`Core/Models/MonsterModel.cs`, and
`Core/Models/EncounterModel.cs`.

## What is integrated

The `CombatState` record has an **optional** `NativeRng` sidecar
(`NativeCombatRngV111`). In a native-RNG combat it owns:

- `RunStreams`: the pinned twelve `run.*` and three `player.*`
  xoshiro256** streams (including `run.niche` and `run.monster_ai`).
- `Formation`: the already generated encounter-local RNG cursor, its
  monster specs, and each monster's independent initial or advanced
  `MonsterModel.Rng` cursor keyed by native `CombatId`.

These streams are deep-forked with `CombatState.Fork()`, persist through
normal JSON serialization, and are checked by
`NativeCombatRngEntryV111.Validate` (also invoked by
`PrototypeStateInvariants.ValidateCombat`).

`NativeCombatRngEntryV111.AttachAndRollInitialHp` takes an existing
typed combat (matching a generated native formation), copies the supplied
native run stream bundle, and selects monster max/current HP **in native
creature creation order** from `run.niche`. Per pinned
`Creature.SetUniqueMonsterHpValue`, the candidate set is the inclusive
model HP range **minus earlier monsters' rolled maxima**; if exhausted,
it falls back to the full range. `NextItem` draws even from a singleton.
The set iteration/order is modeled as increasing integer HP. The exact
native source uses a `HashSet<int>`; this order assumption is a
potential parity check for a future oracle comparison.

`PrototypeGameEngine.CommitEnemyIntents` now chooses an RNG based on
the presence of this sidecar: an opt-in native combat draws from
`run.monster_ai` and stores the advanced cursor in the output
`CombatState`, while all other existing combats use the unchanged
legacy `PrototypeRng` combat stream. Both paths use the same typed
state-machine graph for now. No random sampling occurs in Observe.
`NativeCombatRngEntryV111.CommitIntents` exposes the pure native
snapshot commit without running the entire combat turn.

`NativeCombatRngEntryV111.AdvanceMonsterLocal` is a pure copy-on-write
utility for monster-specific randomness, leaving encounter and
`run.monster_ai` streams untouched. It accepts an audited site and owner;
Punch Off's two construct HP reductions use each saved `CombatId`-owned
monster stream when the experimental native combat-entry option is enabled.
The fixed `PunchOffEventEncounter` formation is persisted with its encounter
and creature contexts. Legacy and unopted combat keep the prototype stream;
seeded native outcome and cursor parity remain unverified.

## Fast isolated encounter snapshots

`PrototypeNativeLaterActFixture.CreateCombatRngSnapshot` constructs a
source-shaped Hive/Glory encounter and its typed `CombatState`
**without a full run or a player deck**. It generates encounter formation
from the native `EncounterModel` context, rolls monster HP from
`run.niche`, then optionally commits opening intents using
`run.monster_ai`. Inputs include seed, native and emulator encounter
IDs, act, total floor, ascension, map coordinates and the first actual
native monster combat ID. The result serializes and forks deterministically,
making it useful as a fast low-variance **combat-state RNG snapshot**.

Example test command:

```fish
dotnet test Sts2Emulator.sln -c Release --filter FullyQualifiedName~NativeCombatRngEntryV111Tests
```

## Unverified and intentionally gated

- This is a composable isolated **combat RNG entry** benchmark, **not**
  a playable Hive/Glory route. The default `StartCombat` still uses
  the prototype combat setup. The new sidecar is attached only
  explicitly; no implicit RNG rewiring happens in old fixtures.
- `CreateCombatRngSnapshot` omits drawing the player's deck, card
  effects, relic/potion hooks, rewards, combat completion, multiplayer
  scaling and most source-specific `AfterAddedToRoom` HP modifications;
  Punch Off's two event-specific creature HP reductions are now routed
  through their native monster-local contexts in the opt-in live entry.
  It starts from fresh run RNG streams rather than a prior-act history.
- Exact per-encounter `GenerateMonsters` call order, the native
  `MonsterMoveStateMachine` RNG draws, `run.niche` hash-set
  iteration compatibility, and all between-battle RNG cursor transfer
  require native reference trace validation. Native *ownership* is
  not native end-to-end *parity*.
- Native combat remains gated by an explicit fidelity switch; default live
  entry and the remaining combat draws continue to use the prototype bundle.

The earlier `NativeEncounterFormationFactoryV111` and
`PrototypeNativeLaterActFixture.GenerateEncounterFormation` remain
available to benchmark formation in isolation without HP or intent rolls.
