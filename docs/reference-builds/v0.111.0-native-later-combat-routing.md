# v0.111.0 — Native Hive/Glory encounter routing

**Pin:** `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`.
Catalogs come from `src/Core/Models/Acts/Hive.cs` (20
encounters) and `Glory.cs` (18). The lists are partitioned by
`EncounterModel.IsWeak` and `RoomType`, not by name guessing.

## Newly available, opt-in native-map combat route

| Act | Weak | Normal | Elite | Boss | Total |
| --- | ---: | ---: | ---: | ---: | ---: |
| Hive (2) | 4 | 10 | 3 | 3 | 20 |
| Glory (3) | 3 | 9 | 3 | 3 | 18 |

All entries already had typed encounter/enemy definitions, including
`ConstructMenagerieNormal` in `PrototypeNativeAdditionalNormals`.
The new source-ordered pools **reuse** these definitions: no
second copy of Construct Menagerie is registered.

The first two normal combat entries in an act draw from the weak
encounter list (`ActModel.NumberOfWeakEncounters = 2`); later
normal fights draw from the normal list. Elite and normal queues
are independent; names are drawn without replacement until
exhausted, then refilled. A seeded boss is selected on act setup
and reused at that act's boss node. Event-only combats (Lantern
Key's Mysterious Knight, Glory Battleworn, etc.) do **not**
decrement these bags or the ordinary combat count.

The selected encounter's typed formation, slot names, opening
AI state, scaling and enemy definitions feed the existing
`StartCombat` pipeline. There is no generic fallback when the
native-map encounter bag is missing or in the wrong act.

Combat victory uses the existing source-shaped prototype of
`RewardsSet`: potion odds/pity, gold bounds, card rarity offset
and per-act upgrade chance, and persistent relic grab-bag.
All of these use prototype streams and restricted implemented
Silent/relic pools, not native byte-identical values. Reward
choices and exits return to the original full-sized map,
recording the completed room once. Defeating the Hive boss
offers the standard boss reward and `continue_act` creates a
fresh Glory map/encounter bag while preserving persistent deck,
relics, potions and run history. Defeating the Glory boss can
terminate a fixture run.

## Still unsupported and/or approximate

* **Native RNG and encounter bag history:** This patch models
  independently draining queues with source catalog order and
  first-two-weak staging. Native bag shuffling, encounter
  restrictions, no-repeat policies, exhaustion and source RNG
  ownership/call order still need oracle comparison.
* **Native full-run transitions:** A native v111 production
  `RunConfiguration` still refuses the Act 1 → Hive transition;
  later-act boss transitions currently operate on explicit
  `PrototypeNativeLaterActFixture` maps only. Act-entry Ancients,
  profile unlocks and global route wiring remain unresolved.
* **Other room types:** Shops, treasures and rest sites on
  native Hive/Glory maps still fail closed; Unknown nodes resolve
  using prototype odds and accept only Event or Combat outcomes.
* **Combat/reward fidelity:** Registered enemy mechanics and
  reward systems are not proven native parity. Native character
  pools and exact relic/card/potion odds are incomplete. All
  later-act encounters have registry and native-map integration,
  not validated replay traces.
* **Unlisted special encounters:** The pinned global inventory
  contains event-specific and special fights beyond each act's
  `GenerateAllEncounters`. These are not placed into the
  ordinary source map roster.

## Regression evidence

Focused tests enumerate all 38 IDs with room-type/act checks,
verify Construct Menagerie's fixed 3-enemy formation, first-two
weak routing, normal without-replacement and refill, independent
elites, preselected bosses, fork determinism, live map-node
combat entry, native-shaped reward dismissal, Hive boss →
Glory transition, and rejection of forged cross-act bag state.
Coverage marks all 38 integrated/implemented at the emulator
slice level, while validation remains `unverified`.
