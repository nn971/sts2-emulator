## Ownership and derivation

- A fresh *encounter-local* `Rng` is constructed from the numeric native
  run seed, `RunState.TotalFloor`, and the exact, case-sensitive native
  `EncounterModel.Id.Entry`. The native formula uses unsigned
  64-bit wrapping addition. This stream is **not** `run.monster_ai`,
  `run.niche`, or the legacy shared prototype `combat` stream.
- `NativeEncounterFormationFactoryV111.Generate` resolves the existing
  source-shaped `PrototypeEncounterDefinition` formation using this
  independent stream. It retains the RNG **after** selection in
  `NativeEncounterFormationV111.EncounterRng` so native encounter hooks
  can continue consuming the correct cursor later. Existing
  `ResolveEnemySpecs(RngBundle)` still uses the legacy prototype stream.
- For each selected creature, `NativeEncounterMonsterContextV111`
  carries the independently seeded native `MonsterModel.Rng`,
  constructed from run seed + **zero-based act index** + real creature
  **CombatId** + **native map column/row**. Monster-specific RNGs start at
  counter zero. The native combat ID is *not* necessarily the zero-based
  formation position: the player creature and earlier spawns consume IDs.
- The native RNG snapshots are ordinary canonical, serializable
  `RngStreamState` records and survive `Fork()` without shared state
  bytes. The creator receives a separate formation plus one monster context
  per formation position.

The caller must explicitly supply the **native encounter entry name**,
e.g. `BowlbugsNormal`, distinct from the emulator registry key
`proto.native.hive.encounter.bowlbugs_normal`. We deliberately avoid
guessing the native hash key from emulator naming.

## Concrete source-backed fixture

`PrototypeNativeLaterActFixture.GenerateEncounterFormation` looks up a
Hive or Glory encounter in the typed content registry and checks act
eligibility. It then produces the formation/encounter-stream/monster-stream
handoff without starting gameplay. For instance, Hive's
`BowlbugsNormal` has a fixed Rock in `first` and two distinct workers
from Egg/Silk/Nectar in `middle`/`last`, selected using the
encounter-local context. Glory's `FrogKnightNormal` has a fixed
formation and needs no encounter RNG draws.

## Known limitations and next integrations

This is **RNG seed, ownership and source-shaped formation selection**
integration, **not** exact end-to-end encounter parity.

- Some encounter models have custom `GenerateMonsters()` methods whose
  precise RNG API/call order has not been independently audited. The
  generic `ResolveEnemySpecs` is deliberately not asserted to match
  every native model byte for byte.
- Native `MonsterModel` per-instance HP, attack, spawn and effect draws
  have **not** been migrated. Native distinct-HP assignment may use
  `run.niche`, AI selection may use `run.monster_ai`, and the
  encounter model can consume its own local stream during hooks.
- The current live `PrototypeGameEngine.StartCombat` still uses the
  shared prototype `combat` stream and does not attach the native
  context snapshot handoff to `CombatState`. Do not silently switch
  combat entry until those streams are persisted on the correct owners.
- Native Hive/Glory route generation and incomplete regional
  encounter/event/reward bags remain explicitly gated.
