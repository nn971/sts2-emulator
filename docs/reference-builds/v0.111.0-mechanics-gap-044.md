# v0.111.0 mechanics gap — pass 044

This pass changes the Overgrowth fidelity workflow from targeted synthetic encounter captures to a
small **natural-run oracle corpus** and defines the stopping rule before AI work.

## Natural-run oracle mode

The passive reference bridge now emits `sts2-reference-probe-v4`.

Set:

```fish
set -x STS2_REFERENCE_CORPUS_MODE overgrowth-silent-act1
```

before launching the instrumented pinned build. In this mode the bridge:

- remains passive and does not Harmony-patch gameplay methods;
- keeps CombatManager lifecycle and CombatHistory evidence;
- keeps combat/player/enemy snapshots and native RNG serialization;
- suppresses exploratory runtime type catalogs;
- tags each record with a stable session id and session-local combat index;
- opportunistically projects additional run identity/seed/region fields when exposed by the pinned
  runtime.

The mode is provenance metadata, not a gameplay filter. The intended corpus is several ordinary
Silent A0 runs through Act 1 Overgrowth with no Loadout or other gameplay-modifying mods.

## Fidelity stopping rule

The purpose of this corpus is to catch material emulator mistakes before strategy work. It is not a
gate requiring exact native RNG parity or exhaustive live coverage.

After corpus analysis:

1. fix clear discrepancies that can change legal decisions, damage/block, powers/statuses,
   monster moves, death/summon lifecycles, or encounter construction;
2. record minor, ambiguous, or exact-RNG differences as known gaps;
3. stop broad Overgrowth fidelity work;
4. move to the parent `sts2-ai` prototype and let real search/training workloads determine which
   fidelity or performance gaps deserve the next emulator iteration.

Underdocks remains deferred.
