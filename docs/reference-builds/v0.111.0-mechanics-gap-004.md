This pass continues the static-first workflow. No new live-game capture was needed.

## Progress since pass 003

### Count-backed effects are now generic

The engine now tracks reusable combat counters/query values rather than implementing individual
cards by name.

Implemented count/query families include:

- Skills currently in hand;
- Attacks played this turn;
- cards discarded this turn;
- cards drawn this combat;
- other cards currently in hand.

These support pinned Silent cards including:

- Finisher;
- Flechettes;
- Memento Mori;
- Murder;
- Precise Cut.

Upgrade-dependent count scaling and upgrade-dependent fixed Energy costs are represented directly in
the effect/cost model.

### Random enemy targeting is now a reusable execution-time primitive

`PrototypeEffectTarget.RandomEnemy` delays target selection until each queued operation actually
executes.

Static `AttackCommand` source confirms that random attacks:

1. rebuild the currently live opponent list before each hit;
2. sample through `RunState.Rng.CombatTargets`;
3. allow duplicate targets unless explicitly disabled;
4. naturally exclude enemies killed by earlier hits.

The prototype keeps a dedicated `combat_targets` stream boundary, even though the stream codec is
still provisional.

This supports pinned:

- Ricochet;
- Bouncing Flask;
- random-target power/relic effects.

### Bouncing Flask

Pinned v0.111.0:

- 2 Energy;
- Uncommon Skill;
- apply 3 Poison;
- choose a random live enemy independently for each application;
- repeat 3 times;
- upgrade adds 1 repetition.

No new card-specific logic was required.

### Dexterity power policy is closer to native

Static `DexterityPower` source confirms:

- counter stack type;
- negative values are allowed;
- only powered card/monster-move Block is modified;
- final Block gain is clamped at zero.

The prototype now:

- marks Dexterity as `AllowNegative`;
- preserves negative stacks instead of deleting them;
- applies Dexterity only to card-sourced Block in the current player slice;
- clamps the modified Block gain before adding it to existing Block.

### Thorns is no longer modeled as an after-damage trigger

Static `ThornsPower.BeforeDamageReceived` confirms that Thorns retaliates before the incoming
powered attack damage resolves.

The prototype now:

- handles player-owned Thorns before enemy attack damage;
- handles enemy-owned Thorns before player powered-attack damage;
- lets the already-started hit finish if retaliation kills the attacker;
- prevents later queued attack hits once the attacker is dead;
- treats retaliation as unpowered damage.

The old `EnemyDamaged`-event encoding has been removed from the shared Thorns definition.

### Serpent Form exposed a generic card-play subscription boundary

Pinned Serpent Form:

- 3 Energy;
- Rare Power;
- gain 4 (+2) Serpent Form;
- whenever the owner plays a card, deal that much unpowered damage to a random enemy.

Static source is two-phase:

- `BeforeCardPlayed` stores the current Serpent Form amount for the card being played;
- `AfterCardPlayed` consumes that stored amount and samples `CombatTargets`.

A newly played Serpent Form therefore does **not** react to its own card play.

The emulator now records a power-application-order ceiling at card-play start. Power triggers created
during that card cannot retroactively subscribe to its completion event.

This is intentionally generic and also improves future "whenever you play..." powers.

## Gap-analyzer correction

The analyzer now distinguishes:

- arbitrary random effects;
- the already-supported `random_target` family.

Descriptions such as "damage a random enemy" are classified as `random_target` even when the card
itself has `TargetType.Self` (for example Serpent Form).

This prevents already-supported random-enemy mechanics from remaining false positives.

## Remaining high-value families

The remaining Silent gaps are now dominated by temporary state and event timing rather than basic
damage/block/status primitives.

### 1. Dynamic costs

Highest-value first case:

- **Pinpoint** — costs 1 less for each Skill played this turn.

The engine already tracks Skills played this turn, so this should be implemented as a generic
count-derived cost modifier.

Further cases:

- Pounce — next Skill costs 0;
- Up My Sleeve — reduce this card's own cost.

### 2. Per-card draw events

Needed for:

- Corrosive Wave;
- Speedster;
- effects that inspect the type/identity of a drawn card.

The current draw routine updates piles/counters but does not yet dispatch a distinct event for each
drawn card.

### 3. Temporary turn-scoped powers/modifiers

Examples:

- Anticipate — temporary Dexterity;
- Piercing Wail — temporary Strength loss;
- Bullet Time — no draw + free hand;
- Hand Trick / Master Planner — temporary Sly mutation;
- Shadowmeld — Block multiplier this turn.

A reusable duration/expiry model should come before these cards.

### 4. Delayed next-turn effects

Examples:

- Predator — draw next turn;
- Dodge and Roll — Block next turn;
- Sidestep — Energy next turn;
- Nightmare — create selected copies next turn.

The likely native representation is temporary powers. The emulator should use a generic delayed
effect carrier rather than card-name flags.

### 5. One-shot card-play modifiers

Examples:

- Burst — next Skill plays an extra time;
- Pounce — next Skill costs 0.

These need one-shot event consumers tied to card type and play lifecycle.

### 6. Complex card-local mutation / replay

Examples:

- Nightmare;
- Knife Trap;
- temporary Retain/Sly mutation;
- combat-local self-cost mutation.

These should build on the existing suspendable-choice and combat-card-state layers.

### 7. Multiplayer-only mechanics

Ally-target and cross-player effects remain deferred for the first trustworthy solo Silent ruleset.

## Known limitations

1. the `combat_targets` stream name/call boundary is source-backed, but the PRNG codec/seed parity is
   still prototype-only;
2. Serpent Form currently snapshots which power instances existed at card-play start, but not a full
   native per-power internal-data snapshot for arbitrary future powers;
3. Thorns retaliation does not yet emit the full native damage/history hook sequence;
4. player-side Vulnerable/Weak and the full symmetric creature power system are incomplete;
5. decimal damage/block calculation and the general native `ValueProp` pipeline are not yet modeled;
6. several existing prototype relics/powers still use simplified timing semantics.

## Next implementation order

1. generic count-derived dynamic cost, then Pinpoint;
2. per-card draw event;
3. temporary turn-scoped power/modifier expiry;
4. delayed next-turn effect carrier;
5. one-shot "next card of type" consumers;
6. remaining Silent content that falls out of those primitives;
7. then broader relic/potion/enemy parity.

No live bridge update or game restart is justified by this pass.
