# Underdocks Drowning Beacon event audit

Target: single-player STS2 v0.111.0 / source commit
`706ef1c9fa2219220065849fd5265328607ece20`.

The pinned [`DrowningBeacon.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Events/DrowningBeacon.cs)
has source SHA-256
`c8bcbd0c528afb6a1207679c4aef0cced4c1e2ef355573b5558aff01917c841a`. Bottle
offers a Glowwater Potion through the optional reward prompt and then finishes
the event. Climb loses 13 max HP, obtains Fresnel Lens, and finishes the event.
The native completion page remains open until continuation after the bottle
offer is taken, skipped, or replaces a potion, and after Climb resolves.

The complete source branch inventory has seven paths:

| Source path | Behavior | Verification |
| --- | --- | --- |
| `page/INITIAL` | Present Bottle and Climb. | `BottlingOpensAnOptionalNativePotionOffer` and `ClimbLosesThirteenMaxHpThenGrantsFresnelLens` select both source choices. |
| `initial/BOTTLE` | Select Bottle and open the Glowwater offer. | `BottlingOpensAnOptionalNativePotionOffer` checks the fixed potion and legal take/skip actions. |
| `page/INITIAL/BOTTLE` | Resolve the initial Bottle choice. | Same test verifies the offer suspends event completion until the potion decision. |
| `page/BOTTLE` | Show the finished Bottle result. | Same test covers skipping and taking; `FullPotionBeltOffersReplacementOrSkip` covers replacement when all slots are occupied. Each path continues to map choice afterward. |
| `initial/CLIMB` | Lose 13 max HP and obtain Fresnel Lens. | `ClimbLosesThirteenMaxHpThenGrantsFresnelLens` checks max HP, current HP, relic, and unchanged RNG. |
| `page/INITIAL/CLIMB` | Resolve the initial Climb choice. | Same test verifies the finished event page follows the relic acquisition. |
| `page/CLIMB` | Show the finished Climb result, then return to the map. | Same test explicitly continues; `FresnelLensEnchantsNewBlockCardAndPreservesExistingCards` exercises the relic's persistent acquisition effect. |

The event uses the shared optional potion-offer and event-continuation flows.
Its fixed potion and relic choices add no event RNG draws in this model. Potion
and relic effects are executable, while live native cursor validation remains
outside this branch audit.
