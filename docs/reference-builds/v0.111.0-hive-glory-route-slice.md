# v0.111.0 Hive / Glory controlled route slice

Pin: STS2 v0.111.0 (`41cef1ea`),
`Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`.
Source classes: `Hive.cs`, `Glory.cs`, `Overgrowth.cs`,
`StandardActMap` shape model (the existing emulator geometry adapter).

## Executable scope

Configured single-player Silent runs with route
`[Overgrowth|Underdocks, Hive, Glory]` can now choose
`continue_act` from the completed Act 1 or Act 2 boss rewards.
The transition initializes an explicit later-act map profile and
independent seeded encounter bags, clears the preceding act's combat,
room and reward state, sets the configured `ActIdentity`, and resets
unknown-room odds. Run ids, player deck, gold, HP, relics, potions,
encounter history, and non-map RNG streams persist.

Hive uses **14 room rows + boss floor 15** with two introductory
weak combats; Glory uses **13 room rows + boss floor 14** with two
introductory weak combats. Both use a seven-column connected
noncrossing path map, first-floor combat, guaranteed floor-9 treasure,
a pre-boss rest row, three shop nodes and act-specific quota sampling.
Hive draws 6–7 rest rooms via a truncated Gaussian centered at six;
Glory draws five or six; both decrease the standard random unknown
room count by one. Elite quota increases at Ascension 1.

All encounter names come strictly from `Hive.GenerateAllEncounters`
(20) or `Glory.GenerateAllEncounters` (18), not from loosely tagged
prototype registries. Pools are split into weak/normal/elite/boss.
The boss is selected once on act entry from the respective native
`BossDiscoveryOrder`:
- Hive: The Insatiable, Knowledge Demon, Kaiser Crab.
- Glory: Queen, Test Subject, Aeonglass.

Weak encounters are drawn without replacement for the first two
ordinary combats in each act. Normal and elite bags draw without
replacement, refill on exhaustion, and avoid an immediately repeated
encounter whenever another candidate exists. Boss selection never
consumes an ordinary or elite bag. All pool state is fully serializable,
forkable and deterministic under the emulator's prototype RNG.

## Boundaries and fidelity classification

This is **source-shaped, not native-parity verified**.
The native `RoomSet` shuffle, encounter RNG streams/call order,
standard-map geometry distributions, rest/unknown assignment,
boss-discovery progression, and map seed correlation still need
oracle comparison. The older typed Hive/Glory combat fixtures retain
`Weight:0` and are selected only by this explicit configured
v0.111.0 routing path. Other run profiles keep their previous behavior.

Later-act event/unknown room choices now **fail loudly** with
`NotSupportedException` instead of silently choosing unrelated
prototype Act 1/legacy events. Full event and Ancient pools are not yet
implemented. Shops, treasures, rewards and rest mechanics currently
inherit the common emulator economy backend; their later-act native
parity is likewise unverified. Knowledge Demon's mandatory enemy-owned
choice remains deliberately unsupported and can stop that boss in
combat. A run reaching an unsupported system is not counted as an
end-to-end native fidelity success.

No cross-character or multiplayer mechanics, hidden content fallback,
or live-game fidelity claims are introduced.

## Regression contracts

- Exact complete 20/18 source encounter inventory and pools,
  including 4/3 weak, 10/9 ordinary, 3/3 elite and 3/3 boss.
- Stable Act 1 map behavior after generalizing structure generation.
- Act 2/3 map layer counts, boss/rest/treasure placement, route edges
  and deterministic regeneration at Ascensions 0, 1 and 10.
- Weak-first selection, pool independence, elite selection,
  one-time boss selection, serialize/fork determinism.
- Configured Act 1→2→3 transitions from either legal first act,
  actual first-floor combat selection, Act/Map identity validation,
  no crossing of Act 1 encounter pool into later acts.
- Explicit exceptions and unchanged source states when a configured
  later-act Unknown room would require unsupported event routing.

Next: native event/Ancient bags and implementations, native
`StandardActMap` and `RoomSet` stream/call-order parity, later-act
economy rewards, mandatory enemy-owned choice support and exhaustive
seeded Act 1→3 capture/oracle comparisons.
