**Important:** executable registrations do not establish source-exact mechanics,
full integration of rewards, regional Ancients or native RNG parity. Later-act
models use provisional combat, summon, AI and reward semantics, documented
per encounter in other source audits.

The **single missing Hive event** is Colorful Philosophers, which requires
unlocked cross-character card pools. Its source
(`src/Core/Models/Events/ColorfulPhilosophers.cs`) requires at least two
unlocked pools and offers three separate rarity-specific 3-card choices
from a non-current character pool. Since cross-character acquisition is
currently deferred, the event remains explicit unsupported content; it is
**not** silently substituted with a Silent card reward.

Native `Hive.NumberOfWeakEncounters` and
`Glory.NumberOfWeakEncounters` are **two**, not three.
Regional weak/normal/elite **ordered sequences** are now pre-generated at
Hive/Glory entry, following the pinned `ActModel.GenerateRooms` draw counts,
refill cycles and adjacent encounter-tag exclusions. Two weak picks precede
12 Hive / 11 Glory normal picks, and a separate 15-pick elite sequence is
also prepared. Queues are owned by `RunWorldState`, fork/snapshot safe, and
validated against the full native regional catalogues. Boss identity is
rolled at act entry and held persistently. Combat entry now consumes queued
IDs with no new selection draw. This corrects the previous room-entry bag
selection timing, while prototype RNG and exact source `NextDouble` call
counts remain provisional. See
[v0.111.0-hive-glory-encounter-queues.md](v0.111.0-hive-glory-encounter-queues.md).

All later-act Event and Unknown map rooms are now executable through
regional event registration, event eligibility, and deterministic
approximated selection instead of the previous single-Event-per-act gate.
Unknowns use the same persistent monster/shop/treasure/event pity weights,
with act-local reset, as native-shaped Act 1. Shops, treasure relic draws
and battle rewards now reuse the same source-shaped rarity/pity/grab-bag
logic across all three configured acts instead of routing later acts into
the six-floor prototype economy. Precise odds, RNG ownership and native
run oracle verification remain pending.
The source-backed `IsAllowed`/condition filtering is still incomplete for
some events and live native trace parity is pending. Source-backed item
acquisition from direct event rewards must prune persistent relic queue
ownership to keep exact snapshot invariants consistent.

## Remaining blockers for Overgrowth-level integration integrity

1. Test naturally generated full runs through every supported encounter,
   including resurrection/phase bosses (Knowledge Demon currently requires a
   blocking native curse choice). Synthetic victory sweeps are NOT parity or
   tactical success evidence.
2. Reproduce native encounter-room generation RNG stream and rejection call
   order; complete event eligibility/continuation branches.
3. Act-entry Ancients, full reward/shop/potion rarity handling, cross-act
   state-reset rules, unlock restrictions, epoch discovery.
4. Extend source-matched native RNG ownership beyond Act 1 and compare replay
   traces after mechanics reach a stable executable baseline.

The experimental three-act fidelity ID remains explicitly distinct from
the default v111 mode and from historical AI training. Only the experimental
mode can select the broader regional pools; catalogued `Weight=0`
fixture IDs do not enter unrelated legacy or default simulations.
