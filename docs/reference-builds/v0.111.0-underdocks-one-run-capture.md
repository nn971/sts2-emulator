# One-run native oracle capture: Silent, Act 1 Underdocks

The player's play time is the scarce resource. **Do not request a new manual
run until we have prepared the logger, verified startup and validated the
postprocessing path.** If an additional capture is needed later, explain the
exact unresolved question and why static source or the existing trace cannot
answer it first.

## Scope and expected result

Use **one ordinary, unmodified Silent A0 single-player run** on Act 1
Underdocks if the game makes this region selectable. Continue through the boss
or defeat; no special card/room choices are mandatory. Favor a varied
ordinary path over farming a particular enemy or artificially stalling in
combat. If the game assigns the other Act 1 region at random, do not spend
multiple full runs rerolling it: preserve the observed region and clearly
label what the sample validates.

The bridge targets **exact installed binary v0.111.0 / commit 41cef1ea**
with fingerprint `3bb5598a35f7763c9de22078643ac2777190994b2be85ebd4ebf5c9d154aa45e`.
The decompiled community source used for recent emulator construction is
`Flaaax/STS2-source@706ef1c9`: it is **not** the same build identifier,
so static-source expectations and captured runtime facts must not be
silently assumed identical.

### Evidence collected without changing gameplay

The opt-in passive recorder supplements existing combat signals with:

| Surface | Observation and limits |
| --- | --- |
| Provenance | Exact file hashes, build/version, bridge schema, timestamp, session id, corpus-mode marker |
| Run lifecycle | RunStarted, ActEntered, RoomEntered, RoomExited, room stack/current floor/map position |
| Native map | Graph of map points, their types and outgoing edges, starting/boss points |
| Run history | Current map-point history, including completed rooms and any option/reward history exposed by the pinned runtime |
| Persistent state | Per-player HP/Block/powers, deck cards and upgrades/enchantments, relics, potions, gold and currency changes |
| Randomness | Native run/player RNG snapshots and event RNG when serializable, with explicit nulls for unavailable reflective fields |
| Event choices | Initial/current option text keys and locked/chosen flags; transitions when EventModel.StateChanged is emitted |
| Noncombat actions | Player gold, relic and potion events, map votes, rest-site option chosen before/after, skipped rewards |
| Combat | Start/turn/end/victory snapshots, native CombatHistory, cards/piles, monster HP/intent/powers, RNG and observer IDs that distinguish duplicate cards |

The bridge **does not** Harmony-patch gameplay, change random seeds, force
maps/encounters/cards, synthesize menu decisions, or expose all reward/shop
options as fully synchronized legal-action sets. Callback-time observations
are not guaranteed atomic pre/post-decision state snapshots. The active
map-point history and room exits complement those callbacks, but complete
RNG and callback-order parity will still require a separate differential
comparison.

## Before starting the run

1. Keep the clean pinned game oracle separate from the expendable
   instrumented installation. Do not use Loadout, gameplay-affecting mods,
   cheats or debug rooms in this capture. The reference bridge is the
   sole intended mod.
2. From the emulator repository, build the recorder against the *clean*
   pinned oracle without modifying it:

   ```fish
   fish tools/reference_bridge/stage_underdocks_corpus.fish \
     '/path/to/clean/oracle/game'
   ```

3. Copy the staged folder `artifacts/reference_bridge_mod/Sts2ReferenceBridge`
   into `<instrumented-game>/mods/`. Fully exit and relaunch the
   instrumented game. Do **not** start a playthrough yet.
4. Confirm that a **new** file
   `<instrumented-game>/reference_traces/underdocks-silent-act1-*.jsonl`
   has appeared, with a recent session timestamp. Check the chosen
   file with:

   ```fish
   python tools/native_one_run_audit.py --preflight \
     '/path/to/instrumented/game/reference_traces/underdocks-silent-act1-YYYYMMDD-HHMMSS-HASH.jsonl'
   ```

   The output must say `READY`, with a matching capture mode, verified
   native fingerprint, `run_recorder_attached` and
   `recorder_attached` diagnostics. If either hook is missing,
   the recorder fails to initialize, or the game hashes do not match,
   **stop before playing**. Investigate from the startup log; do not
   sacrifice a full run to test a broken logger.

## The single run

Play normally at A0 as Silent. If reasonably available on your route,
prefer coverage of a few different room types: early ordinary combats,
an event, a shop visit (including an actual purchase if useful), a rest
site, an elite, a potion use, and the boss. A healthy end-to-end example
is more valuable than forcing a niche interaction that leads to early
defeat. Do not try to visit all ten regional events; that is not possible
on an ordinary single route.

The observer records the naturally encountered *choices and outcomes*.
No screenshots or manual notes are required unless the tool's audit shows
an actual blind spot. An optional short note of any visible menu/game
behavior that seemed wrong may help triage, but is not essential.

## Immediately after the run

Without relaunching or deleting the trace, inspect it:

```fish
python tools/native_one_run_audit.py \
  '/path/to/underdocks-silent-act1-capture.jsonl' \
  --output '/path/to/native-one-run-audit.json'
```

Preserve the **original complete JSONL**, not only its summary. Upload
the JSONL and audit together. If the trace is too large, compress the
original without changing its contents:

```fish
tar -czf undedocks-oracle-capture.tar.gz \
  -C '/path/to/instrumented/game/reference_traces' \
  'underdocks-silent-act1-capture.jsonl'
```

The audit distinguishes startup readiness, corrupt/incomplete JSONL,
missing signals and observed evidence. Missing an event option page on a
run that visited no events is a coverage **warning**, not a request to
replay the entire game. Similarly, a field absent from the runtime is
reported as absent, never inferred from the emulator.

The trace can contain local filesystem paths, run identifiers or
pseudonymous player identifiers. Review or share privately rather than
posting raw captures to a public issue without checking provenance and
privacy.

## Analysis plan after this capture

Perform these offline, in order:

1. Verify mode/build/session and report any missing passive hooks;
   establish actual character/region/Ascension from observations.
2. Reconstruct Act 1 map and ordered room path; identify all
   available encounter and event checkpoints.
3. Align combat-history action frames and native RNG with emulator
   transitions, focusing on the **first** actual divergence.
4. Compare persistent changes across events, card/potion/relic rewards,
   merchant and rest actions. Report sampling limitations for menus
   not observed atomically.
5. Add deterministic regression fixtures and mark which mechanic
   claims are **trace-validated**, only for events and transitions
   actually encountered.
6. Revisit unobserved mechanics from pinned source and existing
   offline programmatic emulation; consider a second oracle request
   only for a specific high-impact ambiguity that cannot otherwise
   be resolved.

### Coverage expectations

The emulator may support **10/10 native Underdocks regional event IDs**
and **20/20 native encounter IDs**, but **one real run never provides
independent live validation of every one**. Separate catalog coverage,
unit-regression coverage, observed native trace coverage, and
RNG/action-order parity in reports. Explicit unsupported cross-character
cards remain unsupported, even when a native event can reward one.
