# v0.111.0 mechanics gap — pass 010

This pass adds the first resumable automatic-event continuation and moves Tools of the Trade onto
the generic event-subscriber path.

## Motivation

The event system already had deterministic application order across player powers, enemy powers,
and stateful relics. Its remaining control-flow restriction was that an event subscriber could not
request a player choice: if one of its effects produced a pending card-selection prompt,
`DispatchCombatEvent` threw immediately.

That restriction prevented source-faithful implementations of hooks whose native behavior pauses
for input and then continues the same event.

## Continuation state

The combat model now carries explicit state for two layers:

- `PrototypeEventDispatchContinuationState` records the current event, the subscriber whose
  remaining operation queue suspended, the ordered later subscribers, and the event recursion
  depth.
- `PrototypeAutomaticPipelineContinuationState` records the next automatic turn-pipeline step and
  whether the just-suspended dispatch still has a post-dispatch stage policy to finish.

These records participate in combat-state cloning, so a suspended decision remains part of the
deterministic emulator state instead of living on the call stack.

The existing pending-choice continuation stores the event-dispatch frame when the choice originates
inside an event subscriber. After the choice resolves:

1. the subscriber's remaining operations finish;
2. one-shot/current-subscriber cleanup is applied exactly once;
3. later subscribers resume in their original application order;
4. event finalization runs;
5. the containing automatic turn pipeline resumes from the next step.

A later subscriber may suspend again; the same continuation shape is rebuilt for the remainder.

## Source-backed acceptance case: Tools of the Trade

Pinned v0.111.0 source separates Tools of the Trade into two hooks:

- normal hand draw is increased by the power amount;
- after player-turn start, exactly that many cards are selected from Hand and discarded.

The prototype previously represented the second half through a dedicated
`DiscardAfterPlayerTurnStartPerStack` stage policy. The card behaved correctly, but that shortcut
did not exercise the generic event system.

Tools of the Trade now subscribes to `PlayerTurnStarted` with a generic `ChooseCards` effect.
The card-selection specification supports a count contribution per power stack, so one stack asks
for one discard, two stacks ask for two, and so on.

This gives a native-shaped flow:

1. BeforeHandDraw hooks resolve.
2. The normal hand draw includes Tools' draw bonus.
3. `PlayerTurnStarted` subscriber dispatch begins.
4. Tools suspends on a discard selection.
5. The selected cards follow the ordinary discard/Sly lifecycle.
6. Remaining `PlayerTurnStarted` subscribers continue.
7. Turn-start event finalization and the automatic pipeline complete.

## Ordering regression

A focused test installs Tools of the Trade before Noxious Fumes in application order.

Before resolving the Tools choice, the enemy has no newly applied Poison. After the choice,
dispatch resumes and Noxious Fumes applies its stacks. This verifies that later subscribers are not
run early, skipped, or rebuilt from mutable combat state after suspension.

A separate stacked-Tools test verifies that the prompt cardinality scales with power stacks.

## Deliberate boundary

Suspension is enabled only for top-level automatic `DispatchCombatEvent` pipeline steps.

Card-play completion events still use the guarded path. If a subscriber invoked from inside a
card-play completion attempts to suspend, the emulator raises a `NotSupportedException` rather
than accepting an incomplete continuation.

That boundary is intentional. A nested card-play event needs one more outer frame covering:

- the currently resolving completion-event sequence;
- result-pile/card-removal cleanup still pending after that event;
- remaining intrinsic Replay/Burst executions;
- any parent choice continuation.

The branch already has explicit choice-resolution parent continuations for nested discard/Sly
choices. The next continuation pass should connect event suspension to the same outer-frame model
rather than add another special hook exception.

## Tests

The full CI suite is green with coverage for:

- existing Tools of the Trade card/power behavior;
- top-level turn-start event suspension;
- one discard per Tools stack;
- resumption of later subscribers in application order;
- normal completion of the automatic turn pipeline after the choice;
- pinned static parity expressed through the event-trigger model.

## Next frontier

The next structural target is **event suspension inside card-play/completion lifecycles**.

Once that outer frame is explicit, the event dispatcher can use one suspension rule everywhere
instead of the current top-level automatic-event opt-in. After that, continue the static-first
mechanics expansion with Phantom Blades and richer enchantment/affliction card-local state.
