# v0.111.0 mechanics gap — pass 028

This pass pins the remaining enemy random-branch repeat ambiguity and promotes **Twig Slime (M)**
as a source-backed Act 1 monster model.

## `CanRepeatXTimes` semantics

The enemy-AI kernel already carried a provisional `CanRepeatXTimes` branch rule, but production
content deliberately avoided it until the off-by-one meaning was established.

The pinned Spire Codex commit used by this project renders a
`CanRepeatXTimes` branch with `max_times = n` as a move that may occur **at most n times in a
row**. A decompiled `RandomBranchState` source mirror independently confirms the implementation
shape: the branch loses weight only after the last `n` logged states are all the same target state.

Therefore the existing emulator predicate was correct:

- after fewer than `n` consecutive uses, the branch remains eligible;
- after exactly `n` consecutive uses, it becomes ineligible;
- choosing another move resets the consecutive-use count naturally.

For `n = 2`, the legal histories include `A` and `A,A`, while `A,A,A` is excluded.

The generic representation is now considered production-backed rather than provisional.

## Twig Slime (M)

Pinned v0.111.0 structured values:

- HP 26–28 at A0–A7;
- HP 27–29 at A8+;
- Pokey Pounce: 11 damage, 12 at A9+;
- Sticky Shot: add 1 Slimed to the discard pile;
- initial move: Sticky Shot.

The structured parser loses the random-branch payload for this monster, so the branch graph is
cross-checked against source-level evidence:

1. Sticky Shot is the fixed opener;
2. both moves lead to one random state;
3. Pokey Pounce uses `CanRepeatXTimes(2)`;
4. Sticky Shot uses `CannotRepeat`.

This gives the native legal pattern:

- Sticky Shot first;
- afterward, choose Pokey Pounce or Sticky Shot;
- Pokey Pounce may occur once or twice consecutively;
- Sticky Shot may not occur twice consecutively.

Exact native RNG choice parity remains outside this claim.

## Regressions

Focused tests verify:

- HP ranges and A8 breakpoint;
- A9 Pokey Pounce scaling;
- Sticky Shot creates exactly one combat-local Slimed;
- the source-shaped fixed opener;
- the random branch stores `CanRepeatXTimes` with `MaxTimes = 2`;
- a second consecutive Pokey Pounce remains reachable;
- a third consecutive Pokey Pounce is excluded and therefore forces Sticky Shot.

The last two checks explicitly distinguish the two possible off-by-one interpretations.

This completes the monster-model prerequisite for the native `SLIMES_WEAK` and

## Next work

The next step should move from isolated models to **native encounter construction**.

Source-backed constructors show:

- `SLIMES_WEAK`: one random medium slime in the middle, with the two different small slime types
  on either side in random order;
- `SLIMES_NORMAL`: Twig Slime (M), Leaf Slime (M), then the two different small slime types in
  random order.

The encounter model therefore needs a small generic extension for independent random slot groups
with optional distinct-within-group selection. Once that is present, both slime formations can be
promoted while native weak/normal pool selection remains a separately tracked fidelity claim.
