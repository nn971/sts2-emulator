# Configured v111 Silent natural-run integrity sweep

## Contract

The `v111-natural-sweep` CLI command is an integration probe for
`v111-experimental-silent-three-act-route-v1`. For each region
(Overgrowth, Underdocks), it instantiates a normal `V111RunFactory.Create`
run at Neow and advances exclusively via the **actual** engine
`GetLegalActions` and `Step` methods until the terminal state.

```sh
dotnet src/Sts2Emulator.Cli/bin/Release/net9.0/Sts2Emulator.Cli.dll v111-natural-sweep 128 0 > natural-sweep.json
```

Arguments: number of seeds *per* first-act region, ascension (0–10),
optional nonnegative seed offset, optional output directory for exact
act-entry checkpoints, and an optional policy. Policies are
`legal-actions-heuristic-v1` (the original baseline) and
`legal-actions-balanced-v2`. The latter still chooses only from the engine's
legal actions; it favors available relic/card/potion rewards and shop offers,
heals below 90% HP, and spends energy on the highest-cost currently playable
card. It is a coverage policy, not a combat solver. Resume accepts the same
optional policy:

```sh
dotnet src/Sts2Emulator.Cli/bin/Release/net9.0/Sts2Emulator.Cli.dll v111-natural-sweep 128 0 0 ./natural-checkpoints > natural-sweep.json
dotnet src/Sts2Emulator.Cli/bin/Release/net9.0/Sts2Emulator.Cli.dll v111-natural-resume ./natural-checkpoints/SEED-act2-dDECISION.snapshot.json
dotnet src/Sts2Emulator.Cli/bin/Release/net9.0/Sts2Emulator.Cli.dll v111-natural-resume ./natural-checkpoints/SEED-act2-dDECISION.snapshot.json legal-actions-balanced-v2
```

Each checkpoint is created *only after a naturally reached act transition*.
It stores the engine's verified full hidden state and has an exact hash in
the report. The resume CLI loads via `RunSnapshot.Load`, runs the **same**
legal baseline policy, and reports a final terminal hash. CI checks every
saved Act 2/3 entry hash against a complete direct run of the same seed.
These snapshots are training/debugging inputs, never fair observations
to give the policy hidden RNG or future draw order. The deterministic seed names are
`natural-v111-overgrowth-N` and `natural-v111-underdocks-N`.
The policy deliberately prefers non-elite, noncombat paths and selects
simple legal cards, decisions and rewards; it is **not trained** or
intended to win reliably.

The sweep never edits a player, card, enemy, map, RNG or encounter,
never injects an Act 1 transition, never selects a boss outside the
generated bag, and never plays synthetic combat finishers.
It runs run-state invariants at each decision and retains the exact
terminal hash. An engine exception, nonexistent legal-action set or
decision limit is counted as a **blocker** rather than a game defeat.
CLI exit code is nonzero if any blocker appears.

A JSON run entry includes region and seed, terminal outcome and
position, highest reached act, visited act identities, decisions,
exact final hash, last encounter/action, and recent actions around
any failure. CI saves the entire report as the
`v111-natural-run-smoke` artifact and summarizes the blocker count
in the job logs.

## Evidence: first 16 runs

CI run [38164210305](https://github.com/nn971/sts2-emulator/actions/runs/38164210305)
executed 8 seeds from each first-act region:

- Terminal run: **16/16**
- Actual game defeats: **16**
- Automatic wins: **0**
- Engine blockers, unsupported actions or invalid states: **0**
- Naturally reached Act 2 Hive: **2**
- Naturally reached Act 3 Glory: **0**

This demonstrates actual, unmodified Act 1→Hive progression for two
seeded baseline runs, as opposed to synthetic post-Act 1 route sweeps.
It does **not** yet demonstrate natural three-act victory or full late-act
boss/event coverage. The baseline strategy is intentionally weak, so
terminal defeats are not evidence of incorrect mechanics.

## Larger-sample discovery: Sly auto-play target blocker

On 256 seeds (128 per first-act region), the initial expanded sweep
reported **255 terminal defeats, 10 naturally reaching Hive, zero reaching
Glory, and one integrity blocker**. Seed
`natural-v111-overgrowth-23` reached Vantom on Act 1 floor 16.
Its `select_cards` continuation discarded a Sly `Bubble Bubble`
card, triggering the old explicit-target hard gate.

Pinned `src/Core/Commands/CardCmd.cs` confirms that
`CardCmd.AutoPlay(card, target: null, AutoPlayType.SlyDiscard)`
selects uniformly from `combatState.HittableEnemies` using
`RunState.Rng.CombatTargets.NextItem` for `TargetType.AnyEnemy`.
The emulator now resolves an ordered living-enemy target and saves
`card instance / turn / candidate count / selected index / stable
enemy instance` in `CombatState.AutoPlayTargetRolls`, including in
forked and exact-restored combat snapshots.

**RNG stream caveat:** the current configured three-act experimental
route still samples the target from the prototype combat stream; exact
native CombatTargets ownership and ordering remain for fidelity work.
The source determines *which population* is randomized, not proof
of parity of each random roll. The existing hand/discard continuation
reuses the already chosen target without resampling.

## Evidence: 256 runs and exact Hive checkpoints

CI run [38164913815](https://github.com/nn971/sts2-emulator/actions/runs/38164913815)
now passes **256/256 unmodified complete runs** (128 Overgrowth,
128 Underdocks; Ascension 0) with **zero** engine blockers.
There were 256 defeats under the fixed weak legal-action baseline,
**11 naturally reached Hive**, and none reached Glory. This is a run
integrity measurement, not a strategic success rate.

The same run created **11 Hive-entry exact snapshots** at their real
Act 1→Hive transitions; all 11 were independently loaded with
`RunSnapshot.Load` and replayed to the **identical terminal state hashes**
as the direct run. No source HP/map/boss/run-RNG values were fabricated.
These verified checkpoints permit later-act training/combat-snapshot
benchmarks without spending time replaying the full Act 1 seed.

## What still needs to be done

1. Expand smoke across seeds to expose rare source-backed event and boss
   continuations, preserving every blocker without silently substituting
   unsupported mechanics.
2. Build more effective, still-legal combat and macro policies to exercise
   later acts naturally; compare survival/terminal coverage separately
   from state-integrity failures.
3. Add Act 2/3 start-from-real-replay checkpoint benchmarks if standard
   full-run survival remains too rare.
4. Independently compare selected source action traces against a clean
   native game recording after event/Ancient/boss feature integrity is complete.

The tests check *engine legality and progression* and do not establish
native RNG parity, combat oracle fidelity, or human-level strategy.

## Balanced-policy discovery sweep

The balanced policy was compared with the baseline on the same 256 seeds
(128 per first-act region, offset 256, A0). Both completed all runs with zero
integrity blockers. The baseline reached Hive twice; the balanced policy
reached Hive six times. Neither reached Glory and all runs ended in defeat.
All six balanced-policy Hive checkpoints were resumed with the same policy;
they ended in ordinary combats on Hive floors 1–3 with no integrity blockers.
Repeating the balanced 256-run sweep reproduced every terminal hash. This
adds deterministic late-act exercise, but does not establish natural Hive
completion or an unassisted three-act victory.
