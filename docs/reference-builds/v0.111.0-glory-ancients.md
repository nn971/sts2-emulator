# Glory Ancient source ledger

Target: single-player STS2 v0.111.0 / build `41cef1ea`, source commit
`706ef1c9fa2219220065849fd5265328607ece20`. This ledger records the source
offer structures and implementation status. It does not claim native RNG
parity or event integration.

## Nonupeipe

Pinned source: [`Nonupeipe.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Events/Nonupeipe.cs),
SHA-256 `beaf1b558150881c7072e07b7481d1671b52489d79a4eccb2f409c5c3b9c8d0f`.

The base pool contains Blessed Antler, Brilliant Scarf, Delicate Frond,
Diamond Diadem, Fur Coat, Glitter, Jewelry Box, Looming Fruit and Signet Ring.
Beautiful Bracelet joins the pool when at least four deck cards can receive
Swift. The Ancient shuffles the eligible pool and presents three relics.
The pinned source inventory enumerates ten possible relic branches; branch
implementation is incomplete.

Blessed Antler's pinned relic source,
[`BlessedAntler.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Relics/BlessedAntler.cs),
adds one energy and, before the first hand draw of each combat, generates three
Dazed cards at random positions in the draw pile. The emulator implements both
effects through the shared relic and generated-card pipelines. A combat-entry
test verifies the energy, all three temporary Dazed instances, and their pile
membership. Draw-pile insertion currently uses the prototype combat RNG; native
call-order parity and Nonupeipe offer integration remain gated.

Beautiful Bracelet's pinned relic source,
[`BeautifulBracelet.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Relics/BeautifulBracelet.cs),
adds Swift amount 2 to four randomly selected eligible deck cards. Nonupeipe
includes it only when at least four deck cards pass `Swift.CanEnchant`. The
emulator implements that eligibility predicate and acquisition hook, shuffles
the eligible deck order with native `run.niche`, and persists the stream cursor
through reward acquisition. When an event-gained relic choice acquires the
Bracelet, the existing generic controlled event-choice continuation now
captures each conditional shuffle swap with the current ordered physical
card-instance IDs and commits the enchantments without advancing Native
`run.niche`. The pinned
[`ListExtensions.UnstableShuffle`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Extensions/ListExtensions.cs)
uses Fisher-Yates, matching the implemented selection algorithm. A focused test
checks the four selected cards and the exact cursor advance. Prototype-only
runs use the `event` stream. Swift's pinned source,
[`Swift.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Enchantments/Swift.cs),
draws two after the enchanted card is played; the emulator triggers that once
per combat and tests repeat-play behavior. The Nonupeipe event and its
conditional offer sequence now execute through a named Glory Ancient fixture.
Normal Glory Ancient assignment remains gated.

Fur Coat's pinned relic source,
[`FurCoat.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Relics/FurCoat.cs),
marks up to eight randomly shuffled Monster/Elite map points in the current
act and sets each enemy's current HP to 1 before combat; enemies added during
those combats are also reduced to 1 HP. The emulator persists the marked map
node IDs and the relic-owned `FurCoat` content RNG snapshot, applies the effect
to initial and summoned enemies, and preserves their maximum HP. Selection
uses the native-shaped player-content context when native run ownership is
enabled and the prototype event stream otherwise. The map selection call
order and live-game parity remain unverified. When acquired by an event choice,
the existing controlled event-effect continuation scripts each conditional
shuffle swap with the current ordered node IDs and replays the marked nodes.
That counterfactual keeps the relic-owned Native `Rng` field absent, so Nature
marks are not paired with an unconsumed Native content cursor.

Nonupeipe's pinned event source,
[`Nonupeipe.cs`](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Events/Nonupeipe.cs),

each offered relic through shared acquisition hooks. This path is available
through a named Glory Ancient fixture; normal run-start assignment remains
gated.

## S0 stochastic boundary: War Hammer elite upgrade

The `relic.war_hammer.elite_upgrade.shuffle_swap_index` site belongs to a
War Hammer relic instance after an Elite victory. Its private support is the
ordered set of currently upgradable physical deck cards. Native uses
`run.niche`; prototype-only runs use the legacy `event` stream. The emulator
shuffles the eligible cards and upgrades the first four, with canonical
CardId plus instance ID standing in for the source's model ordering. Exact
source ordering and cross-relic hook order remain unverified.

Players observe which cards were upgraded, not the pre-upgrade candidate
order or shuffle state. The synchronous elite-victory relic hook applies the
ordinary card-upgrade mechanics. A conditional Chance Law and atomic
ReferenceNature shuffle session now cover one active War Hammer when a legal
combat action wins immediately; multiple hammers and later run.niche draws
remain outside that boundary. Its law remains **UNVERIFIED**. The emulator's
CardId-plus-instance-ID ordering proxy remains distinct from the unverified
source ModelId order.

## S0 stochastic boundaries: other Glory relic operations

Three additional rows resolve at relic acquisition or combat entry. Beautiful
Bracelet shuffles the source-ordered physical deck cards that pass Swift
eligibility, then enchants four; the native path uses `run.niche`, while
prototype-only acquisition uses the legacy `event` stream. Distinguished
Cape selects two distinct cards without replacement from the source-ordered
modifier-eligible curse pool using `run.niche`, then adds three Apparitions.
Fur Coat shuffles the current act's Combat and Elite map nodes, marks up to
eight by node identity, and later applies its 1-HP effect at those combat
entries. Its native-shaped owner is the player-content context; the
prototype-only path uses `event`.

The player-visible outcomes are the enchanted deck cards, acquired curses, or
marked map encounters and their combat effects. Eligible supports, shuffle
order, provider state, and acquisition candidates are not Nature observations;
no atomic ReferenceNature continuation or privileged per-choice transcript
covers these sites. The synchronous relic-acquisition and combat-entry hooks
apply the selected outcomes through ordinary mechanics. Each site's law
remains **UNVERIFIED**; controlled requests must fail closed until the
site-specific constraints and continuation are captured together.

## Vakuu

The pinned source inventory lists ten possible relic branches. The offer code
uses three independent pools and presents one relic from each:

- Blood-Soaked Rose, Whispering Earring or Fiddle.
- Preserved Fog, Sere Talon or Distinguished Cape.
- Choices Paradox, Music Box, Lord's Parasol or Jeweled Mask.

Vakuu now shuffles each source pool independently with its persisted
`context.event.VAKUU.player_0` stream and offers the first relic from each
pool. Its named opening fixture tests the exact offers, stream cursor,
snapshot round trip and the Sere Talon and Lord's Parasol branches. Lord's
Parasol purchases stocked cards, relics and potions for free through existing
purchase hooks, then pauses for a potion replacement when the belt is full and
forces one free deck removal. The pending choices survive snapshots. Normal
Ancient assignment and route integration remain gated.

Fiddle's +2 opening draw and player-turn extra-draw suppression are implemented
and tested. Blood-Soaked Rose also grants +1 energy and adds the Eternal
Enthralled curse. The curse blocks manual plays of other
cards while it is in hand, can itself be played, and is permitted during
auto-play, matching the pinned [Blood-Soaked Rose source](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Relics/BloodSoakedRose.cs)

one selected draw-pile card to hand. Upgraded Wish gains Retain, matching the

and [Folly source](https://github.com/Flaaax/STS2-source/blob/706ef1c9fa2219220065849fd5265328607ece20/src/Core/Models/Cards/Folly.cs).

Acquisition, first-turn movement and cost expiry are covered. See the pinned

## S0 stochastic site contract: Ancient opening offers

This contract covers the Nonupeipe, Tanx and Vakuu offer-shuffle rows in the
migration matrix. Each named opening fixture owns a per-player event context
(`context.event.NONUPEIPE.player_0`, `context.event.TANX.player_0`, or
