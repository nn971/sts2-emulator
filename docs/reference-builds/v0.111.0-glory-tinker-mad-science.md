## Event decision boundaries

Tinker Time starts with one action: **Choose Card Type**. The event
samples two distinct types from Attack, Skill and Power, persists
their IDs and offers the two options. Selecting a type then samples
two distinct riders from the associated three options. Choosing a
rider grants exactly one `Mad Science` deck card.

| Base type | Cost | Base effect | Available riders |
| --- | ---: | --- | --- |
| Attack | 1 | Deal 12 damage | Sapping: apply Weak 2 + Vulnerable 2; Violence: 3 hits of 12; Choking: apply Strangle 6 |
| Skill | 1 | Gain 8 Block | Energized: gain 2 Energy; Wisdom: draw 3; Chaos: add one generated character card, free this turn |
| Power | 1 | Custom power | Expertise: Strength 2 + Dexterity 2; Curious: Power costs reduced by 1; Improvement: one random permanent deck upgrade after combat |

Upgrading Mad Science grants Innate. The same physical card ID
(`proto.native.glory.mad_science`) is used for every choice. Its
persisted JSON holds `tinkerType` and `tinkerRider`, analogous to
native saved card properties, and combat resolves its type, target,
effect list and power-card destination at runtime. Upgraded and
copied cards retain their selected rider state. Unsupported or
incompatible saved state is rejected explicitly.

The existing Strangle source-shaped power model is reused. Its
owner-scoped trigger resolves completed player card plays and it
expires after the owner's side turn, rather than maintaining an
unrelated duplicate Tinker-specific power. Curious and Improvement
are new named Power models; Improvement's target and selection are
persistent deck card instances, chosen without replacement.

## Isolation and fidelity limits

The event is reachable through the experimental Glory event selection and
the explicit full Glory event fixture. The default configured route remains
gated from later acts. Native v111 runs use the persisted `TINKER_TIME`
event-local stream for type and rider offers; the legacy profile retains the
prototype `event` stream. Seeded offer results and cursor parity remain
unverified.

The type and rider offer shuffles now use the shared ReferenceNature event
shuffle session. It samples each conditional bounded-index prefix and replays
the ordinary event action after the whole shuffle is resolved. The rider offer
requires the prior scripted type result; the Native event stream stays at its
entry cursor across both stages. The session contract documents the exact
supported page boundaries and does not certify probabilities or seeded Native
parity.
Chaos samples the implemented solo Silent reward pool rather than
the exact unlocked character-card pool and generation RNG. The
Improvement choice uses the prototype combat stream rather than
native CombatCardSelection. Exact Strangle owner-trigger ordering,
automatic replay/duplication interactions and power-cost
modification in every exotic cost context need native traces.
Character-specific Mad Science scenarios remain future work.

The coverage baseline reflects source-oriented typed mechanics,
but cards and events retain unverified native parity and lack
random full-route integration. Test fixtures exercise the choices
and all nine effects, canonical state forks, and combat operation
outcomes without asserting native RNG equivalence.

## S0 stochastic boundary: Improvement upgrades

The `combat.glory_tinker.improvement_card.index_draw` site is triggered by
the Improvement Power after combat. Its private support is the deck-ordered
set of physical cards accepted by the upgrade eligibility predicate. The
resolver chooses up to the Power's stack count without replacement, shrinking
the pool after each choice, then applies the upgrades to the persistent deck.
The current implementation uses the legacy `combat` stream.

The player sees the upgraded cards, not the candidate order or RNG state.
The existing saved victory replay session now accepts a legal combat action
that wins immediately and triggers at least one Improvement pick. It scripts
the legacy `combat` index requests in order, recaptures the remaining support
after each chosen card, then commits the ordinary victory action and Nature
cursor together while preserving the legacy stream cursor. The request-index
law remains **UNVERIFIED**; source-native stream assignment, independent pool
verification, and Native parity are not claimed.
