## S0 stochastic site contract: `event.pael.relic_offer.index_draw`

This site resolves the three ordered Pael pools at an unvisited Act 2,
floor 0 Hive Ancient boundary, using the event-local
`context.event.PAEL.player_0` stream and request ordinals 0–2. The private
candidate lists come from `OfferPools`: Flesh/Horn/Tears; Wing with Claw when
at least three Goopy-enchantable cards exist and Tooth when at least five
cards are removable, followed by a duplicate of that eligible list and
Growth; then Eye/Blood with Legion only when the player has no event pet.
Repeated entries are separate source draw indices and therefore add integer
weight to that relic choice.

The event stores the three selected `OfferedChoiceIds` and the completed RNG
context. The player observation projects those offers and their visible
choice values. The opt-in `chance_law_query` supports this site through
`ChanceLawEngineV111.QueryAncientOffer`; it uses the same `OfferPools`
builder, returns stable choice identities with repeated-entry weights, and
fingerprints the ordered pre-outcome candidate entries.
`ReferenceNatureAncientOfferSessionV111` adds an atomic three-choice
continuation shared with Orobas and Tezcatara. It keeps partial results inside
the session and only publishes the event and sampler cursor after the third
choice. Fork, save, restore and JSONL operations replay the sampled transcript
through the existing Pael generator. EventState keeps its established
compatibility shape, so support is reconstructed from the origin run and query
law rather than stored as an additional event field. Direct offer masses are
`SOURCE_VERIFIED` for the Native bounded-index transform on the declared
support, including aggregated preimage mass for duplicate entries. Native
UpFront assignment, full pool fidelity, seed frequencies, and native cursor
certification remain open. Invalid boundaries or unsupported sites fail closed, and no
privileged-inspector projection is provided here.

## S0 stochastic site contracts: Pael relic operations

The two `relic.paels_*` rows in the migration matrix retain their distinct
owners and private supports. Pael's Legion samples one of four skin names at
acquisition; the emulator derives an isolated legacy bundle from the current
reward-stream snapshot and relic slot, then saves the selected skin on that
relic. Its direct four-skin index law and the existing ReferenceNature
run-action and event-choice sessions now cover a legal Shop purchase or a
supported event reward. Scripted Nature selection does not advance the shared
reward cursor; the emulator's source seed derivation remains unverified. Pael's
Tooth samples from the ordered saved physical card instances when a surviving
combat ends. Each non-melted Tooth skips an empty saved queue; a selected card
is removed, receives a new instance ID, and gains one upgrade level when
possible.

The player-facing projection shows the saved Legion skin/pet or the
returned deck card; private pool order, local seed, and cursor are not part of
the ordinary player view. Pael's Tooth now has an `UNVERIFIED` request-index
law and an atomic ReferenceNature continuation for a legal combat action that
immediately wins
and reaches one or more nonempty Tooth queues. It scripts the ordered Tooth
returns and rejects unrelated `reward` draws before or between them; later
reward draws retain their legacy provider. This session models the emulator's
current synchronous post-combat hook, not Native source parity. Existing
atomic ReferenceNature run-action and event-choice sessions cover Legion
indices during supported Shop purchases and event rewards. Other acquisition
routes remain outside those continuations and unsupported as Nature requests;
the isolated relic-seed derivation remains unverified. Neither operation has a
per-choice privileged-inspector transcript. Legion's resolver is the
synchronous acquisition hook; Tooth's resolver remains the post-combat hook.

## Remaining integration gates

Pael's source pools are ordered: Flesh/Horn/Tears; Wing with conditional
Claw and Tooth, then duplicate that entire list and append Growth; Eye/Blood
with Legion only if the player has no event pet. Each pool consumes one native
event-context NextItem draw. `BeginPaelOpening` builds these pools from the
deck and pet progression, samples all three offers in order, stores the event
cursor, and the state invariant recomputes both the offers and cursor. Legal
actions retain the sampled order. Configured run-start assignments dispatch
this opening during Act 1→Hive. Native UpFront assignment and cursor
certification remain open.

Pael and Overgrowth's Byrdonis Nest now share the source `Player.HasEventPet`
predicate. `AddsPet` is modeled independently from combat-pet spawning, and the
source checks every relic instance plus an unhatched Byrdonis Egg.
