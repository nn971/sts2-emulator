# v0.111.0 mechanics gap 143 — Lasting Candy combat card rewards

The pinned source registers Lasting Candy as an Uncommon shared relic. Its
saved `CombatRewardsSeen` counter advances once after a combat reward set is
generated when that set contains a card reward. The first reward has no bonus;
starting with the second, each eligible combat card reward gets one additional
Power option on alternating rewards. The hook requires an Encounter source and
both `IsCardReward` and `IsFromCombat` flags. It prefers a Power ID absent from
that reward's options and permits duplicates if needed. The added card uses the
original rarity odds type with `CardCreationSource.Other`, so its rarity roll
uses base odds without consuming the persistent rarity offset. Its upgrade roll
still uses the current act's normal upgrade scaling.

The emulator registers Lasting Candy in the shared Uncommon relic queue. It
stores the reward counter in relic persistent state, adds a Power option to
eligible combat reward groups on every other reward starting with the second,
and retains the card's upgrade and Glam metadata. Driftwood rerolls regenerate
one fewer regular option and then append a newly generated Lasting Candy Power,
keeping the reward group size stable. The configured Glory queue removes it at
the same treasure-row cutoff used for other Act 3 chest-limited shared relics.

The card candidate set is the implemented single-player Silent reward pool.
Rarity and upgrade probabilities use the emulator's discrete `reward` stream;
they do not reproduce native float draws or native RNG call encoding. The
prototype does not model the relic's activation visuals or display counter, and
the Act 3 availability gate follows the configured map row instead of the
source's global floor check. Event and relic-created card rewards outside the
combat reward generator are not covered by this hook. No new executable
coverage claim is recorded for this implementation.
