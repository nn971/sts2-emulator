# v0.111.0 — Hive/Glory event-room routing (partial integration)

**Source pin:** `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`.
The catalog comes from `src/Core/Models/Acts/Hive.cs` and
`src/Core/Models/Acts/Glory.cs`, in their exact `AllEvents` order.
Restrictions were cross-checked against individual event models.

## What now executes

On a **native Hive or Glory map profile**, entering a map node
that resolves to Event now selects from **that act's native event
catalog only**. Previous act events and the legacy six-floor generic
prototype selector cannot enter this path. An eligible native event
runs on the existing event/reward/deck-choice state machine, with
the event history appended once at entry. The run remains on the
same map node throughout follow-up choices, including Battleworn
event combats and the existing Lantern Key forced encounter.

| Act | Pinned `AllEvents` | Engine entries | Known eligibility checks |
| --- | ---: | ---: | --- |
| Hive | 10 | 10 | Amalgamator requires two Strikes and Defends; Field of Man-Sized Holes requires a Perfect Fit target; Colossal Flower requires HP >=19; Zen Weaver requires gold >=125 |
| Glory | 7 | 7 | Round Tea Party requires HP >=12; Grave of the Forgotten requires an Exhaust-keyword card eligible for Souls Power |

`ColorfulPhilosophers` is **catalogued but unsupported**:
the source requires more than one unlocked character card pool and
offers three-rarity rewards from another character. The emulator
does not yet represent all unlocked character pools. For the
fully-unlocked fixture assumption, this ID remains in Hive's
candidate distribution, and drawing it raises an explicit
`NotSupportedException` *before* event entry. It must not be
silently replaced, filtered out or marked implemented.

`WarHistorianRepy` is excluded from `Glory.AllEvents`. The
existing Lantern Key conditional override remains higher
priority on Glory Event and Unknown nodes.

## Honest limitations

* Event selection currently uses **uniform weights** over eligible
  source-ordered entries and the prototype `event` RNG stream.
  Native event bag/history selection, rarity, unlocked event
  profile, draw order and native event-RNG call count remain unknown.
* Unknown node type resolution still uses the existing prototype
  odds; if it resolves to a non-Event later-act room, the emulator
  fails with `NotSupportedException`. Thus **ordinary later-act
  combat, elite, shop, treasure, boss and rest routing remain
  gated**. This patch does not make complete Hive/Glory runs playable.
* The single-player profile currently assumes other character
  card pools are unlocked only for the unimplemented Colorful
  candidate; full source `UnlockState` eligibility and
  cross-character mechanics are not modeled.
* Conditional filters use already available deck/gold/HP rules;
  item/difficulty-specific event odds and native oracle replay
  need fidelity capture. `LostWisp` persists its entry gold roll.
* This is **partial event-map integration**, not native fidelity
  validation. Coverage baseline marks Colorful as registered but
  not implemented; already implemented event bodies retain their
  previous conservative evidence status.

## Tests

The regression suite verifies all 17 act-listed IDs in source order;
source-known eligibility; one-time event histories; correct act
scope; deterministic event starts and event state validation through
actual `StepMap` map actions on a test-shaped native map; explicit
unsupported Colorful selection; unchanged source snapshots on
failure; guarded non-Event nodes; and later-act floor limits.
