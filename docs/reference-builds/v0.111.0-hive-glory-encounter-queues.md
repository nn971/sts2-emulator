## Source rule and change

The native `RunManager.GenerateRooms` initializes **all acts** at the
beginning of a run, sharing `run.Rng.UpFront` across act generations.
Each `ActModel.GenerateRooms` precomputes its encounter identities in this order:

1. `NumberOfWeakEncounters = 2` weak ordinary picks;
2. `BaseNumberOfRooms - 2` normal ordinary picks (12 Hive / 11 Glory);
3. 15 elite picks, using a separate grab bag;
4. a preselected boss.

Within a queue, a pool is refilled only after exhaustion. Picks are made
without replacement; a candidate sharing the **name or any
`EncounterTag`** of the preceding encounter is ineligible whenever
an alternative remains in the current bag. The weak-to-normal transition
carries the same preceding-encounter restriction. Elite history is
independent. If the whole remaining bag conflicts, source allows a
fallback draw from that bag. The same rules apply even if the player's
actual map path never visits most of the precomputed encounters.

The experimental `v111-experimental-silent-three-act-route-v1` now
builds both later-act sequences **during run initialization** and stores them
in `RunWorldState.PreparedLaterActEncounterBags`. Act entry transfers a copy
into the active `PrototypeLaterActEncounterBagV111`; both act entry and
combat/elite entry consume prepared identities without new selection draws. Arrays persist
through fork and exact JSON snapshot. Structural invariants recognize
legitimate duplicates across refill cycles, enforce queue lengths against
the ordinary-fight cursor, and reject foreign encounter identities.

The initial weak/normal/elite sequences and current position are internal
run state; a player-facing observation should reveal only the active
encounter (and other legitimately visible history).

## Scope and remaining native parity gaps

The distribution of each uniform legal choice matches the pinned
unit-weight grab-bag rule. The current implementation uses the
emulator's existing **prototype combat RNG**, and selects uniformly from
the eligible subset with one bounded draw. The native `GrabBag` calls
`NextDouble` and rejection-samples until the tag predicate succeeds;
all three acts are generated together from the shared `run.Rng.UpFront`
stream, after shared-Ancient assignment and before map traversal. Thus call counts,
ownership and seed-by-seed native encounter sequences remain **unverified**.
Act-local event shuffles, unlocked/shared-Ancient assignment and selection,
and the exact native full-run upfront cross-act generation order are also omitted
from this RNG sequence. Native discovery-order boss overrides remain an
additional gate.

The previous room-entry refill behavior is replaced in the
**experimental route only**. This changes generated encounters for the
same experimental seed. Historical experimental snapshots containing
short, partially consumed room-entry bags should be regenerated;
their incompatible queue lengths now fail validation rather than being
misread as version-2 pre-generated schedules. Default v111 and legacy
`sts2-ai` training paths are unchanged.

New regressions cover 64 seeds per act, complete bag cycles, weak-to-normal
tag restriction, RNG consumption boundary, exact entry snapshot and
corrupt cursor rejection. Real-game trace parity and complete natural
Hive/Glory victories remain outstanding.

Run-start preparation now also makes future encounter histories independent of
map traversal and prior combat draws. See [the follow-up audit](v0.111.0-upfront-regional-history.md)
for ownership tests and current experimental snapshot compatibility.
