# Encounter selection stochastic contracts

Pinned source evidence is consolidated in the [Hive/Glory queue audit](v0.111.0-hive-glory-encounter-queues.md), [Underdocks opening audit](v0.111.0-underdocks-opening.md), [native formation audit](v0.111.0-native-encounter-formation-rng.md), and the Overgrowth encounter implementation records. This page records the shared stochastic ownership and audience contract for the encounter-selection rows in the migration matrix; it does not replace those source audits.

## Site support and constraints

| Stable site ID | Owner and declared support |
| --- | --- |
| `run.encounter.overgrowth_boss.index_draw` | Run start; one choice from the ordered three-entry Overgrowth boss pool. The chosen boss is saved in `ActOneEncounterPool.BossEncounterId`. |
| `combat.encounter.formation.index_draw` | Encounter entry and floor; a source resolver requests bounded indices from an encounter-local native formation stream. The support depends on that encounter's pinned `GenerateMonsters` rule; fixed formations make no request. The read-only Native law accepts `native_encounter_entry`, `total_floor`, `support_count`, and `ordinal` to describe one exact bounded transform. |
| `combat.encounter.overgrowth_weak.index_draw` | Act 1 Overgrowth; remaining weak bag after prior draws, with exhaustion and source adjacency exclusions. |
| `combat.encounter.overgrowth_normal.index_draw` | Act 1 Overgrowth; remaining normal bag after prior draws, filtered by the source adjacency rules and the current supported pool. |
| `combat.encounter.overgrowth_elite.index_draw` | Act 1 Overgrowth; remaining elite bag, excluding the previous elite when another candidate remains and falling back to the remaining bag when necessary. |
| `combat.encounter.weighted_selection.ticket` | Ordered eligible weighted encounter definitions; the bounded ticket interval is the sum of their current weights. |
| `combat.encounter.underdocks.weak.index_draw` | Act 1 Underdocks; remaining weak bag with previous-encounter exclusion and exhaustion handling. |
| `combat.encounter.underdocks.normal.index_draw` | Act 1 Underdocks; remaining supported normal bag with previous-encounter exclusion and exhaustion handling. |
| `combat.encounter.underdocks.elite.index_draw` | Act 1 Underdocks; remaining supported elite bag with previous-elite exclusion and refill behavior. |
| `combat.encounter.underdocks.boss.index_draw` | Act 1 Underdocks run initialization; one choice from the configured ordered boss pool. |
| `combat.encounter.later_act.weak.index_draw` | Hive/Glory run initialization; ordered weak bag, draw ordinal, prior weak history, and the weak-to-normal adjacency restriction. |
| `combat.encounter.later_act.normal.index_draw` | Hive/Glory run initialization; ordered normal bag, draw ordinal, prior history, and source name/tag adjacency filtering. |
| `combat.encounter.later_act.elite.index_draw` | Hive/Glory run initialization; 15 ordered elite draws with a separate no-repeat bag, refills, and source adjacency filtering. |
| `combat.encounter.later_act.boss.index_draw` | Hive/Glory run initialization; ordered boss pool, followed by the separately modeled first-undiscovered-boss preference. |
| `combat.encounter.later_act.second_boss.index_draw` | Glory Ascension 10 or higher; ordered alternatives after the first boss is selected. |

These constraints and future queue positions are private stochastic state. The fair observation exposes the current room map and resolved combat; it does not expose encounter bags, candidate pools, queue history, RNG streams, or future draws. Act 1's selected Overgrowth boss is the explicit exception: `PrototypeAiObservation.ActOneBossEncounterId` projects that committed boss identity to the player.

## Resolution, probability status, and unsupported paths

The ordinary engine resolves Act 1 and legacy encounter entry through its run/combat mechanics. The opt-in three-act route prepares and consumes its Hive/Glory encounter histories at run initialization. Native formation selection is a separate combat-entry operation: `NativeEncounterFormationFactoryV111` returns the generated formation and the advanced encounter-local stream for the native combat-entry owner. The read-only Native formation law reconstructs only the context stream identity from the declared model entry and floor, and returns exact `NextInt` grid masses for the caller-declared support and ordinal. Its `SOURCE_VERIFIED` status covers that transform only; it does not validate the source candidate pool, resolver sequence, preceding `GenerateMonsters` prefix, seed derivation, or cursor parity. These paths do not exchange their private pools with the player observation.

Both fixed Act 1 boss pools have an outcome-blind direct law query at their
pre-run boundary. `chance_law_query` takes either boss site ID and ordinal
zero; an optional `support_count` must match its three-entry pool. It returns
one equal-weight outcome per source-ordered encounter ID and fingerprints the
fixed owner and pool. The laws remain `UNVERIFIED`: they describe the declared
index models, not the legacy seed-to-index distributions or Native cursor
parity. Queries are read-only. The existing Overgrowth run-action continuation
can still resume its legacy `start_run`; the configured Underdocks factory
remains source-owned.

The Glory Ascension 10 second-boss index also has a read-only conditional
query. Supply `first_boss`, `ascension` (at least 10), and the call's declared
ordinal on the legacy `combat` stream; an optional `support_count` must be two.
This draw follows the later-act encounter queue preparation, so its ordinal is
not fixed at zero. The query derives the source-ordered alternatives from the
declared first boss, fingerprints that pool and Ascension, and returns the
remaining encounter identities with equal weights. Its law remains
`UNVERIFIED` and does not validate the full run-start prefix or make later-act
initialization resumable.

The initial Hive/Glory boss-pool index has a read-only query conditioned on
`act` 2 or 3 and the call's declared ordinal on the legacy `combat` stream; an
optional `support_count` must match the selected act's three-entry pool. This
draw follows later-act encounter queue preparation, so its ordinal is not
fixed at zero. The law returns source-ordered encounter identities for the raw
draw and fingerprints the act and pool. It describes the draw before the
source's first-undiscovered-boss preference replaces the selected boss. The
equal-index model remains `UNVERIFIED`, and the query does not validate the
full run-start prefix or make encounter preparation resumable.

The controlled run-action continuation now covers the selected Overgrowth and
Underdocks encounter-pool index during eligible legacy Act 1 Combat/Elite map
entry, plus shared formation and combat-start indices. Its generic request-index
law remains `UNVERIFIED`; this is not a Native continuation. Configured
Underdocks boss selection and later-act encounter preparation remain outside
that session. Native formation support remains limited to source resolvers
already implemented by the factory.
Unsupported encounters or formation changes must fail before an invalid
continuation is published.

The migration matrix marks every site's probability provenance `UNVERIFIED`. Ordered emulator pools and pinned source constraints do not establish native seed/cursor parity or an independently calibrated conditional law. The native game's exact run-start order, several bag refill/fallback details, and unimplemented source encounter models remain separate fidelity work.
