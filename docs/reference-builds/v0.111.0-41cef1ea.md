## Audited passive surfaces

The installed assembly exposes:

- `[ModInitializer]` loader support;
- `CombatManager` lifecycle events for setup/start/turn/end/victory;
- `CombatManager.DebugOnlyGetState()`;
- `CombatStateTracker.CombatStateChanged`;
- serializable run/player RNG sets;
- the game's own `CombatReplayWriter` with initial-state, game-action,
  player-choice, and checksum recording methods.

The first bridge therefore observes public/runtime event surfaces and state
getters. It does not Harmony-patch combat semantics and does not infer a
global hook order.
