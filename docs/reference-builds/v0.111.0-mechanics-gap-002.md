## Progress since pass 001

The following generic mechanics are now represented in the prototype engine:

- **Innate**: innate cards begin combat in hand and count toward the normal opening-hand target;
- **Retain**: retained cards remain in hand during the end-turn discard step;
- **Sly discard/autoplay lifecycle**:
  - identify Sly cards before discard;
  - move selected cards to the discard pile;
  - dispatch a per-card `CardDiscarded` combat event;
  - resolve discard-trigger hooks;
  - auto-play queued Sly cards for zero Energy;
  - only then resume the parent card's suspended continuation;
- generated cards can derive their upgrade level from the source card.

The Sly ordering is source-backed. An auxiliary public STS2 decompilation exposes
`CardCmd.DiscardAndDraw` with the sequence:

1. collect the cards to discard and remember which are currently Sly;
2. move each card to Discard;
3. record `CardDiscarded`;
4. run `Hook.AfterCardDiscarded`;
5. complete any coupled draw;
6. auto-play the remembered Sly cards in order.

The exact local v0.111.0 decompilation remains authoritative before making a final parity claim.

## Remaining Sly content

The Sly lifecycle itself is now a reusable primitive.

Three pinned Sly cards remain blocked by independent mechanics rather than by Sly:

- **Ricochet** — repeated random-enemy targeting;
- **Abrasive** — Dexterity + Thorns power semantics;
- **Sneaky** — multiplayer-only reactive power; deferred for solo-first work.

This is the intended decomposition: `Sly` should no longer be treated as a blocker for Ricochet.

## Next high-value mechanics

### 1. Random target/effect

Needed by Ricochet and several other Silent cards.

Before implementing parity-sensitive randomness:

- identify the pinned native RNG stream used for random combat opponents;
- inspect whether each hit rerolls independently;
- preserve the exact call count/order in the versioned native ruleset.

The engine already has named RNG streams, so the likely work is a generic random-target effect
rather than card-specific code.

### 2. Core player powers

Implement the smallest generic pieces required for:

- Dexterity modifying card-derived Block;
- Thorns retaliatory damage;
- Vulnerable modifying incoming attack damage.

This unlocks Abrasive, Assassinate and additional relic/potion content.

### 3. Ethereal / Unplayable / Eternal

These are universal card properties but are not required by the current Silent reward pool.
They should be added before status/curse generation expands:

- Ethereal: cards still in hand at end of turn Exhaust instead of Discard;
- Unplayable: omit the card from legal play actions;
- Eternal: block run-deck removal/transform operations.

### 4. Conditional effects

The broad conditional bucket is still the largest structural gap. Do not introduce one giant
condition enum. First classify source patterns into small reusable predicates such as:

- first/next N occurrences this turn/combat;
- hand/pile composition;
- cards played/discarded/drawn this turn;
- target power/status state;
- unblocked damage;
- HP/death conditions.

## Differential testing policy

No new live-game capture is justified by this pass.

The unresolved questions are static-source questions first. A new bridge build/game launch should
only happen after implementation reaches a specific ambiguity that the exact pinned source cannot
settle or when differential replay is needed to validate a substantial subsystem.
