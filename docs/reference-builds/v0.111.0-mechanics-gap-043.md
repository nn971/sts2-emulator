# v0.111.0 mechanics gap — pass 043

This pass changes the active Overgrowth work from broad combat-content implementation to a
**seeded fidelity-audit baseline**.

## Scope

Overgrowth remains the only active Act 1 target.

Underdocks is deliberately deferred even though it remains represented in the completeness ledger.
The branch already contains current-semantic implementations for all 22 Overgrowth combat encounters:

- 4 weak;
- 12 normal;
- 3 elite;
- 3 bosses.

The next fidelity questions are therefore about visibility, seeded encounter sequences, live-oracle
agreement, and eventually RNG/timing parity rather than missing encounter definitions.

## Preselected boss visibility

The Overgrowth boss is selected at run start and stored in canonical Act 1 encounter-pool state.
That identity is player-visible strategic information and must therefore cross the AI observation
boundary.

`PrototypeAiObservation` now exposes:

- `ActOneRegion`;
- `ActOneBossEncounterId`.

A focused regression checks that the observed boss equals the canonical preselected boss and belongs
to the three-entry Overgrowth boss pool.

The seed and RNG state remain hidden from ordinary AI observations.

## Seeded Overgrowth audit command

The developer CLI now provides:

```fish
dotnet run --project src/Sts2Emulator.Cli -- \
    prototype-overgrowth-audit 100 0
```

The command initializes real run state, then synthetically enters ordinary/elite/boss rooms while preserving the canonical encounter bags. This isolates encounter-selection semantics from combat-policy survival. It reports:

- coverage across all 22 Overgrowth combat encounter IDs;
- encounter occurrence counts;
- preselected boss frequencies;
- weak-pool no-replacement violations;
- any Overgrowth encounters not reached by the sampled policy.

Every transition is checked through `PrototypeStateInvariants`.

This command is intentionally a **selector/state structural audit**. It does not claim that encounter
frequency or ordering matches the native RNG codec/call schedule.

## What this audit can catch

The selector audit is useful for detecting regressions such as:

- an Overgrowth encounter becoming unreachable from its selector;
- a boss not being selected at run start;
- a weak encounter repeating during the first three ordinary combats;
- selection-state corruption that only appears across long whole-run transitions;
- schema changes that hide strategic boss information from search consumers.

## What remains outside this pass

The command does not prove native fidelity for:

- exact encounter RNG state/call order;
- exact map generation;
- exact rewards/events/rest sites;
- exact combat RNG;
- subtle native hook/timing boundaries.

Those require live reference evidence.

## Next Overgrowth work

The highest-value native differential targets are now the mechanics with timing or lifecycle risk:

1. Ceremonial Beast Plow threshold -> Strength reset -> Stun transition;
2. The Kin Priest death removing both Followers;
3. Phrog Parasite death summons, especially player-turn versus enemy-turn-start deaths;
4. Fogmog / Eye With Teeth death-revive-minion lifecycle;
5. Vantom / Inklet Slippery HP-loss capping and consumption.

The existing Loadout-assisted oracle workflow is suitable for these targeted combats. We should
capture them as small synthetic native probes rather than replaying entire natural runs just to reach
a specific encounter.

Once those high-risk mechanics are live-checked, the next question is whether whole-Act divergence
is dominated by encounter/map RNG, non-combat room semantics, or remaining Silent content.
