# v0.111.0 native Tough Egg in-place hatching

Source: `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`,
`src/Core/Models/Monsters/ToughEgg.cs` (the
`HatchMove`, `Hatch`, and `GenerateMoveStateMachine` methods).

## Audited behavior

The source does **not** destroy a ToughEgg and summon a Hatchling.
`HatchMove` sets the existing egg's `IsHatched` state, removes Hatch,
and removes every other power except Minion. `Hatch` performs an
unconditional direct `RunRng.Niche.NextInt` roll for the hatchling HP
range and calls `SetMaxAndCurrentHp` on **the same creature**.

- A0–A7: 19–22 inclusive; A8–A10: 20–23 inclusive.
- Each hatch consumes one direct bounded `run.niche` draw.
- There is **no unique-HP exclusion set** and no new monster-combat ID.
- `ToughEgg` remains the source `MonsterModel`; its move state
  advances from Hatch to self-looping Nibble.
- The original creature's `MonsterModel.Rng`, formation slot and
  native encounter RNG do not advance because of the hatch.
- Hatch does not reset Block or recreate the combat creature.
- A separate `AfterAddedToRoom` path can hatch an egg preemptively
  when it spawns with `IsHatched=true`; the experimental native
  integration here covers the **existing egg's HatchMove**, not
  that separate instantiation branch.

## Representation

The earlier prototype implementation changed
`EnemyCombatState.EnemyId` from `ToughEggId` to `HatchlingId` for
the post-hatch move definition. In the opt-in native sidecar this is
now an **explicit move/observation proxy**, marked by
`NativeToughEggHatched`; it is not a new native MonsterModel.

`NativeCombatRngEntryV111.HatchToughEgg` retains the original
`NativeEncounterFormationV111.Enemies` entry and
`NativeEncounterMonsterContextV111`, including original ToughEgg
model identity and monster-local stream. It atomically advances
`run.niche`, sets current/max HP, clears non-Minion powers, and
preserves the existing typed enemy's instance, slot and Block.

Native validation permits exactly this guarded ToughEgg/Hatchling
proxy mismatch, only inside the `OvicopterNormal` formation when
the explicit marker is present. Any other spontaneous model swap
still fails validation, and general native `TransformEnemy`
continues to throw `NotSupportedException`.

## Scope and tests

`NativeToughEggHatchV111Tests` performs 192 independently seeded
A0/A8/A10 hatches with direct RNG-oracle roll comparison; checks
unchanged native encounter and creature-local RNG streams,
unchanged combat ID/slots, power cleanup and immutable snapshots;
and exercises serialization plus invalid marker/model mismatch
rejection.

The native Hive map, Ovicopter room selection, native encounter
formation/summon timing, visual-only setup, and full native
gameplay oracle parity **remain unsupported**. The isolated
`PrototypeNativeLaterActFixture` is sufficient to exercise the
native hatching state transition but is not a real-game replay.

Default prototype/AI training remains unchanged.
