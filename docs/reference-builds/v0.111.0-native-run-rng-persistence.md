# v0.111.0 persistent native run RNG ownership

Source pin: `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`
(`RunRngSet`, `PlayerRngSet`, `EncounterModel`, `CombatState`,
`MonsterModel`, and `Creature`).

## Canonical long-lived owner

`RunState.NativeRunRng` is a separate, nullable native v111
`RngBundle`: 12 `run.*` and three `player.*` streams.
It does not replace the six prototype `RunState.Rng` streams.
`V111RunFactory.Create` now seeds the 15 native streams on the configured
run, and `V111RunFactory.Initialize` preserves their full cursors.
Legacy prototype factories retain `NativeRunRng == null` unless
`NativeRunRngV111.Enable` is called explicitly.

- `RunState.Fork` deep-copies all native stream byte arrays.
- `RunSnapshot.Save/Load` preserves the full native stream state, including
  the independently seeded 15-stream inventory and counters.
- `PrototypeGameEngine.Step` preserves the persistent owner through
  room transitions. When an *explicitly attached native combat* consumes
  native RNG, `NativeRunRngV111.ReconcileAfterStep` copies the advanced
  combat-side run streams back to the run; if combat ends, the final
  combat-side run cursor is retained before the temporary combat disappears.
- `NativeRunRngV111.Validate` is invoked by
  `PrototypeStateInvariants.Validate` and checks the exact inventory,
  codec/counters, and equality of all 15 cursors in run and active combat.
  A missing native run owner or inconsistent combat cursor fails explicitly.

## Explicit combat transfer

`NativeRunRngV111.BeginEncounter(state, formation)` requires an active,
matching typed combat and native run bundle. It calls the isolated
`NativeCombatRngEntryV111.AttachAndRollInitialHp` with the **current**
run cursor, consumes native `run.niche` in creature order, and transfers
the updated stream set back to `RunState.NativeRunRng`.

`NativeRunRngV111.ReplaceCombat` copies back all advanced native stream
cursors after a pure intent commitment or creature-local operation.
`NativeRunRngV111.ReleaseCombat` explicitly detaches the combat's
native owner without resetting the persistent run cursors.
`NativeRunRngV111.SampleNextInt` offers an opt-in audit draw for
one named native run/player stream; in combat, the run and combat owners
advance atomically, and outside combat only the persistent run owner
advances. Neither affects the old six-stream RNG.

`NativeCombatRngEntryV111.CommitIntents` and
`NativeCombatRngEntryV111.AdvanceMonsterLocal` remain opt-in pure
combat utilities. End-to-end deterministic snapshots can now retain
the same 15 native run/player RNG cursors across different encounters,
rather than recreating their seed on every combat entry.

## Limits

**Native RNG ownership is not live native gameplay parity.** The v111
configured Silent run is still restricted to Act 1 execution. Normal
`StartCombat` still constructs source-shaped combat using prototype
formation, HP and opening draws; the native combat binding is opt-in
and must be given the correct native encounter entry, actual creature
combat IDs and source-specific slot formation. It does not recover
historical RNG consumption from an already-played prototype combat,
and it does not migrate reward/event/shop streams or delayed summoning
semantics. Any source-specific HP hooks, stable `HashSet` ordering,
and complex native AI call ordering still need oracle comparison.

The new default 15-stream `NativeRunRng` for configured runs is
**sidecar-only** and advances only through explicitly integrated
native RNG operations; the existing prototype mechanics still consume
`RunState.Rng`. No silent substitution or unsupported Hive/Glory
content is enabled.

## Checks

```fish
dotnet test Sts2Emulator.sln -c Release --filter FullyQualifiedName~NativeRunRngV111Tests
```

The tests cover configured run initialization, legacy opt-in, real
Act 1 map→combat transition, native HP draws after prior run-level
consumption, run/combat atomicity, fork/JSON/snapshot replay, release
of combat-local owners, preservation into the next room, and corruption
rejection. Real-game trace parity remains an independent release gate.
