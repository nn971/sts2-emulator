## Implemented experimental quest route

- In the experimental route's Glory act (native act index 2 / emulator act 3), a persistent
  Lantern Key overrides an unknown map node to an Event room and
  replaces an eligible event with War Historian Repy. Both direct Event
  and Unknown rooms are intercepted. Other unsupported Glory unknown
  rooms still reject rather than using prototype fallbacks.
- Repy's initial options unlock the cage or chest. Initial choice
  removes one **specific** Lantern Key card from the persistent deck.
- Cage sets `FreedRepy` on the run and obtains the event-only
  `History Course` relic.
- Chest pre-rolls two potion offers and two *distinct* relic offers
  at the moment it is chosen. All four appear on one reward screen;
  each offer can be taken or skipped independently. Potion choices can
  replace occupied slots. The hidden selections and per-offer resolution
  persist in the reward state.
- If more keys remain after the initial choice, the **opposite**
  choice becomes available, after reward resolution. That second
  choice removes *all* remaining Lantern Keys, matching the
  source's single-player RemoveLanternKeysForSecondChoice.
- Snapshot forks, unknown-room RNG non-consumption, multiple-key
  consumption, independent optional rewards and page legality are
  covered by deterministic regressions.

## Known differences and blockers

- All four chest offers are rolled on entry, independently of prior
  reward-taking actions. The emulator now presents the source-shaped
  single screen and supports independently taking or skipping each
  potion and relic. Native card/relic bags and RNG stream ownership
  remain unverified.
- The v111 native CardFactory/RelicPool bags and RNG stream ownership
  are not integrated. The event currently draws from the implemented
  prototype potion and relic pools. Offer distributions remain provisional.
- `History Course` now implements the native
  `AfterAutoPrePlayPhaseEntered` hook: capture the last finished
  non-dupe Attack on each player turn, then on turn 2+ duplicate
  and auto-play it after start-turn effects. The copy uses the
  existing source-shaped free auto-play and `combat_targets` RNG,
  retains upgrade/card state, dispatches normal card-play triggers,
  and is excluded from the next turn's source history.
- Combat-history snapshots and duplicate markers are cloned on forks.
  Capturing at `CardPlayed` approximates the native
  `CardPlaysFinished` reference in the absence of an independently
  modeled native history list. Multi-character owner filtering and
  native live-trace parity are unverified. History Course remains
  conservatively classified **partial** pending native validation.
- The default configured route remains gated. The experimental Glory map and
  supported event bag are integrated; complete event eligibility, native RNG
  parity and oracle replay remain open. No native parity claim is made.

## S0 stochastic boundary: War Historian Repy chest offers

The two `event.war_historian.repy.*` rows occur when the chest choice is
resolved. The emulator draws two potion offers independently from its
configured potion pool and shuffles its supported unowned relic pool before
taking two distinct relic offers. These are restricted prototype supports;
`player.rewards` attribution remains a source hypothesis, with legacy
`reward` providers retained. Native pool order and stream assignment are not
confirmed.

The player sees the four chest offers and their take-or-skip results, not the
candidate-pool order or RNG state. The existing atomic event-shuffle session
admits only the page-zero `unlock_chest` action before reward generation. It
captures the relic shuffle followed by both potion indices, conditions each
potion law on the full preceding prefix, replays the ordinary action, and
commits the completed offers with the Nature cursor. Configured Native replay
preserves the captured `player.rewards` cursor; the Native-regional fallback
validates the legacy `reward` ordinal and call count. The event has no Native
event RNG context at this boundary.

The declared-support Native bounded-index transforms are `SOURCE_VERIFIED`
under the uniform-grid model. This does not establish the emulator pool's
fidelity, `player.rewards` attribution, seed frequencies, or Native cursor
parity. Legacy equal-index weights remain `UNVERIFIED`; see the [atomic session
contract](../REFERENCE_NATURE_NATIVE_EVENT_SHUFFLE_D3.md#boundary) for the
supported boundary and replay limits.
