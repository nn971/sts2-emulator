# v0.111.0 mechanics gap — pass 032

This pass promotes **Shrinker Beetle**, implements its source-bound **Shrink** debuff, and completes
the monster/formation prerequisites for all four Overgrowth weak encounters.

## Shrink

The Beetle version of Shrink is represented as a player power with:

- debuff semantics, so Artifact-style blocking uses the ordinary generic path;
- source binding to the applying enemy;
- non-stacking behavior;
- player Attack damage multiplier 7/10;
- automatic cleanup when the source enemy dies.

This matches the pinned source behavior that Beetle Shrink is permanent while its source lives and
disappears when that Beetle is defeated.

The generic attack-value pipeline applies the multiplier only to powered Attack damage. Other
damage sources remain outside this modifier.

## Shrinker Beetle

Pinned v0.111.0 values:

- HP 38–40 at A0–A7;
- HP 40–42 at A8+;
- Shrinker: apply Shrink;
- Chomp: 7 damage, 8 at A9+;
- Stomp: 13 damage, 14 at A9+.

The move program is:

1. fixed Shrinker opener;
2. Chomp;
3. Stomp;
4. alternate Chomp / Stomp forever.

The existing sequential-loop representation handles this directly with loop start index 1.

## Reference encounters

Two weight-0 reference encounters are added:

- `SHRINKER_BEETLE_WEAK`: one Shrinker Beetle;
- `OVERGROWTH_CRAWLERS`: Fuzzy Wurm Crawler in position 0 and Shrinker Beetle in position 1.

These promote model + formation fidelity without yet enabling native pool selection.

## Regressions

Focused tests verify:

- A0/A8 HP ranges;
- A9 Chomp/Stomp scaling;
- Shrinker opener and Chomp/Stomp alternation;
- Shrink reducing a 6-damage Strike to 4;
- source-bound Shrink disappearing immediately when the Beetle dies;
- the weak singleton and Fuzzy+Beetle reference formations.

## Weak-pool milestone

All four native Overgrowth weak encounters now have source-backed monster models and source-backed
formations:

- `NIBBITS_WEAK`;
- `SLIMES_WEAK`;
- `FUZZY_WURM_CRAWLER_WEAK`;
- `SHRINKER_BEETLE_WEAK`.

The remaining weak-pool work is encounter queue semantics rather than combat mechanics.

## Next work

Translate the native Overgrowth weak queue as one unit:

1. the first three ordinary monster combats use the weak pool;
2. the weak pool has four equal-weight encounters;
3. three distinct weak encounters are consumed per run, so no weak encounter repeats during those
   first three combats;
4. after the weak phase, ordinary monster combats use the normal pool.

preserve pool eligibility/history semantics and keep the selection state explicit and forkable.
