# v0.111.0 native Overgrowth combat gold

Pinned sources: `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`,
`Core/Models/EncounterModel.cs`, `Core/Rewards/RewardsSet.cs`,
`Core/Rewards/GoldReward.cs`, and `Core/Helpers/AscensionHelper.cs`.

## Source-backed bounds

| Room | A0–A2 | A3+ (Poverty) |
| --- | --- | --- |
| Normal encounter | 10–20 | 7–15 |
| Elite | 35–45 | 26–33 |
| Boss | 100 | 75 |

`EncounterModel` supplies these defaults. From Ascension 3 onward
`Poverty` applies a 0.75 multiplier **to each endpoint individually**,
then truncates to integer. `GoldReward.Populate` draws an inclusive
uniform integer from the resulting interval with the player's Rewards RNG.
Normal combat scales *both* endpoints by `CombatRoom.GoldProportion`
using float multiplication and midpoint-to-even rounding. A normal
combat with proportion zero omits the gold reward and consumes no gold
RNG draw. Elite and boss rewards use the unscaled interval.
The first Overgrowth combat profile has no implemented escaping enemies;
its combat gold proportion is therefore 1.

The restricted emulator now rolls this amount on its Rewards stream
before generating card reward options, stores it in
`RewardState.NativeCombatGoldAutoGranted`, and credits the player's
gold in the existing reward-entry transition. The older prototype
generation profile keeps its legacy economic constants.

## Deliberate remaining fidelity gap

Native gold is a selectable `GoldReward` which is credited when the
player clicks the reward. The prototype still credits combat gold at
reward entry. This is an explicit compatibility choice for existing
whole-run reward actions; a future native reward-selection pass should
replace it with `take_reward_gold` and support leaving gold behind.
Encounter-specific gold overrides, escaped monsters, stolen-gold
recovery, gold-gain hooks, and exact native RNG call order remain
separate follow-up tasks.
