# v0.111.0 native combat RNG snapshot owner identity

Pinned context source: `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20` — `EncounterModel.GenerateMonstersWithSlots` and `CombatState.CreateCreature`.

## Why this matters

The emulator's experimental native combat sidecar preserves the encounter's independent RNG and each creature's independently seeded RNG. The existing validation checked xoshiro snapshots and positional monster model/slot bindings. Swapping two otherwise valid monster-local stream cursors could therefore pass validation while changing the future stochastic behavior after a fork or JSON restoration.

## Owner binding

`NativeCombatRngEntryV111.Validate` now checks:

- The encounter RNG stream identity identifies the exact native encounter entry and total floor.
- Each creature RNG stream identity identifies its recorded native **CombatId**, native act index and map coordinate. Stream IDs must be distinct.
- When recorded, creation provenance includes both run seed and native act index; the index must match the combat act. Source-compatible map coordinate bounds are checked.
- Initial combat attachment validates the finished sidecar before returning. No new RNG draws are introduced.
- Historical isolated snapshots lacking both optional provenance fields retain their previous accepted shape, with distinct monster-stream IDs and encounter identity still checked.

The native CombatId belongs to the source creature context; it can differ from the emulator's prototype InstanceId in isolated fixtures. No new assumption equates those IDs.

## Tests

`NativeCombatSnapshotIdentityV111Tests` exercises multi-enemy stream swapping and duplication using individually valid native streams; an encounter stream from another entry, changed floor, changed act, wrong map coordinate, and partial provenance; plus 36 valid fork/JSON/advanced-cursor cases across Hive/Glory and non-default first CombatIds.

These tests enforce coherent **snapshot ownership**, rather than establishing native call-order or observed game parity. Native creature creation, full encounter/boss behavior, and the reference differential corpus remain separate roadmap items.
