# v0.111.0 mechanics gap — pass 015

This pass adds the first complete source-bound Affliction lifecycle, using Spectral Knight's Hex as
the native acceptance case. It also extends the enemy move model with an opener prefix followed by a
repeating suffix so Spectral Knight can be represented without faking its pattern.

## Native evidence

Pinned/current source-derived references establish the v0.111.0 behavior used here:

- Spectral Knight has 93 HP at base difficulty.
- Its opening move applies 2 Hex. Hex does not stack, so the visible amount has no gameplay effect.
- After Hex, Spectral Knight alternates Soul Slash and Soul Flame.
- Soul Slash deals 15 damage at base difficulty.
- Soul Flame deals 3 damage three times at base difficulty.
- While Spectral Knight is alive, Hex marks every otherwise-unafflicted player-owned combat card
  with Hexed.
- Hexed adds Ethereal.
- Cards already carrying another Affliction are skipped.
- Cards generated after Hex is applied become Hexed on arrival.
- When Spectral Knight dies, Hex disappears and the Hexed state supplied by that source is removed.
  Intrinsic Ethereal or unrelated Afflictions remain.

## Source-owned power and Affliction state

`PrototypePowerInstanceState` can now carry an optional source-enemy instance ID.

`PrototypeCardAffliction` can likewise record the enemy instance that owns a source-bound
Affliction.

`PrototypePowerDefinition` has generic metadata for this family of mechanics:

- source-bound-to-enemy;
- non-stacking;
- Affliction applied to cards while active;
- skip cards that already carry an Affliction;
- clear the source-owned Affliction when the power is removed with its source.

The combat invariants now require:

- every source-bound player power to point at a live enemy;
- non-source-bound powers not to carry an enemy source;
- every source-owned card Affliction to have a matching active source power.

This avoids using the power ID alone as ownership. Two hypothetical sources can therefore be
distinguished even when they apply the same Affliction kind.

## Enemy-sourced player powers

`PrototypeEnemyEffectKind` now includes `ApplyPlayerPower`, and enemy effects can identify the
power to apply.

When the enemy effect creates a source-bound player power, the acting enemy's combat instance ID is
attached automatically. Ordinary card/potion player-power application remains source-less.

Hex is represented as data:

- power ID `proto.power.hex`;
- source-bound;
- non-stacking;
- applies Hexed;
- skips already-afflicted cards;
- clears its source-owned Hexed tags when its source disappears.

The native amount of 2 is preserved on the power instance even though the power is non-stacking.

## Existing-card coverage

Applying Hex walks the combat-card registry rather than just Hand.

That means Hand, Draw, Discard and Exhaust cards are all covered through the same card instances.
A card with an existing Affliction is left unchanged.

The Affliction itself stores Spectral Knight's enemy instance ID so later cleanup only removes state
owned by that source.

## Generated-card arrivals

Generated cards pass through the active source-bound Affliction powers before entering Hand or
overflowing to Discard.

This covers Blade Dance/Shiv-style generation without mutating each generator separately.

It also gives the correct Nightmare interaction:

1. Nightmare selects a Hexed card.
2. Nightmare's selected-card snapshot transform removes Affliction from the stored payload.
3. If Spectral Knight is still alive when Nightmare creates the copies next turn, those newly
   created cards enter the active Hex environment.
4. The clean payload copies are therefore Hexed again on arrival.

The copy transform and the ambient source lifecycle are intentionally separate layers.

## Source-death cleanup

Whenever an enemy reaches zero HP through the currently modeled death paths, source-bound player
powers owned by that enemy are removed.

Before the combat state is exposed again, card Afflictions supplied by those removed powers are
cleared by the exact pair:

`(source enemy instance ID, Affliction kind)`.

Cleanup is wired through:

- direct enemy damage resolution;
- enemy status-stage deaths;
- enemy-action retaliation deaths.

This means killing Spectral Knight immediately removes Hex rather than waiting for the end of the
turn.

The regression test also verifies the v0.107-era bug-fix behavior: an intrinsically Ethereal Dazed
remains Ethereal after Hexed is removed, while an ordinary Defend no longer follows the Ethereal
path.

## Enemy opener/loop move policy

The previous prototype enemy model repeated the full move array forever. That could not represent
"one opener, then repeat a suffix."

`PrototypeEnemyDefinition.MoveLoopStartIndex` now supplies that boundary:

- move indices before the boundary occur once;
- after the explicit move array is exhausted, only the suffix beginning at the boundary repeats.

Existing enemies default to zero and therefore preserve their previous cyclic behavior.

Spectral Knight uses:

- move 0: Hex;
- move 1: Soul Slash, 15;
- move 2: Soul Flame, 3 × 3;
- loop start: 1.

The resulting sequence is:

`Hex, Soul Slash, Soul Flame, Soul Slash, Soul Flame, ...`.

## Production-content boundary

`proto.enemy.spectral_knight` is now a production enemy definition with exact prototype A0 values.

It is deliberately **not** added to the reachable encounter catalog yet.

Knight Gang as a real encounter still requires at least:

- native Flail Knight behavior, including its random post-opener policy and repeat restriction;
- Magi Knight / Dampen semantics;
- native Ascension 8 HP and Ascension 9 damage scaling;
- Artifact/debuff immunity for blocking Hex;
- encounter-order and reward parity.

Keeping Spectral Knight unreachable avoids overstating whole-encounter fidelity while still letting
its exact isolated mechanics drive reusable engine work.

## Tests

Focused coverage verifies:

- Hex applies 2 stacks and remains non-stacking when reapplied;
- source enemy identity is stored on the power;
- every pre-existing un-afflicted combat card becomes source-owned Hexed;
- an existing different Affliction is skipped;
- generated Shivs become Hexed while the source lives;
- Nightmare clears Hexed from its stored payload but generated copies are re-Hexed on arrival while
  Hex remains active;
- killing the source removes Hex and only its source-owned Hexed state;
- unrelated Afflictions survive source cleanup;
- intrinsic Ethereal survives Hex cleanup;
- the real Spectral Knight definition has the expected opener/loop metadata and A0 numbers;
- executing four enemy turns produces Hex, 15, 3×3, 15 in that order.

## Remaining frontier

The first Affliction lifecycle is now end-to-end, but Hex still bypasses one important native
defense: Artifact/debuff immunity is not yet represented in the prototype player-power path.

For Knight Gang fidelity, the most natural next structural work is either:

1. generic debuff application/blocking, with Hex as the acceptance case; or
2. the remaining knight move/power mechanics, especially Dampen, which is another source-bound
   whole-card-state effect.

A full Knight Gang encounter should wait until both pieces are available.
