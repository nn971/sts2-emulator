# v0.111.0 experimental native creature creation and RNG ownership

Reference build: `Flaaax/STS2-source@706ef1c9fa2219220065849fd5265328607ece20`,
notably `Core/Combat/CombatState.CreateCreature`,
`Core/Entities/Creatures/Creature.SetUniqueMonsterHpValue`, and the
`Core/Models/Monsters` source implementations.

This extends the explicitly opt-in `NativeWeakCombatEntryFidelityId`
combat path to support **append-only creature creation**, while leaving
default configured runs and prototype training unchanged.

## Native lifetime ownership

The `NativeEncounterFormationV111` snapshot now retains immutable
`RunSeed`, `NativeActIndex`, `MapColumn`, and `MapRow` provenance.
Older JSON fixtures without these fields deserialize unchanged; live
creature creation requires the pinned provenance.

`NativeCombatRngEntryV111.AppendSummonedEnemy` validates the existing
combat and RNG contexts **before** advancing any stream, and:

1. Requires a new strictly increasing lifetime CombatId matching the
   newly assigned prototype `EnemyCombatState.InstanceId`. Prior
   defeated monsters remain in the typed combat history.
2. Samples one HP index using the current persistent `run.niche`
   stream, including one draw for fixed ranges, excluding max HP of
   **living** enemies where possible and using the full range if all
   choices are occupied.
3. Preserves both `Hp` and `MaxHp` for the new monster.
4. Creates a separate `NativeRngV111Contexts.ForMonster` stream seeded
   by the original run seed, act index, current map coordinate and
   assigned native combat ID. This cursor starts at zero and is not
   `run.monster_ai` or the encounter-local generation RNG.
5. Appends matching source-shape `PrototypeEncounterEnemySpec` and
   `NativeEncounterMonsterContextV111` records atomically; existing
   RNG cursors, enemy histories, and the original snapshot are untouched.
6. Returns a new, fully validated combat. The ordinary engine
   reconciles its advanced run streams back to the canonical run owner.

The native creation handoff is used in both the general
`PrototypeEnemyEffectKind.SummonEnemy` path and the
`ResolveEnemyDeathSummons` path. Their **prototype** paths remain
unchanged, including their original combat-stream draws.

## Strict lifecycle boundaries

- **Native transformation** remains rejected with
  `NotSupportedException`; mutating a live creature model and reusing
  its RNG has not been source-audited.
- **Randomized summon pools** remain rejected in opt-in mode until their
  source-specific selection RNG call order is confirmed.
- Untracked removal/replacement or formation inconsistencies still
  reject at the native reconciliation/validation boundary; no silent
  fallback, no malformed snapshot.
- Spawn selection eligibility, slot assignment, summoned special
  effects, and monster AI still use the existing source-shaped
  prototype mechanics in this milestone. The new native RNG *identity
  and HP sampling* do not establish exact summon behavior parity.
- Later-act Hive/Glory execution and multiplayer remain gated.

## Test coverage

`NativeCreatureCreationV111Tests` exercises repeated native spawn
allocation, strict immutable-input behavior, `run.niche` counters,
all new monster-local seeds and cursor independence, invalid/reused
combat-ID rejection, and deep forks.

`NativeActOneNormalCombatEntryV111Tests` also exercises a real
Underdocks Living Fog fight through **two enemy turns**, including the
first native Gas Bomb creation and exact whole-run snapshot replay.

Native game trace and complete on-spawn effect oracle parity remain
future tasks.
