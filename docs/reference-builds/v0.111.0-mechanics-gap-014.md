# v0.111.0 mechanics gap — pass 014

This pass introduces typed combat-card Affliction state, implements Hexed's keyword effect, and
makes Nightmare's v0.111.0 Affliction-clearing behavior a generic snapshot transformation.

## Native evidence

The pinned v0.111.0 build contains seven card Affliction identities:

- Bound;
- Entangled;
- Galvanized;
- Hexed;
- Ringing;
- Smog;
- Tainted.

The acceptance cases for this pass are intentionally narrower than that identity catalog.

**Hexed** adds Ethereal to the afflicted card.

Since v0.104.0, **Nightmare** has an explicit exception to its otherwise rich card-copy semantics:
if the selected card has an Affliction, the cards generated next turn do not carry that Affliction.
The selected original card remains afflicted.

## Typed combat-card state

`CombatCardInstance` now has an optional `PrototypeCardAffliction` containing:

- a typed `PrototypeCardAfflictionKind`;
- an integer amount.

`PrototypeCombatCardSnapshot` can also carry Affliction state. This keeps the generic snapshot
representation capable of preserving an Affliction for clone operations whose native semantics do
so.

Affliction is combat-card state in this first slice; it is not added to the persistent
`CardInstance` deck record.

The presence of all seven enum values is an identity/modeling commitment, not a claim that all seven
effects are implemented.

## Generic selected-card snapshot transforms

`PrototypeSelectedCardPowerSpec` / action now support
`ClearAfflictionFromPayload`.

When a selected-card payload is built, the transform is applied while the source combat-card
instance is left untouched.

Nightmare declares this flag in content data. The combat engine therefore contains no
Nightmare-specific branch for Affliction handling.

The resulting lifecycle is:

1. Nightmare selects an afflicted card.
2. The original card keeps its Affliction.
3. Nightmare's instanced power stores a snapshot with no Affliction.
4. At `BeforeHandDraw`, generated copies are created from that clean snapshot.
5. Every generated copy is un-afflicted.

The same snapshot still preserves the other modeled properties: upgrade level, opaque card state,
combat-local cost state, keyword overrides, Replay, Enchantment, and single-use Enchantment
consumption.

## Hexed

The effective card-keyword query now treats Hexed as another source of Ethereal.

End-turn hand cleanup already asks the generic effective-keyword query before moving cards.
Consequently a Hexed card remaining in Hand follows the same Ethereal path as an intrinsically
Ethereal card and is moved to Exhaust.

Other Afflictions currently carry identity/amount only.

## Tests

Focused coverage verifies:

- Nightmare's content definition requests Affliction clearing from its selected-card payload;
- an Entangled source card selected by Nightmare remains Entangled;
- the stored Nightmare payload is un-afflicted;
- all three generated copies are un-afflicted;
- Hexed contributes effective Ethereal at end of turn;
- a non-Hexed Affliction does not accidentally contribute Ethereal.

The full CI suite is green.

## Deliberate boundary

This pass models card-local Affliction state and one card-local effect. It does not yet model the
complete source lifecycle of Afflictions.

Examples still requiring native encounter-driven work include:

- enemy/power commands that apply an Affliction to particular card populations;
- restrictions on applying a second/different Affliction;
- source-dependent cleanup, such as Hexed cards clearing when the governing Hex no longer applies;
- Bound/Ringing/Smog turn restrictions;
- Entangled cost modification;
- Galvanized/Tainted damage hooks.

Those should be added from the pinned source together with the encounter/power that owns them.

## Next frontier

Prefer a concrete native encounter as the next driver for Affliction lifecycle work. If no
high-priority Silent encounter needs it immediately, return to the enchantment corpus and add the
next modifier whose semantics reuse existing generic cost/keyword/event primitives.
