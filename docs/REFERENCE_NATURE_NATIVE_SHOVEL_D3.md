# Native Shovel ReferenceNature continuation

**Snapshot:** 2026-10-21. **Status:** the dedicated session is implemented for
one legal configured Native Rest `dig` action; the generic run-action session
also handles the Native-regional fallback when `NativeRunRng` is absent.
Source-pool fidelity and Native cursor parity remain open.

## Boundary

`ReferenceNatureNativeShovelSessionV111` starts only from a legal Rest `dig`
action with Shovel on a configured Native route. It replays that ordinary
action and captures the relic-bag rarity float followed by the relic identity
index. Those requests, the resulting Reward, and the ReferenceNature sampler
cursor form one saved boundary. Until both requests resolve, the published run
remains at its projected origin. The completed Reward and Nature cursor are
committed together.

The session uses `relic_grab_bag.rarity.unit_float` on `player.rewards` and
`treasure.relic_grab_bag.model.index_draw` on the same stream. It rejects other
phases, routes, actions, or stochastic sites. The Native relic queue is
projected to canonical `NatureUnordered` rarity sets; selected identities are
applied through the existing `PlanPull` and `PullSelected` helpers.

## Law and replay

The rarity request uses the shared exact Native float-threshold Chance Law.
Its 50/33/17 transform is `SOURCE_VERIFIED` for the declared request. The
identity request uses the exact Native bounded-index transform on the current
sorted fallback support. The session recomputes that support from the origin
and prior selected identities, then validates the rarity, fallback tier,
support, and request owner before accepting the choice. Its Chance Law uses
those validated relic IDs as ordered outcome IDs and preserves the exact
bounded-index weights.

Each `ResolveNext()` samples one request and replays the full ordinary Rest
action from its saved origin with the typed decision prefix. Save/restore
recomputes that prefix, and forks keep independent snapshots. JSONL and Python
expose begin, status, resolve, fork, save, load, release, and the committed
playable run through `begin_reference_nature_native_shovel()`.

## Scope limits

The session handles one configured Native Shovel dig. Legacy Shovel and the
Native-regional fallback with no `NativeRunRng` use the generic run-action
continuation; the fallback controls the retained rarity ticket and conditional
identity request. Other Native relic acquisitions retain their existing event,
merchant, Treasure, or reward boundaries. Neither session claims complete
source relic eligibility, hidden queue identity
probabilities, source call-order completeness, seeded Native result parity,
or Native cursor parity. The Native reference mod and Fidelity Inspector are
still required for those source-evidence checks.
